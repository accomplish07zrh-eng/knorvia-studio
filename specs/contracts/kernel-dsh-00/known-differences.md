# kernel-dsh-00 已知差异

本包没有“被替换实现”，差异分为**本包边界**、**DSH 事实**、**暂缓验证**三类。每条给出理由与对应测试。

## 一、本包边界（有意不做）

| #   | 差异                                                                           | 理由                                                            | 对应测试 / 验收                                 |
| --- | ------------------------------------------------------------------------------ | --------------------------------------------------------------- | ----------------------------------------------- |
| D1  | 开关打开后 `app-server` **不产生 v4 帧**，只输出就绪行并保活                   | v4 桥是 `kernel-bridge-01`；本包只证明新运行时能启动            | B12/B13；`process-contract.test.mjs`（实现 PR） |
| D2  | 开关对 `tui`、`prompt`、`version`、`help` 等命令无效                           | 这些命令的运行时接入属于后续 cli/tui 包；提前切换会破坏默认体验 | B1/B2；T1/T2（合同 PR）                         |
| D3  | 本包不挂工具、权限、Hook、凭据、记忆、技能来源、MCP 配置、目标、子 Agent、压缩 | 计划书把这些划给 `kernel-plugin-*`；本包只起最小必要组合        | B7/B8/B15；`composition.test.mjs`（实现 PR）    |
| D4  | 新运行时的系统提示只有 Knorvia 开场，没有 Knorvia 工具/工作区/技能分段         | 这些分段由后续插件注册；本包不伪造                              | B11；`identity.test.mjs`（实现 PR）             |
| D5  | 开关打开后 `agent-loop` 的 `agents` 为空，不自动创建会话                       | 会话创建由协议桥按 v4 命令驱动                                  | B15；`composition.test.mjs`                     |

## 二、DSH 事实（不是缺陷，但影响边界）

| #   | 事实                                                                                  | 处置                                                              |
| --- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| D6  | `DSH_TELEMETRY_DISABLED` 只禁用已存在的 `session-telemetry-otel` 行，不是全局网络开关 | 组合中完全不放遥测行；用组合快照 + 网络证据双证（B9）             |
| D7  | `dsh-skill-filesystem` 默认包含项目 `.dsh/skills` 与 `$DSH_HOME/skills`               | 设 `includeDefaultRoots:false`；本包零技能来源（B7）              |
| D8  | `dsh-sandbox-local` 会附带一个 Windows ACL 诊断技能                                   | 本包不挂 sandbox；`kernel-plugin-policy` 接入时评估是否禁用该技能 |
| D9  | DSH 身份句只能通过 `includeHarnessIdentity:false` 关闭；DSH 其他文案没有统一开关      | 本包关闭身份句；用户可见错误文案由 bridge 映射（G4）              |
| D10 | DSH 0.2.0-rc.2 是预发布，SDK 不承诺兼容                                               | 锁定确切版本；升级单独合同与验收                                  |

## 三、暂缓验证（如实标注）

| #   | 项                                             | 原因                                                               | 归属                            |
| --- | ---------------------------------------------- | ------------------------------------------------------------------ | ------------------------------- |
| D11 | 安装版 / 便携版实机启动                        | 需要 DSH 运行时树 staging 与原生模块解包；本包只固化打包说明       | `kernel-switch`                 |
| D12 | macOS 实机                                     | 本机无 macOS；只做路径与模块解析静态审查                           | `kernel-switch`                 |
| D13 | 真实模型下的身份三问（“你是谁 / 底层 / 模型”） | 需要用户提供 key；本包用 prompt 装配断言代替，未执行真实模型问答   | `kernel-switch` 真实模型冒烟    |
| D14 | 网络抓包证明无遥测外发                         | 本包用组合无遥测行 + 启动期无网络调用断言；完整抓包归内核验收      | `kernel-switch`                 |
| D15 | 原生锁（koffi / node-addon-system）实机加载    | 本包只启动与就绪，不创建 agent 会话；锁在首次 agent 会话写入时使用 | `kernel-bridge-01` 起的会话测试 |

## 四、不得放宽

- 不因为 D1/D3 未实现而删除对应能力测试；这些测试在后续包补齐。
- 不把“没有 v4 帧”写成通过；`app-server` 在开关下的验收就是“就绪 + 保活”。
- 不把 DSH 包登记成 Knorvia 原创；许可与来源如实记录。
