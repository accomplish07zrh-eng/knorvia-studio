# core-runtime-helpers-01 行为契约（v1）

> 每条 B 编号发布后不重用。九项字段固定为：**输入 / 输出 / 错误语义 / 时序与并发 / 幂等 / 资源释放 /
> 平台差异 / 状态所有者 / 日志级别**。条目与测试的对应关系见 [`README.md`](README.md) 的对照表。

## A 回合附件解析

### B1 回合附件逐条解析（`attachments.ts` 对外的解析入口）

- **输入**：`TurnState["attachments"]`（可为 `undefined`）+ 解析选项（工作目录、trace、可选的
  文件系统端口 / 图像处理器 / 附件产物库、会话与回合标识、可取消信号）。
- **输出**：与输入**等长且同序**的已解析附件数组；每项给出模型可直接消费的内容块、mime、
  `metadata`（可恢复性、存储形态、体积、错误码）与 `url`。
- **错误语义**：解析过程**不抛异常**——任何读取、统计、缩放失败都降级成带 `errorCode` 的占位项；
  只有外部端口在「取消」时抛出的中止异常按原样冒泡。
- **时序与并发**：严格**串行**按数组顺序解析，前一条完成后才开始下一条；不做并发、不做重排。
- **幂等**：同样的附件列表与同样的端口响应重复调用得到结构等价的结果；函数自身不写任何状态。
- **资源释放**：只通过注入的端口读文件，端口调用统一携带 `abortSignal`；本函数不持有句柄。
- **平台差异**：相对路径以注入的工作目录为基准解析；文件名用 `basename` 取值，Windows 与 POSIX
  路径都能取到末段；扩展名判定一律先转小写。
- **状态所有者**：无状态（纯函数式，状态全在注入端口里）。
- **日志级别**：本条不打日志；解析结果的观测由 B13 负责（`debug`）。

### B2 回合附件的事件摘要（`attachments.ts` 的摘要入口）

- **输入**：回合状态里的附件数组（可为 `undefined` 或空）。
- **输出**：空输入返回 `undefined`；否则返回逐项 `{fileName, mime, bytes, ref?}`。
- **错误语义**：不抛异常；缺文件名时按 `attachment-<序号>` 兜底，序号从 1 开始。
- **时序与并发**：同步、纯计算，无并发。
- **幂等**：同一输入恒等输出。
- **资源释放**：无。
- **平台差异**：文件名取自 `basename`，路径分隔符差异不影响结果。
- **状态所有者**：无。
- **日志级别**：无日志。

### B3 data URL 头解析与 base64 载荷校验（`attachment-data-url.ts`）

- **输入**：data URL 字符串；或 base64 载荷字符串。
- **输出**：头解析返回小写媒体类型（参数段被丢弃）或 `undefined`；字节估算返回去掉填充后的
  解码字节数；严格校验返回载荷是否为「4 的倍数长度 + 合法字符 + 尾部填充」。
- **错误语义**：不抛异常；前缀非 `data:`（大小写不敏感）、缺逗号、媒体类型为空一律返回
  `undefined` / `false`。
- **时序与并发**：同步、纯计算。
- **幂等**：是。
- **资源释放**：无。
- **平台差异**：只用 `charCodeAt` 判定字符集，与平台无关。
- **状态所有者**：无。
- **日志级别**：无日志。

### B4 图片内联预处理与图片 MIME 推断（`attachment-image.ts`）

- **输入**：base64 图片 data URL + 媒体类型 + 可选图像处理器与取消信号。
- **输出**：无处理器时原样返回 `{dataUrl, mediaType}`；有处理器时返回缩放后的 data URL 与
  尺寸元数据（原始尺寸、缩放后尺寸、是否缩放、目标字节上限）；载荷不是 `;base64,` 形式返回
  `undefined`。MIME 推断按 `.jpg/.jpeg`、`.gif`、`.webp` 分派，其余一律 `image/png`。
- **错误语义**：图像处理器抛错由**调用方**翻译成占位项（见 B7），本函数自身不吞错。
- **时序与并发**：单次 await，无内部并发；携带 `abortSignal`。
- **幂等**：同样输入与同样处理器响应结果等价。
- **资源释放**：Buffer 由函数内创建即弃，不缓存。
- **平台差异**：扩展名判定先 `toLowerCase`，大小写敏感文件系统行为一致。
- **状态所有者**：无。
- **日志级别**：无日志（失败由调用方记录）。

### B5 PDF 与视频的内联解析（`attachment-pdf.ts`、`attachment-video.ts`）

- **输入**：内联 data URL 字符串；或文件路径；或字节序列。
- **输出**：PDF 解析要求媒体类型 `application/pdf` + `base64` 参数 + 严格载荷 + `%PDF-` 魔数，
  通过则返回解码字节与体积；视频解析只要求 `video/*` + 严格载荷，返回媒体类型与体积；路径推断
  按扩展名表给出视频 MIME（表外返回 `undefined`）。
- **错误语义**：不抛异常，任何不满足的条件返回 `undefined`；PDF 单文件上限为导出常量
  `PDF_INPUT_MAX_BYTES`（20 MiB）。
- **时序与并发**：同步、纯计算。
- **幂等**：是。
- **资源释放**：只在栈上构造 Buffer，不落盘。
- **平台差异**：扩展名与魔数判定均与平台无关；路径比较先转小写。
- **状态所有者**：无。
- **日志级别**：无日志。

### B6 占位项、路径引用与产物读写（`attachment-placeholder.ts`、`attachment-path-reference.ts`、`attachment-artifacts.ts`）

- **输入**：附件描述、占位串、错误码、可选的文件名/mime/体积/来源；或 data URL + 产物库选项。
- **输出**：占位项给 `[Attached <mime>: <占位串>]` 文本块并标注 `metadata_only`；
  路径引用项给出三行说明文本（mime、原因短语、提示用读取工具）并标注 `local_ref`；
  产物写入在有产物库与会话时返回 artifact URI（否则原样内联），读取内联内容时把 `data:` 直接返回、
  artifact URI 经产物库读回。
- **错误语义**：产物读取的任何异常都被吞掉并返回 `undefined`（降级为占位）；产物写入的异常
  **不**吞，向上冒泡；`safeAttachmentOriginalRef` 优先取路径，data URL 内联内容归一成
  `inline:data-url`，避免把大段内容写进引用字段。
- **时序与并发**：单次 await，无内部并发；端口调用携带 `abortSignal`。
- **幂等**：同样的 `existingArtifactUri` 直接复用，不重复写产物。
- **资源释放**：产物库为注入端口；本模块不持有句柄。
- **平台差异**：文本型扩展名判定用正则（大小写不敏感），分隔符无关。
- **状态所有者**：无（产物状态在 `ToolArtifactStorePort`）。
- **日志级别**：无日志。

### B7 本地媒体与内联媒体的分派解析（`attachment-media-resolver.ts` + `attachment-media-resolver/*`）

- **输入**：附件、序号、已解析出的媒体类型（内联路径）或文件系统端口 + 工作目录（本地路径）。
- **输出**：本地路径先 `stat`——非文件给 `attachment_not_file` 占位，统计失败给
  `attachment_read_failed` 占位；图片按体积上限判定超限转路径引用，读取失败给占位，缩放失败给
  `attachment_image_resize_failed`、缩放结果无效给 `attachment_image_invalid`；PDF 超限转路径引用，
  端口报 `too_large` 同样转路径引用，魔数不匹配给 `attachment_pdf_invalid`；视频超限转路径引用，
  空读给 `attachment_video_invalid`。内联路径上图片缩放异常/无效、PDF 头不合法或超限、视频头不合法
  分别给 B7 表内对应占位/引用；非图片/视频且无内容返回 `undefined` 交回上层回退为内联文本。
- **错误语义**：所有可预期失败都映射成带 `errorCode` 的占位项；只有取消（中止）异常冒泡。
- **时序与并发**：单条附件内部按 `stat → 读取 → 缩放 → 产物写入` 顺序 await；不同附件之间由 B1 串行。
- **幂等**：同输入等价；产物写入在已有 artifact URI 时被 B6 短路。
- **资源释放**：所有端口调用携带 `abortSignal`；不持有文件句柄（按需读取）。
- **平台差异**：绝对路径用注入的工作目录解析；文本/二进制判定只看扩展名；编码统一 base64。
- **状态所有者**：产物状态在 `ToolArtifactStorePort`。
- **日志级别**：本组不打日志，失败只体现在返回值的 `errorCode`。

## B 媒体预算、能力与观测

### B8 模型输入格式的能力投影（`media-capability.ts`）

- **输入**：模型输入消息数组 + 该模型的输入能力（是否支持图片/PDF/视频）。
- **输出**：三者全支持时原样返回消息（只统计保留的媒体块数）；否则把不被支持的媒体块替换成
  说明文本，并返回四类计数（图片/PDF/视频/其他被省略数、保留数）。
- **错误语义**：不抛异常；输入能力缺失语义由类型层保证。
- **时序与并发**：同步、纯计算；同一消息内的块按索引顺序处理。
- **幂等**：是；未发生替换时返回**原始数组引用**。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无。
- **日志级别**：省略数大于 0 时由 `logMediaCapabilityProjection` 打 `debug`（含模型名与四类计数）。

### B9 媒体体积预算投影（`media-budget.ts`）

- **输入**：模型输入消息数组 + 预算选项（上限字节、是否保护最新真实用户消息、显式指定被保护
  消息下标）。
- **输出**：总量不超上限时原样返回并给出全量计数；超限时**先保留受保护消息的媒体**，再按
  「越新越优先」（消息下标大者优先、同消息内块下标大者优先）填充预算，被丢弃的媒体块替换成
  `[Attached …] + 省略说明`文本，返回四元计数与投影后消息。
- **错误语义**：上限非有限数或为负 → `ConfigurationError`（可恢复）；受保护消息自身超过上限 →
  `InvalidInput` 且带固定错误码 `MEDIA_BUDGET_CURRENT_ATTACHMENT_TOO_LARGE_ERROR_CODE`，
  提示用户删除或压缩附件。
- **时序与并发**：同步、纯计算，无并发。
- **幂等**：同输入恒等；投影不修改入参数组与消息对象（浅拷贝返回新对象）。
- **资源释放**：无。
- **平台差异**：体积一律按 UTF-8 字节数计算，与平台无关。
- **状态所有者**：无。
- **日志级别**：有省略时由 `logMediaBudgetProjection` 打 `debug`（四类计数 + 字节数）。

### B10 压缩重试请求的媒体占位投影（`compact-media.ts`）

- **输入**：只读模型输入消息数组。
- **输出**：把图片换成 `[image]`、视频换成 `[video]`、无文本的 data URL 文件块换成 `[document]`，
  其余块复制；返回投影后消息与被替换计数；未替换的消息保持原引用。
- **错误语义**：不抛异常。
- **时序与并发**：同步、纯计算。
- **幂等**：是；不修改入参。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无。
- **日志级别**：计数大于 0 时由 `logCompactMediaRetryProjection` 打 `debug`，事件名固定为
  `compact.request.media_placeholder_projection`。

### B11 附件路径物化（`media-attachment-path.ts`）

- **输入**：模型输入消息数组 + 可选附件产物库。
- **输出**：只处理 `user` 消息里带 `inline`（artifact URI）或 `local_file`（本地路径）来源的
  图片/视频/PDF 块；本地路径直接采用，artifact URI 经产物库物化成真实路径；每成功物化一条就在
  消息末尾追加一条 `[Image|Video|PDF: source: <路径>]` 文本注记；没有可物化块时返回原数组引用。
- **错误语义**：来源不是 artifact URI、产物库缺 `ensureMediaAttachmentPath`、产物库抛错、或物化出
  空路径 → 抛 `Unable to materialize <kind> attachment path: <标签>`（产物库错误作为 cause 保留）；
  产物库明确回报 `unsupported` → 跳过该块（不抛）。
- **时序与并发**：消息之间与块之间用 `Promise.all` **并发**物化，结果按输入顺序落位。
- **幂等**：重复调用在同一产物库响应下等价；不修改入参。
- **资源释放**：产物库为注入端口。
- **平台差异**：产物库返回的路径原样透传，不做字符串加工。
- **状态所有者**：路径状态在 `ToolArtifactStorePort`。
- **日志级别**：无日志（失败靠异常语义暴露）。

### B12 工具结果媒体的落盘（`tool-result-media-persistence.ts`）

- **输入**：助手消息 id、回合/会话/工具调用标识、模型内容、会话存储与产物库、可取消信号。
- **输出**：内容里只有「文本块 + data URL 媒体块」且至少含一个媒体块时，逐块写入产物库并返回
  `FilePart[]` 附件与**布局表**（记录每个块是文本还是第几个附件）；否则返回 `undefined`。
- **错误语义**：无会话存储 → `undefined`；有媒体块但缺产物库 → 抛
  `Cannot persist tool result media without an artifact store`；产物写入异常向上冒泡。
- **时序与并发**：逐块**串行**写入，顺序与内容块顺序一致；携带 `signal`。
- **幂等**：块来源已有 artifact URI 时直接复用，不重复写。
- **资源释放**：全部经注入端口，无自有句柄。
- **平台差异**：无路径加工。
- **状态所有者**：产物在 `ToolArtifactStorePort`，附件记录由调用方持久化。
- **日志级别**：无日志。

### B13 媒体观测（`media-observability.ts`）

- **输入**：日志器 + trace +（已解析附件，或 模型请求的投影前后消息与预算投影结果）。
- **输出**：无日志器、或没有可统计的媒体时**直接返回不打日志**；否则发出结构化 `debug` 记录。
- **错误语义**：不抛异常；日志器异常不捕获（与仓库日志约定一致）。
- **时序与并发**：同步；内部没有 await。
- **幂等**：只读入参。
- **资源释放**：无。
- **平台差异**：字节数按 UTF-8 计算；条目数组最多取前 12 个并给出截断标记。
- **状态所有者**：无。
- **日志级别**：`debug`；附件事件名 `turn.attachments.resolved`，请求事件名
  `model.request.media_summary`，含省略时才发。

## C 权限与子 Agent 中转

### B14 权限 broker 的能力判定（`permission-broker.ts`）

- **输入**：一个权限 broker 端口对象。
- **输出**：两个类型谓词——是否具备「按 id 结算」能力（`resolvePermission`）、是否具备「列出挂起
  请求」能力（`listPendingRequests`）。
- **错误语义**：不抛异常；对**缺方法**或**同名字段非函数**的对象一律判 `false`（属性读取用可选链式取值）。
  输入须为非空对象——`null`/`undefined` 会抛 `TypeError`（调用方永远传端口对象，不作业务兜底）。
- **时序与并发**：同步、纯判定。
- **幂等**：是。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无（判定的是端口自身状态）。
- **日志级别**：无日志。

### B15 会话恢复时的授权标记回填（`permission-grant-resume.ts`）

- **输入**：运行时内部对象（含会话存储、会话 id、当前标记字段、日志器）+ trace。
- **输出**：先清空 `lastPermissionGrantId`，再取该会话的最后一条 full-access 授权条目；解析通过且
  会话一致时把 `interactionId` 写回该字段；没有条目时保持清空状态。
- **错误语义**：条目格式损坏或会话不一致**不抛异常**——只记一条 `warn` 并放弃回填；会话存储抛错
  由调用方处理。
- **时序与并发**：单次顺序 await；本函数只在恢复路径调用一次。
- **幂等**：重复执行结果相同（先清空再按最后一条回填）。
- **资源释放**：无自有资源。
- **平台差异**：无。
- **状态所有者**：授权标记归**运行时实例**所有（写入 `runtime.lastPermissionGrantId`）。
- **日志级别**：`warn`，事件 `session.resume.permission_grant_invalid`，字段含 `entryId` 与
  `reason`（`invalid_receipt` / `session_mismatch`）。

### B16 子 Agent 交互中转与子端口派生（`subagent-interaction-broker.ts`、`child-client-ports.ts`）

- **输入**：父 broker + 归属上下文（父会话 id、子会话 id、代理类型等）；或父的客户端面端口集合 +
  归属上下文。
- **输出**：包装后的 broker 会把请求的 `sessionId` 改写成**父会话**，`origin` 缺省时按上下文生成、
  已有值则保留；`requestPermission` 等价于「先 prepare 再 activate」。端口派生对
  `permissionBroker` 与 `providerRuntimeHeadersPort` 分别包一层：前者改写 `request.sessionId`，
  后者改写 `refreshBeforeModelRequest` 入参的 `sessionId` 并透传 `shouldRefreshBeforeModelRequest`
  （缺实现时默认 `true`）；父侧端口缺席时对应子端口**整体缺席**（不造空壳）。
- **错误语义**：不吞父 broker 的异常；`parentSessionId` 由父 runtime 提供，调用方给不出错误值。
- **时序与并发**：同步构造端口；实际请求顺序由父 broker 决定。多层嵌套时**入口层先执行**
  （它就是最深子代理的包装，缺省 `origin` 由它生成），随后逐层向真实 broker 推进，**越靠近真实
  broker 的一层最后改写 `sessionId`**，因此任意深度最终都落到根会话；`origin` 相反只在缺失时写入，
  归属恒为真正发起请求的那个子代理。
- **幂等**：同一父端口可被多次包装；包装层之间无共享可变状态。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无（会话归属状态在请求对象上）。
- **日志级别**：本组不打日志（由父 broker 记录）。

### B26 压缩条目选择与超长重试截断（`compact-selection.ts`）

- **输入**：条目数组 + 触发枚举 + 可选的最少保留轮次数；或超长错误链 + 已保留轮次数/尝试次数。
- **输出**：
  - 基础选择：上下文前缀单列，剩余按「助手起始轮次」分组；仅自动/反应式触发保留最近轮次（至少
    1 组且不超过 `总组数-1`），手动/部分/会话记忆保留 0 组；返回「供摘要的条目、保留组数、保留
    条目、总组数」。
  - 是否够压缩：剔除上下文前缀后 ≥2 组且至少含一个助手条目。
  - 估算：按提供方请求消息估算 token。
  - 超长续压：从错误链里解析 `<实际> tokens > <上限>` 形式的差距（遍历 `message/errorDetails/
details/body` 与 `cause/lastError/error`，最多 6 层、防环），按「新到旧累计直到覆盖差距」算出
    需要多保留的组数并推进保留进度；无法推进返回 `null`。
  - 首次超长：要求 >3 组且能解析差距，保留数从 1 起步再加覆盖量。
  - 摘要重试截断：尝试次数达到上限直接返回 `null` 并 `warn`；否则按差距（无差距时按 20% 组数）
    从最旧开始丢组，丢弃后若以助手开头则补一条重试标记用户条目，返回新数组并 `warn` 记录丢弃量。
- **错误语义**：所有不满足条件的输入返回 `null` 或空结果，**不抛异常**；差距解析失败视为无差距。
- **时序与并发**：同步、纯计算；不 sleep、不设超时。
- **幂等**：同输入恒等；不修改入参（条目被克隆）。
- **资源释放**：无。
- **平台差异**：数字解析兼容千分位逗号；文案与平台无关。
- **状态所有者**：尝试次数由**调用方**传入，本模块无状态。
- **日志级别**：`warn`，事件 `compact.prompt_too_long.retry`（含 `attempt`、
  `droppedMessages`、`remainingMessages`、`maxAttempts`）与
  `compact.prompt_too_long.retry_limit`。

## F 错误分类、取消与流式工具账本

### B28 模型错误与流式错误的归一（`model-errors.ts`）

- **输入**：提供方元数据、`finishReason`/`rawFinishReason`、模型响应长度与工具调用数、用量、
  任意错误链。
- **输出**：

    `context_length_exceeded`、`prompt_too_long` 等）即成立；超限错误为可恢复且可重试，正文固定。
  - 媒体过大判定：标记集与「media/image/document + too large/exceed」的消息组合。
  - 空响应判定：文本 0、工具调用 0、finishReason 不是 `stop`/`tool-calls`、用量全 0。
  - 空响应收尾：命中提供方业务失败 → 抛 `ModelError`（**不可重试**、带 `providerCode` 与响应摘要）；
    否则抛「空模型响应」`ModelError`（可重试、`reason=empty_model_response`）。

  - 流式错误归一：先尝试转供应商业务错误，再退化为 `Error`（字符串原样、其它 JSON 序列化）。
  - 诊断对象：给出 finishReason、元数据键（最多 20 个）、出站 header 键、业务码与响应摘要。
- **错误语义**：判定函数全部不抛；两个「收尾/熔断」构造函数**以抛出为正常返回**。
- **时序与并发**：同步；错误链遍历最多 7 层并用 `WeakSet` 防环。
- **幂等**：是。
- **资源释放**：无。
- **平台差异**：标记匹配统一 `trim().toLowerCase()`，跨平台一致。
- **状态所有者**：无。
- **日志级别**：不直接打日志（错误对象由上层记录）。

### B29 提供商业务错误的识别与转换（`provider-business-error.ts`）

- **错误语义**：识别不抛；转换函数不命中返回 `undefined`。
- **时序与并发**：同步、纯计算。
- **幂等**：是。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无。

### B30 回合失败与取消的判定、事件落盘（`turn-errors.ts`）

- **输入**：取消作用域的父信号；或错误 + 中止信号 + 回退文案；或「运行时 + 结果事件参数」。
- **输出**：
  - 取消作用域：派生子 `AbortController`，父信号中止即级联中止；父已中止时立即为中态；`dispose`
    解除监听。
  - 取消判定：外部故障优先判定为**非**取消；父信号已中止即取消；否则沿 `cause` 链找
    `TurnCancelled` 类型/码、`MODEL_REQUEST_CANCELLED`、`ABORT_ERR`、`AbortError`（最多 7 层防环）。
  - 失败映射：外部故障 → 可恢复的 `UnknownError`（保留原 message 与 cause）；取消 → `TurnCancelled`
    且原文已含正文则复用；上下文超限（核心错误或按消息识别）→ `ModelContextExceeded`（可重试）；
    其余 → `UnknownError` + 回退文案 + wrapper 角色。
  - 结果事件：取消 → 追加 `TurnComplete`（`resultType: "cancelled"`、用量由既有事件汇总、
    `tokenCount` 与 `toolCallCount` 归零）；否则追加 `TurnError`（含错误类型、投影后的错误负载与
    栈、回合阶段）。两种情况都**先落事件再打日志**。
- **错误语义**：`throwIfTurnAborted` 在已中止时抛 `TurnCancelled`；其余构造函数只构造不抛。
- **时序与并发**：事件追加是顺序 await；外部故障标记 `knorvia.externalTurnFault` 沿 abort 原因与
  错误两条链查找。
- **幂等**：判定与构造幂等；事件追加由调用方保证只调一次。

- **平台差异**：无。

  窄化接口写回并回读会话：匹配 → 返回回读结果；不匹配但记录已一致 → 返回；不匹配且仍需修 → 回调

- **幂等**：已干净的记录重复调用原样返回；修复后再次调用即为 clean。
- **资源释放**：全部经注入端口。
- **平台差异**：路径比对用字面相等与「工作区根 + `/` + 身份」的嵌入形式，分隔符固定 `/`（远程
  身份是协议串，不随本机平台变化）。
- **状态所有者**：记录归**会话存储**。
- **日志级别**：不直接打日志（失败经回调与异常暴露）。

### B45 项目记忆的启用判定与记忆代理上下文（`project-memory.ts`、`project-memory-agent.ts`）

- **输入**：运行时配置 + 工作区路径；或运行时 + 记忆根/操作/trace。
- **输出**：记忆根只在「配置启用、未显式关闭、给了 CLI 存储根、任务类型属主任务」四项同时满足时
  解析出来，否则 `undefined`。记忆代理上下文一次性快照：遥测因果、记忆根、当前运行时条目的
  **拷贝**、中途系统提醒配置、带请求元数据（`querySource`、`skipTranscript`、会话类型 `other`、
  每次尝试前刷新运行时 header）、读取文件状态拷贝、工具合同拷贝、工作目录与工作区根。请求消息 =
  快照条目 + 追加的 prompt 用户条目（开启缓存控制）。工具执行器固定 `yolo` 模式 + **拒绝型权限
  broker** + 默认权限配置 + 会话级作用域，事件回写为空操作。
- **错误语义**：不抛异常；缺记忆根时上层跳过。
- **时序与并发**：同步快照（条目与状态均为拷贝，之后的运行时变化不影响快照）。
- **幂等**：同一运行时状态重复快照等价。
- **资源释放**：无。
- **平台差异**：记忆根由记忆模块解析（本模块不加工路径）。
- **状态所有者**：快照归**本次抽取任务**；记忆根归**配置 + 工作区**。
- **日志级别**：不直接打日志。

### B46 项目记忆抽取的调度与排空（`project-memory-extraction.ts`）

- **输入**：运行时 + 模型与 trace；或排空超时（默认 60 秒，`null` 表示一直等）。
- **输出**：调度前置条件——运行时未关闭、抽取未被关、记忆根存在、非远程工作区、会话与文件系统
  端口齐备、有最新对话消息 id；满足后捕获快照，异步解析「截止到边界消息的持久化活跃分支」，交给
  惰性创建的抽取调度器。执行体：扫描记忆清单 → 构造提示 → 组装请求消息与执行器 → 跑记忆代理
  循环（最多 5 轮），全程挂遥测（成功/失败/取消三种收尾）。排空：`null` 直接等，否则与超时计时
  **竞速**，先到即返回并清理计时器。
- **错误语义**：边界消息不在活跃分支 → 抛「Extraction boundary is missing…」；扫描或循环失败被
  吞成 `error` 收尾；已中止或 `AbortError` → `aborted` 收尾；关闭期直接跳过调度。
- **时序与并发**：快照里的消息与会话记录并发读取；调度器保证抽取任务串行执行；排空是竞速而非
  强制超时（超时只是返回，任务继续）。
- **幂等**：调度前置条件不满足时是空操作；同一边界重复调度会产生两条任务（由调度器去重语义决定）。
- **资源释放**：计时器在 `finally` 里清理；扫描携带 `abortSignal`。
- **平台差异**：无。
- **状态所有者**：调度器归**运行时实例**（惰性创建），遥测归**遥测组件**。
- **日志级别**：无直接日志，结果经遥测记录。

### B47 上下文用量的分类贡献者（`context-usage-breakdown.ts`）

- **输入**：来源 → 分类的映射、一个来源键、贡献者数组；或各明细（分段/工具/技能/角色）。
- **输出**：分类不存在返回 `undefined`；否则返回分类并附上贡献者。四类构造器分别产出

- **错误语义**：不抛异常。
- **时序与并发**：同步、纯计算。
- **幂等**：是。
- **资源释放**：无。
- **平台差异**：无。
- **状态所有者**：无。
- **日志级别**：无日志。
