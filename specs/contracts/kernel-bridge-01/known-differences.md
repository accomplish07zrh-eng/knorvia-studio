# kernel-bridge-01 已知差异

本包没有“被替换的实现”，差异分为**本包边界**、**DSH 事实**、**暂缓验证**三类。每条给出理由与对应测试。

## 一、本包边界（有意不做）

| #   | 差异                                                                                            | 理由                                                                  | 对应测试 / 验收                        |
| --- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------- |
| D1  | 不切换默认引擎；`KNORVIA_KERNEL_ENGINE` 缺省仍走旧运行时                                        | 默认切换是 `kernel-switch`；本包只保证开关下等价                      | B1；旧门默认引擎全过                   |
| D2  | 不删除旧运行时、旧 `core` 包与旧会话库                                                          | 删除与导入是后续包；双写会破坏单一事实源                              | B1；[acceptance.md](acceptance.md) §五 |
| D3  | 合同测试只锁定 CommandInbox/序号/快照/双链路；其余命令组由验收矩阵覆盖                          | 离线无法覆盖模型轮、工具、附件、工作流等全部路径                      | [acceptance.md](acceptance.md) §三     |
| D4  | 不迁移旧会话正文；DSH 事件是会话事实的唯一来源                                                  | 导入归 `kernel-legacy-sessions`；桥不得双写                           | B2/B8；interface §六                   |
| D5  | 不暴露 DSH 自有 ACP/SDK/Web 表面                                                                | v4 是唯一产品协议面；暴露第二套会分叉状态                             | B2/B12                                 |
| D6  | 旧运行时草稿会话上的 `renameSession` 返回 `failed`（“Session not found”），本包**不冻结**该行为 | 属旧内部实现细节，不是锁定语义；新桥可按 DSH 能力实现或返回既有 fault | 无断言；实现 PR 记录实际结果           |
| D7  | 不把 DSH 内部事件名、tool 名或 session 文件格式暴露到 v4                                        | 字段冻结；客户端只消费 v4                                             | B2；interface §六                      |
| D8  | 不新增 `KNORVIA_*` 环境变量或测试专用产品开关                                                   | 引擎开关已存在；测试变量只存在于测试进程                              | B1；interface §七                      |

## 二、DSH 事实（不是缺陷，但影响实现）

| #   | 事实                                                                                                      | 处置                                                                                             |
| --- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| D9  | DSH 事件与 v4 源事件不是一一对应：一个 DSH 事件可能投影为 0..N 个 v4 delta，或多个 DSH 事件合成一个源事件 | 桥按源事件独立记账 v4 `seq`（0 delta 也占位）；见 README G2、interface §六.5                     |
| D10 | DSH 没有 `logEpoch` 概念                                                                                  | 桥在会话元数据中持久化；失配时必须回落 snapshot（B10）                                           |
| D11 | DSH 会话持久化是自有 JSONL，不含 v4 projection；恢复时必须从事件重建                                      | 复用既有 projection，禁止直接读旧 CLI `db.sqlite`；见 B8/B10、README G5                          |
| D12 | DSH 只提供 `buildForkSeed`，没有 v4 分支/行/文件回退语义                                                  | 桥构造 seed；文件回退与行目标校验保持旧命令语义；不足处按既有 fault 返回（README G6）            |
| D13 | DSH 的 MCP 是启动期组合，`createSession.mcpServers` 不能直接动态挂载                                      | 桥/后续插件决定；不新增字段、不伪造成功（README G7）                                             |
| D14 | DSH 是预发布 SDK（`0.2.0-rc.2`），不承诺 API 兼容                                                         | 锁定确切版本；升级单独合同与验收（README G9）                                                    |
| D15 | DSH 的 agent loop、工具、权限等能力由组合中的插件提供；本包不补齐 `kernel-plugin-*` 范围                  | 能力缺席时沿用既有 capability/fault 错误，不静默降级（README G10）                               |
| D16 | DSH 没有关闭全部 DSH 品牌/账号文案的运行时开关（`kernel-dsh-00` G4）                                      | 桥映射用户可见错误/状态文字为 Knorvia 中英文文案；不改协议字段，原始原因只进 debug（README G11） |

## 三、暂缓验证（如实标注）

| #   | 项                                                            | 原因                                                               | 归属                                              |
| --- | ------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------- |
| D17 | 首次真实模型轮（sendText → assistant/tool 行 → TurnComplete） | 合同测试不需要模型；桥的离线命令/帧语义已锁定                      | 实现 PR 的验收矩阵 + `kernel-switch` 真实模型冒烟 |
| D18 | 冷恢复后跨进程 resume 与 rowId 稳定性                         | 需要 DSH 持久化会话与桥元数据；合同阶段无桥                        | 实现 PR 验收                                      |
| D19 | 工具、权限、Hook、附件、工作流命令的完整 DSH 映射             | 属 `kernel-plugin-*` 与后续适配                                    | 后续包                                            |
| D20 | Windows 实机与安装版/便携版                                   | 本地仅 Linux；Windows CI 在 main/PR 上运行；打包归 `kernel-switch` | CI / `kernel-switch`                              |
| D21 | 真实模型下的身份问答与网络/遥测抓包                           | 需要用户凭据与网络环境                                             | `kernel-switch`                                   |

## 四、不得放宽

- 不因为 D1/D3 未实现而删除 B3–B16 的任何断言；这些是锁定语义。
- 不把“schema 套件通过”写成“运行时通过”；新运行时必须用 `--engine dsh` 跑同一套用例。
- 不把 DSH 事件直接透传成 v4 delta；序号与字段由桥按合同记账。
- 不修改 DSH 源码来“消除”G1–G10；缺口记录在 `bridge01-gaps.md`，在桥侧或后续包处置。
