# Subagent profile behavior-only contract

Scope: all exported implementation in subagent/profile.ts, including Markdown result assembly, tool-spec interpretation, built-in profiles, normalization and prompt formatting. Exported API/type declarations in api.d.ts stay identical. Unchanged dependency helpers own frontmatter parsing, tool policy, model selection, built-in system prompts and Explore capability formatting. No new policy, filesystem access or authorization. Source-derived curation is disclosed; author may not read predecessor source/history/compiled oracles/tests. Representation/decomposition is author choice; ordinary constrained idioms are permitted.

Built-in factories return fresh objects. General-purpose property order: name,description,color,injectAgentsMd,conditional modelSelection,source,systemPrompt,tools. Values: DEFAULT_SUBAGENT_TYPE equals GENERAL_PURPOSE_AGENT_TYPE; blue,true,built-in,buildGeneralPurposeSystemPrompt(),fresh ["*"]. Explore has the same order; Explore name,cyan,false,built-in,empty prompt,fresh [Bash,Glob,Grep,Read,WebFetch,WebSearch,TodoWrite]. Preserve exact descriptions from runtime-text.json; these are retained runtime/model-facing prose. Optional modelSelection is included only when truthy, and retains its reference. Built-in Explore detection requires exact name Explore AND source built-in, allowing project/user namesakes without special policy.

Normalization creates both built-ins first, passing override references by built-in names. Then caller profiles replace by exact name; first insertion determines output position and last duplicate wins. Caller objects keep identity, including overridden built-ins. Return fresh array, without mutating caller array/objects. Prompt formatting always normalizes first. Heading exact "Available agent types and the tools they have access to:". Each row '- name: description' plus ' (Tools: text)' only for nonempty text; LF join, no terminal LF. Actual built-in Explore uses unchanged capability formatter with provided options. Other profiles with truthy tools use unchanged child-tool filter(tools,disallowedTools), else no tools. Strings used directly, arrays comma-space joined. Normalization always supplies two profiles; retain API null union without inventing new empty behavior.

Markdown parsing:

- Invoke splitMarkdownFrontmatter(content). Missing/falsy frontmatter returns diagnostic only, code agent_missing_frontmatter, message 'Agent Markdown must include frontmatter: PATH', path field present even undefined; PATH is path nullish fallback '<inline>'.
- Parse via parseAgentFrontmatter(frontmatter), use values and mcpServers. Name/description must be strings with nonempty trim; trimmed scalar. Description replaces each literal backslash+n pair with LF after trimming. Missing name precedes missing description. Return diagnostic only: code agent_missing_required_frontmatter,message 'Agent frontmatter must include FIELD: PATH',path including undefined.
- Model selection remains owned by resolveProfileModelSelection(values). Color uses trimmed scalar then exact red/blue/green/yellow/purple/orange/pink/cyan membership. Permission uses trimmed scalar auto/plan, but source project always omits permissionMode; user/built-in may include. Never accept arbitrary/bypass modes or elevate project frontmatter.
- maxTurns numeric: positive integer only. String: exclusively ASCII digits and Number(string)>0; no additional finite/safe-integer cap. Other values omitted.
- Memory only exact string user/project/local, with no extra trim. Defined invalid memory gives agent_invalid_memory_scope diagnostic ('Agent frontmatter memory must be user, project, or local: PATH') alongside usable profile. mcpServers null overrides this with diagnostic only agent_invalid_mcp_servers ('Agent frontmatter mcpServers must be a list of parent server names: PATH'). mcpServers undefined omitted; any non-null supplied list retained reference and included, including empty array.
- Successful outer result order: optional diagnostic then profile. Profile order: name,description,source,systemPrompt=body.trim(),truthy path,truthy modelSelection,color,permissionMode,maxTurns,memory,tools,disallowedTools,skills,background,injectAgentsMd,mcpServers. Conditional absent fields really absent. Optional lists and booleans follow rules below; source is passed through and no input mutation.

Lists: array input filters to string items whose original length>0; retains their strings/order/duplicates, including whitespace strings. String input for skills splits commas/whitespace, trims, drops empties. Non-array/non-string omitted. Skills use this list directly; omit when empty. Tools/disallowedTools additionally interpret individual specs: trim; truncate at first '(' then trim; drop names empty. String tool input separates commas/whitespace only outside parentheses; nested '(' increases depth and ')' decreases with floor zero, parentheses remain in token until name extraction. This permits Bash(git status,git log). Do not enforce args or grants here: unchanged policy filter applies later. Empty array tools explicitly produces tools:[] even when normalization loses every item; empty tools string omitted. Empty disallowedTools/skills always omitted. Boolean values retained; string matching true/false case-insensitively, with no extra trimming; all else omitted.

Display name: truthy profile.path -> 'name (basename(path))', otherwise name. Uses existing node:path basename platform semantics. No external effects in this owner besides unchanged synchronous helper calls. Every diagnostic and prompt string is a compatibility obligation, not evidence of new authorship.
