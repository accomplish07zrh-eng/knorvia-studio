# REPL 结果呈现与可信来源独立实现

替换 node-repl-host 的纯结果适配器，保持 `toMcpRunResult(NodeReplRunResult): CallToolResult` 入口。此处没有 IO、会话、审批、重试或 UI 状态；输入仍由既有 Session 收集，输出仍交给 MCP 和原聊天组件。

## 呈现次序

- 显式 structuredResults 非空时优先采用全部结果，不解析 result 字符串；否则无执行错误时，尝试解析 result（可有前导 `=>`），仅把具有 content 数组且每个块有字符串 type 的对象视为兼容结构化结果。普通字符串或解析失败继续作为末值文本。
- 显式结构化块在前，再放 run.images；回退解析出的块位于 run.images 之后。日志放最后，只有未采用结构化结果时才将末值加 `=> ` 前缀接在日志后。无任何输出时保留 `(no output)`。
- 只有显式结构化结果参与 emitImage 去重：按 data/base64 与 mimeType 完全相等，复用已有内容中第一张匹配图片。没有显式结构化结果时保留重复的 emitImage，也不和回退块去重。
- 对帧合同认定的相邻“image + authority text”二元组，仅保留最后一组，其他普通图片/文字和孤立 authority text 保留。当前 Computer Use 合同尚不授予这种 authority；测试通过模拟合同核验兼容分支，不声称真实驱动已提供该能力。
- 执行错误只输出 error.message，不输出此前日志、末值或图片，也不向内容暴露 stack。结果中任一个结构化 isError 或执行错误决定输出 isError。最后一个非 undefined 的 structuredContent 保留，使用原有有效对象语义。

## 元数据与来源

先合并 run.responseMeta，再按出现顺序覆盖结构化结果的 `_meta`；不修改任何输入对象。元数据是 JSON 键值，`__proto__` 等输入键必须作为普通自有属性处理，不能改变输出原型。

可由代码写入的截图下标、CUA 应用标记和应用关联字段均先剥离（包括公开常量及兼容字面键）。仅从宿主专用 cuaApp 恢复应用身份；仅从宿主 browserScreenshotImageIndices 和当前内容布局的真实映射生成截图下标。无效索引丢弃，相同最终位置只保留一次，保留首次出现的顺序。真实内容有 image 时设置 nodeReplEmittedImage；普通元数据字段继续保留，不扩大可信字段集合。

```text
Session 的结构化结果 / 末值 → 选择呈现来源 → 内容布局及图片位置映射
                                       ↓                    ↓
                    普通元数据合并、剥离可伪造字段 ← 宿主来源投影
                                       ↓
                             原 MCP CallToolResult
```

执行错误不新增图片来源，但保留已观察的宿主应用及原元数据合并行为。适配器不把模型写入的字段升级成宿主记录，也不以正文相似、工具名称或模型声明作为来源证据。

## 验收

先在旧实现验证普通/显式/回退/错误输出顺序、去重边界、元数据覆盖、可信索引映射与帧对裁剪；新增缺陷单独记录。新实现使用纯内容布局及来源投影，按同一契约检查真实构建 MCP 的结果，不调用浏览器、桌面或模型。

执行根及 CLI 类型/lint、变更严格 lint、新测试类型、架构、格式、CLI 构建及完整离线回归。来源复核只覆盖具体新设计文件，披露旧源码访问，不将摘要不同等同于原创，其他未迁移实现和第三方合同继续保留适用许可。
