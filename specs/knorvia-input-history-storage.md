# 输入历史持久存储

2026-09-28，基线 `15c993f`。按公共合同独立替换 input-history.ts 的 recordInputHistory 与 recallPreviousInputHistory。保留现有输入/附件/跨项目裁剪和外层事务边界，修复同步并发去重及自动回滚覆盖原始错误。

SQLite input_history 是唯一持久状态；当前预检只允许无写入退出，最终新写入准入由同一自有 SQLite 写事务判断。使用现有 encodeJson/decodeJson 与 withWriteTransaction，不迁移 schema，不新增缓存、队列或内核状态；所有用户功能和当前前端保留。

```text
输入 → trim/附件投影 → 同步最近记录预检 → 相同：无写入返回 null
                           └→ ID/时间 → 自有写锁 → 最新记录复查 → 相同：提交空事务并返回 null
                                                   └→ 插入 → 全局前 100 裁剪 → COMMIT → 返回本次条目
外层事务：空/重复/投影读取错误不控制事务；真正写入仍由 BEGIN 拒绝并保留外层
```

主代理与复核者接触旧实现用于行为提取，隔离作者只获本规格、选定公共声明和依赖签名；不提供旧目标、SQL模板、历史、构建/映射、基线或测试。不能以改名、转发或测试通过单独确认原创；MIT 范围须逐文件审查，根许可与版本不提前变更。

## 公开入口和调用边界

两个仓储入口首参都是 DatabaseSync，均返回 Promise。recordInputHistory 接受公共 RecordInputHistoryInput，返回 InputHistoryEntry 或 null；recallPreviousInputHistory 接受 RecallPreviousInputHistoryInput，返回同类型或 null。数据库会话 facade 只传递连接与参数，不改变结果或吞异常。

RecordInputHistoryInput：必填 projectID、text、kind；可选 sessionID、attachments、time.created。kind 的公开值是 prompt、steered_input、slash_command。RecallPreviousInputHistoryInput：必填 projectID，可选 skip。沿用公共类型，不新增协议字段。

实际 bootstrap 调用先投影附件，再按运行时 projectID 和当前 sessionID 记录接受的输入。其上层写入失败会记录 `Input history write failed` / `input_history.record.failed`，然后返回 null；这是调用方的容错政策，不能搬进仓储。回忆调用按项目取记录，随后在别处物化附件；仓储不读取文件、下载 URL、调用模型或物化附件，读取异常继续传播。

SQLite input_history 行是唯一持久状态。仓储不增加业务缓存、去重集合、后台清理任务、自动重试或第二个事务 owner；写入不 touch session，也不修改其他业务表。

## 文本与空输入

recordInputHistory 首先对 text 调用原生 trim，保存去除两端空白后的文本；内部空格、换行和大小写不变。结果为空则返回 null，且不读取或校验附件、不读数据库、不分配 ID、不读时钟、不开始事务、不裁剪历史。这包括已有外层事务的场景。

空文本配合运行时坏附件（例如数组中含 null）仍为空操作；不能为了先验证完整请求而改变此边界。非字符串 text 超出公共类型时保留原生错误，不转换成字符串或伪造空输入。

recall 直接返回存储文本，不额外 trim 旧行。去重比较的是当前输入 trim 后的字符串与最近行存储文本的精确相等；带尾空白的旧存储文本不能被新实现自行改成相同文本。

## 附件投影和 JSON

接受的附件种类恰为 file、image、pdf、url，区分大小写，不补新的类型。数组中未识别类型的项丢弃。对每个保留候选：

- path 和 content 仅接受字符串，各自 trim；空白字符串和非字符串值按缺席处理。
- content trim 后若以小写 `data:` 开头，则丢弃该 content。匹配区分大小写；`DATA:` 不被这条规则过滤。path 不适用 data: 过滤。
- path/content 两者都没有有效值时丢弃该项；否则保留 type 以及有效的 path、content。无未知附加成员，不验证 URL、文件存在性、MIME 或绝对路径。
- 保留输入数组顺序和重复项。投影输出是新的对象/数组，不修改输入；对象成员次序固定为 type，再可选 path，再可选 content。

无有效项时表示 undefined，不改成返回 attachments:[] 或 null。写入经既有 encodeJson，因此无附件落为 SQL NULL；非空附件数组使用正常 JSON 文本。去重以同一投影规则处理两边，然后把缺席视为空数组，比较其 JSON 表示；数组顺序不同、有效 type/path/content 不同均不是重复。只在原始成员书写顺序或被丢弃字段不同的输入应被视为相同。

读取先经既有 decodeJson 再进行相同附件投影。SQL NULL、空文本列、JSON null、JSON [] 均可形成无附件结果；损坏非空 JSON 传播原生解析错误。有效 JSON 但根形状不是数组（且不是 null），或数组含 null 等无法读取成员的项，继续保留既有原生错误，不默默修复成空附件。稀疏数组的空槽不制造附件；未知类型可以被丢弃，但不能用“容忍无效数据”为由吞掉所有附件错误。

这些是有限 JSON/材料化对象合同，不要求任意可变 getter、Proxy 或原型篡改的全读取次数等价，也不新增不必要的附件 schema 验证。

## 最近记录与重复判断

最近记录只按 projectID 精确选择，排序为 time_created 降序、id 降序。它不是最近写入调用，也不按 rowid 或当前 session 排序。

当前 trim 后文本与该项目最近记录文本相同，且投影后的附件相同，则返回 null。判断不包含 kind、sessionID、调用时间或 ID；相同项目的另一个 session、另一种 kind 也可被抑制。不同项目互不参与去重。

只比较该项目最近的一条，不能扩展为全历史去重。中间出现另一条不同文本后，较早出现过的文本可以再次保存。显式较旧时间的新记录可能不是项目最近项；后续相同文本是否被抑制仍由排序后的最近项决定。

最近记录必须完整解码附件后才参与判断；其坏 JSON 可以在文本本来不同、无论是否将重复的情况下使调用拒绝。预检重复返回时不刷新时间、不改旧附件/kind/session、不分配 ID、不裁剪全局历史。

## 新记录、时间、ID 和保留上限

确定准备尝试新写入后，分配一个 ID：`input_` + 当前 Date.now 的 base36 文本 + `_` + 一次 crypto.randomUUID 的结果。创建时间使用 input.time.created 的非空值，否则再读 Date.now。因此 ID 的时间来源与显式 created 独立；未给 created 时旧行为允许两次时钟读数不同。0 有效，不改成真值默认；运行时 null 的 created 按缺省处理。

保留 UUID/原生时钟及数据库失败，不重试 ID 冲突、不改变前缀，不做毫秒精度修正。ID/time 的原有准备阶段在 BEGIN 尝试之前；如采用后述预检+锁内复查，竞态导致的二次重复可能已消耗本次 ID/时钟，但不能返回该 ID 或写行。不要为减少一次分配而未经说明改变正常写入或嵌套事务失败的时间阶段。

一次真正写入包括插入当前记录，然后全表裁剪，只保留按 time_created 降序、id 降序排名前 100 的行，最后提交。100 是跨所有项目/session/kind 的全局上限，不是每项目 100。重复和空输入不触发清理；读取也不清理已有超额数据。相同创建时间用 ID 的数据库比较顺序决定保留者，不另按 UUID 生成顺序或行位置排序。

显式很早的 created 可能使刚插入的行立即被本次裁剪删除。旧行为仍返回本次构造的 InputHistoryEntry，而不是 null；不要新增写后存在性检查来改变这一结果。返回只表示本次插入/裁剪事务成功，不保证该行属于最终全局前 100。

返回对象包含 id、projectID、自有 sessionID 字段、text、可选 attachments、kind、time.created；sessionID 未给出时自有值为 undefined。attachments 无有效项时该成员缺席。返回值在 COMMIT 成功后构造/交付，不重新读取或让触发器改写内容替代本次返回投影。

运行时显式传入 sessionID:null 虽超出公共类型，立即 record 返回仍保留自有 null；落库为 SQL NULL，随后 recall 为 undefined。此项保留旧的输入投影边界，不把三个阶段强制统一。

## recall 与 skip 的原生行为

recallPreviousInputHistory 查询指定项目排序后的第 skip 项，零基，缺省和运行时 null 使用 0。无行返回 null；有行按上述 JSON/附件规则解码。

skip 直接交给 SQLite，不新增 floor、clamp、范围截断或应用层校验。已用当前真实内存 SQLite 核对：-1 和 0 均取第一项；0.5、NaN、Infinity 抛 ERR_SQLITE_ERROR / datatype mismatch。足够大的非负整数没有结果时返回 null。其余超出公共输入或驱动支持范围的值继续由原生绑定/查询决定，不做新的宽松转换。

解码使用 SQL 行的 id、project_id、text、kind、time_created；不校验或重写 kind。session_id 为 NULL 或空字符串时对外 sessionID 为 undefined；非空值原样返回。写入时 sessionID 的缺席/null 为 SQL NULL，但空字符串仍是空字符串；本次 record 返回的空字符串与随后 recall 的 undefined 可以不同，不能合并成一个统一默认逻辑。未知列不进入公开条目。

## 事务所有权：必须保留的特殊边界

旧版真正新写入始终要求自己的事务。BEGIN 在清理 catch 外；已有外层事务时，尝试新写入报原生嵌套事务错误，不能主动提交/回滚外层，也不能悄悄改成借用成功。

但是“有外层事务”不是所有调用的统一错误：

| 输入/阶段                  | 旧行为及需保留的能力                                              |
| -------------------------- | ----------------------------------------------------------------- |
| trim 后为空                | 直接 null；不开始事务，甚至不检查附件                             |
| 非空，附件投影失败         | 原错误传播；不开始事务、不清理外层                                |
| 当前项目最近行解码失败     | 原错误传播；不开始新事务、不清理外层                              |
| 已有外层事务，最近记录相同 | 读取调用者可见的记录后返回 null，不执行 BEGIN/COMMIT/ROLLBACK     |
| 已有外层事务，需要新记录   | 原生 BEGIN 失败；外层及其既有修改保留，不能执行插入/裁剪/ROLLBACK |
| 独立新记录                 | 自己持有插入+全局裁剪的完整事务                                   |

本轮已在真实新内存 store 复验：外层事务中相同文本但换 kind/session 返回 null，控制命令为零；新文本只尝试一次 `begin immediate`，错误为 `cannot start a transaction within a transaction`，外层仍活动。空白文本带坏附件也无事务命令。这些不是可随重构删除的偶然能力。

## 单所有者实现边界

本批采用“同步预检 + 自有事务内最终复查”，而不是无条件先 BEGIN：

1. 先完成 trim/空操作和附件投影；同步读取本项目最近条目。若已相同，直接 null，保留独立或外层事务中的原空操作能力。
2. 预检显示可能需要写入时，按既有顺序准备 ID/time，然后进入唯一自有写事务边界。已有外层事务会在 BEGIN 阶段原生失败，不借用、不清理外层。
3. 取得写锁后再次同步读取并判断最新记录。只有锁内最终判断仍非重复才插入和裁剪；若另一个写入者已提交相同内容，返回 null，不插入或裁剪。自有空事务仍正确收尾。
4. 全部实际数据库流程没有 await 插在读后与写前；Promise 签名保留。预检只决定无写入退出，不能作为后来插入的最终许可。相同匹配/投影合同共用，不建立两个长期状态来源。

这种两次有限读取不构成缓存或第二个事务 owner；权威的新写入准入判断仍位于 SQLite 写锁内。允许预检重复按其读取时点结束，也保留旧版对并发后来记录变化的空操作语义。不能只删掉一个 await，却仍让跨连接写入依赖锁外旧快照。

不推荐未经决定的替代方案：对每个非空调用先取得自有写事务，会使原本外层重复的 null 变成嵌套事务错误，也可能把原本只读的独立重复变成写锁/BUSY 失败；简单使用 borrow 则会把原先必须拒绝的外层新写入变成成功。若主代理选择改变其中任何一条，必须另列明确行为变更和先失败验收，不能称完全兼容。

复用既有同步写事务 helper 时，此入口使用“必须自己取得事务”政策，不复用 message/session 的 borrow 政策。无需新的表、唯一键、队列、进程锁或保存点。

## 第二项有意修复：失败原因与收尾

旧版事务内失败后无条件 ROLLBACK。数据库触发器 RAISE(ROLLBACK) 已自动终止事务时，重复 ROLLBACK 会以“没有活动事务”覆盖原始失败。本批应修正这一已确认缺口。

自有事务的插入、裁剪、COMMIT 失败必须撤销本次已执行修改和同事务触发器效果。仍有活动事务才回滚；已自动终止直接传播首因。回滚也失败则用既有 helper 的 AggregateError/cause 保存两个原因。BEGIN 失败不进入清理、不消耗外层事务。不得因为上层最终会记日志并返回 null，而在仓储吞掉异常或返回虚假的新条目。

## 先行合同与失败测试

- trim/空操作：两端空白去除、内部不变；纯空输入无 SQL/ID/时钟/附件检查；外层活动时同样成立。
- 附件：四种类型、未知类型丢弃、path/content 各自 trim、仅小写 data: content 排除、保留 path、非字符串缺席、顺序/重复保留、空投影缺席；材料化输入不被修改。读取 SQL NULL、JSON null/[]、损坏 JSON、非数组和数组 null 元素各有明确结果或原错误。
- 去重：同项目最近内容/投影相同但换 kind/session 为 null；附件顺序变化和不同项目可新增；仅旧成员顺序/无效字段变化仍重复；更早的同文本不是全历史去重；较旧 created 不被当成最后插入顺序。
- 原失败：同一事件轮次并发提交两条相同有效输入，旧版可插入两行；新版恰好一条成功结果、一条 null，数据库仅一条。再以受控不同连接时序证明“预检后他人提交相同记录”会被锁内最终复查挡住，不靠进程内队列。
- 第二连接在预检后提交损坏附件 JSON 时，锁内复查传播 SyntaxError 并结束本次自有事务，保留对方已经提交的行，不插入或裁剪；不是只验收锁外解码失败。
- 外层边界：已有外层记录中的重复可 null 且无事务控制；不同输入原生 BEGIN 拒绝，先前写入与外层活动状态保留；坏附件/坏最近 JSON 也不收尾外层。
- 原失败：插入或实际裁剪触发 RAISE(ROLLBACK)，旧版首因被覆盖；新版保留触发器原错误。另测普通 ABORT、真实延迟外键的 COMMIT 阶段失败、清理双失败，确认不返回成功条目。
- 保留上限：多个项目合计超过 100，按全局 time/id 决定保留，不做分项目配额；相同时间的 ID 次序；极旧新记录可被立即裁剪但成功返回；空/重复调用不顺便清理人为超额历史。
- ID/时间：显式 created=0；ID 时钟和 created 独立；缺 created 时两个受控时钟读数；UUID 失败/ID 冲突传播而不重试。新并发复查抑制分支单列，不伪造旧版已经存在的分配次数保证。
- recall：项目隔离、零基 skip、负值原生效果、无行、原生小数/NaN/Infinity 错误、空 sessionID 的写入/返回/回忆差异、坏 JSON 拒绝而不删除该行。

源码、测试各文件小于 400 行。执行根/CLI 类型与 lint、严格测试类型、架构、格式、相关和全量离线测试；最终 CLI 构建后对照编译入口与实际打入产物的模块。记录源码输入和最终摘要，提交前密钥扫描必须为 0。
