# 权限规则匹配与有序合并

2026-09-28。以 549dc57 为基线，独立替换 project-rule-matching、rule-matching 和 permission-rules 的纯计算实现。先定义合同和失败回归，再实现。已访问旧源码，不作无接触声明；固定工具名称、协议字段、模式语法及标准字符串/集合操作是兼容约束，不能单凭改名、拆分或测试通过声明来源独立。

## 已确认问题及改进

1. WebFetch 的默认“在项目中总是允许”保存完整 URL，旧对象输入匹配却只生成 domain:host，因此同一 URL 再次调用仍要求批准。已通过实际默认建议 → 协议批准选项 → 规则合并 → PermissionService 的纯内存调用复现。现有说明是“后续相同权限请求不再询问”，没有整站授权承诺。本批使完整 URL 规则按原始字符串精确匹配，不把旧规则迁移为域名许可。
2. 去重使用 toolName + NUL + ruleContent 时，不同字符串二元组可碰撞，导致一条规则消失。公共数据合同允许任意字符串，合并器应比较真实二元组，而不是假定分隔字符永不出现。新增反例须先在原实现失败，再用按工具名分层的内容身份集合消除碰撞；不修改存储结构或外部 schema，也不宣称已发生真实桌面故障。

## 独立设计及边界

一次匹配先完整筛出有资格的规则引用，再选择自定义策略或内容匹配程序。内容规则编译为不记忆状态的种类：无条件、命令前缀、通配、字面量，以及 WebFetch 对象输入的精确 URL。输入主题保持惰性读取，不增加项目或会话缓存。通配编译器按字符生成转义表达式，公开 wildcardToRegExp 仍返回无 flags 的 RegExp，供原 Bash 消费者使用。

每个更新类别用一个临时有序合并器处理已有条目和新条目；以工具名及内容分别索引身份，按首次出现顺序保留原对象引用。最终 ruleset 是纯返回值，由原 Service 或 store 成为事实所有者；本层不保存规则，不访问 IO，不新增审批或自动放行通道。

```text
规则集合 → 完整工具范围筛选 → 自定义端口 / 内容程序 → 一个布尔结果
旧 ruleset + 更新序列 → 按类别依次有序合并 → 新 ruleset → 原 Service / store
```

属于现有 unmanaged CLI，复用其公开合同；原 UI、协议选项、Host、Desktop continuous / Web replay、规则持久化及审批流程不变。本批只覆盖这些纯函数和新增内部匹配程序；建议生成、Bash 专用策略、预批准域名清单、路径判定、公共类型和存储不自动改变许可。

## 必须保留的合同

- toolName 严格区分大小写；Edit 规则单向覆盖 Write。保留的 Computer Use 全组规则只能命中宿主已验证的 capability group，同名普通工具不能借此提升权限。
- 无对应行为数组或无候选范围时直接 false。自定义 evaluateRules 在完整范围筛选之后才调用一次，receiver 为策略对象，候选数组新建、元素保留引用/顺序/重复；false 不进入默认匹配，原异常上抛。
- 默认规则按顺序短路。缺席/空 ruleContent 直接匹配，不读输入。普通字符串输入原样作为主题；普通对象按 command、url、file_path、path、pattern、patch_text 取第一个字符串，空串也挡住后续字段，不做 trim。
- 命令 `:*` 后缀优先，前缀中的其他 `*` 按字面量处理；匹配本身或后接空格/tab，不能匹配单词粘连或换行。其他含 `*` 模式使用无 flags、首尾锚定正则，其他正则特殊字符转义，保持原 RegExp 的换行与 UTF-16 语义；末尾换行也不匹配，不扩大为任意多行匹配。
- WebFetch 对象的 url 字段仍优先于其他字段。域名主题使用 trim 后的 URL 解析、hostname 小写、去掉一个末尾点；保留 IDN/IPv6、忽略端口/路径/查询。无 hostname 或解析失败不产生域名主题。公开 webFetchRuleSubjects 继续只返回域名主题。
- 新精确 URL 分支只在规则内容可解析为带非空 hostname 的绝对 URL 时使用，比较 ruleContent 与对象 url 的原始完整字符串。**不规范化协议、主机大小写、默认端口、路径、查询、片段或空白；URL 中的 \* 是字面量。**不同地址必须再次询问。已有 domain:host 和其他域名模式保持原语法和范围，不能因为新增 URL 主题而扩大非 URL 规则的匹配对象。
- 此层不是出站安全校验；网络协议、私有地址、认证、HTTP 升级及重定向仍由原 WebFetch handler/adapter 检查。通过许可不代表网络请求一定成功，也不执行网络以验收。
- applyPermissionUpdates 总是浅复制根对象并设 version:1，保留扩展字段与未触及数组引用。忽略非 addRules 更新。每次被更新的类别均产生新数组，旧条目先于新条目，首条获胜、对象不克隆；空更新列表仍产生新根，空 addRules 仍整理该类别的已有重复项。
- 缺席/空 ruleContent 继续属于同一个身份，不同行为类别互不去重。未被更新类别的已有重复保留。输入对象和数组不被修改；NUL 字符不再使不同工具/内容二元组相撞。

## 验收

先在原实现锁定范围筛选、自定义策略 receiver/错误/惰性、首个输入字段、通配正则/命令前缀/域名、实际 Bash 消费者及更新顺序、对象身份、扩展字段和不变性；另外记录 WebFetch 授权闭合与 NUL 身份碰撞两条预期失败。使用冻结普通记录与少量 accessor 验证承诺的读取边界，不声称任意 Proxy/全局原型修改等价。

新实现复跑合同、实际建议/批准选项/Service 的 URL 与域名范围回归、Bash 策略，做固定基线有限对照并单列两项有意差异；检查编译公开入口及真实 CLI 打包模块，没有旧实现 fallback。执行根/CLI 类型与 lint、严格变更 lint、架构、完整离线回归、格式、来源摘要和暂存密钥检查，再提交并跟踪两平台 CI。根许可、版本、旧发行及最终安装/便携/官网交付仍按整体迁移门槛处理。

### 只读复核发现的读取边界

先行合同之外，复核发现并用失败回归锁定六项有限反例：没有工具名的条目不能因“缺席别名相等”被接受；默认匹配每条内容前重新核实范围，防止前条 getter 改变后条工具名后继续放行；非空内容在选出输入主题后读取用于实际匹配的值；已有规则数组在读取 update.rules 前快照；新增数组在读取任何条目身份前快照；写入类别须在读取新增规则前捕获，不能被该 getter 改写。自定义策略候选仍只筛选一次，不增加回调。保持这些已识别的读取边界，不声称支持任意 Proxy 或全局原型篡改。
