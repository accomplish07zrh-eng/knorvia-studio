# REPL MCP 调度与启动入口独立实现

本规格替换执行宿主的 MCP 服务编排与入口，保持 `createNodeReplMcpRuntime`、`main`、环境捕获和已有公开导出。执行器、桥和结果投影使用前面已验证的独立实现；不增加业务队列、模型请求或系统权限。

## 请求与所有者

- 每个 runtime 独占一个生命周期取消源、已接纳处理器的收尾记录、同 session 的 JS admission 队列及本实例创建的本地 CUA broker。收尾记录仅跟踪 Promise，不另存业务会话或第二份队列事实。
- 工具发现保留可用 Windows 工具及 js，Windows 工具优先路由到其独立 runtime；原结果、参数与由可信请求元数据投影的上下文保留。JS 的参数校验、队列和执行预算不能套到 Windows 原生工具上。
- JS 仍严格接受 code、可选 title（1–120 字符）、可选 timeout_ms（整数 1–120000）。保留原广告 schema、60 秒缺省、无效参数错误码与文字。空白代码返回明确 isError，不创建执行器。
- JS 请求 context 保留原 schema 语义：合法对象的 runtime_scope 缺省 main，session_id trim 并要求非空，扩展字段保留；整体校验失败时使用空 context。title 由本次合法参数覆盖，不能被 context 中同名值替代。
- 同一规范化 session 串行接纳，不同 session 可并行；无 session 的请求使用独立的内部键，不能与字面 session_id=`__unscoped__` 冲突。前一个调用拒绝不能阻塞下一项。
- 超时预算从真正接纳执行时开始，排队时间不占用该预算。调用者取消、runtime 关闭和本次预算合并后传入执行器；每次创建执行器前与收到结果后核验取消状态，迟到结果不能作为成功发布。执行器已提供的结构化错误继续保留，不丢掉内核重置等已有诊断；包括顶层 error、structuredResults 的 isError 和末值回退中的 isError，以同一结果投影的错误标记为准。

```text
MCP 请求 → runtime 接纳与生命周期记录 → Windows runtime（原独立队列）
                             └──────→ JS 参数/context → 同 session admission
                                                            ↓
                                                   开始预算 → 执行器
                                                            ↓
                                                再核验取消 → 结果投影
dispose → 禁止新请求 → 取消信号 / 拒绝未接纳项 → 释放 broker / runtime → 等待处理器收尾
```

## 关闭与资源

- 关闭开始后，工具调用与发现均拒绝；在加载可用能力后再次检查，避免关闭期间的迟到加载重新开放能力。
- dispose 为共享完成屏障。后续调用不能只因取消标志已设置就提前宣布完成；已接纳处理器必须结束后屏障才完成。
- 先传播取消并停止未接纳任务，再启动各资源的独立清理，等待处理器与清理结算。一个资源失败不能跳过其他资源的释放；保留原清理汇总不向调用者升级单个释放错误的行为。
- 取消不等于回滚，也不能强制停止忽略信号的第三方执行器或外部进程。关闭等待是收尾保证，不引入固定延时掩盖同步，也不伪造完成。

## 入口与环境

- 对外稳定的 server 入口负责选择主进程 stdio 或带固定 kind 的 Worker 模式。默认 Worker 必须仍加载该稳定入口，而不是误指向拆分后的编排模块。
- 主进程标题继续为 knorvia-node-repl-mcp；采用既有 MCP Server / serveStdio，拒绝 legacy，注册已独立实现的进程错误及关闭触发器。关闭完 runtime 后再关闭 stdio 并退出。
- stdio 工厂创建的每个 runtime 各自捕获可选 CUA 配置并拥有资源；不同 runtime 不共享一个会被重复 dispose 的外部实例。关闭开始后工厂也拒绝新建；多个关闭触发器共用同一次收尾。同步抛错的清理不能跳过其他实例。
- 构造动作本身也纳入 stdio 关闭屏障：若构造回调同步触发关闭，返回的 runtime 仍须释放且不得再交给传输；若构造抛错，屏障须结算失败的构造，不能无期限等待或产生未处理拒绝。
- Worker 模式执行一个 cell、投递一个结构化结果；主线程普通 import 不启动服务。既有环境变量名、trim 和缺省语义保留，不新增变量。仅配置了权限 broker 地址才创建兼容 CUA runtime；缺省不假定该接口具备真实设备能力。
- Windows 可用性仍由独立加载边界确认，不能因为拆分调度就跳过插件或驱动校验。本文不授权触发桌面操作。

## 验收

先以原公开 API 和协议替身验证参数、元数据、并行/串行、预算、取消和释放；失败分别记录。协议替身只用于可控调度测试，完整 stdio/Worker 构建链仍须用真实 MCP SDK 复核。与前述类型/lint、架构、格式、来源、CLI 构建和完整离线/两平台 CI 一起形成验收，不以单元测试代替产物行为。

来源与许可决定只针对具体新实现，披露原源码访问，保留公共协议约束和第三方 SDK 归属，不将拆文件或同功能自动视为独立实现完成。
