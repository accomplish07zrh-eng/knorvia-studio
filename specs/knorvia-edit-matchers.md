# Edit 纯文本匹配策略

2026-09-30。在不改Edit权限、read-before-edit、读写/修订保护、用户数据格式与UI的前提下，重做纯匹配模块。保留全部匹配策略次序和原有边界行为；本步不自动授予MIT，也不把旧实现用于逐行改写。

## 所有者与新结构

一次调用拥有候选计数、首个实际片段和是否出现不同片段三项临时事实，采用流式归并而不是存储全部Candidate数组。策略顺序固定，首个有候选的策略即决定结果；不是跨策略挑“更好”的结果。宽松行匹配共享只读行视图。锚点相似度仍为精确UTF-16编辑距离，使用复用行缓冲，不用第八步的固定阈值3算法替代。

输入 → exact → 引号归一 → Read行号剥离 → 可见转义 → Unicode转义 → 行trim → 共同缩进 → 首尾锚点 → matched/ambiguous/not_found。replaceAll跳过最后三种宽松策略，其余不变。无IO或持久状态。

## 冻结行为

- 精确子串不重叠计数；相同实际片段重复仍matched并保留总次数，只有不同实际片段才ambiguous。返回第一份实际文件片段
- 空search在exact阶段没有候选，但现有quote_normalized阶段有content.length+1个空片段。这是兼容性记录，不静默改成not_found
- 四种弯引号归一为ASCII后按原位置取实际片段。Read行号必须每行均满足数字加“: ”或tab，保留原RegExp对末尾行终止符的行为
- 可见转义只处理n/t/r/双引号/单引号/反引号/反斜线/$；Unicode仅处理四位十六进制，成对反斜线不解码。不串联不同策略的转换
- 行策略仅剥离一份末尾空行；trim比较使用JS trim。共同缩进只度量tab/space，空白行原样保留。锚点至少三行，首尾trim相等，中间各行相似度等权平均至少0.8
- 编辑距离按UTF-16 code unit；弯引号替换的邻接判断按Unicode code point。不得混淆
- normalizeLineEndings仅将CRLF改LF，保留孤立CR。仅escape_normalized策略解码replacement
- preserveQuoteStyle在oldString===actualOldString时直接保留newString；否则仅根据实际旧片段是否含各类弯引号决定转换。开引号位置严格保留旧白名单，字母中单引号转右弯；不扩大为空白/标点泛匹配
- 未命中不写文件，歧义仍由原Edit调用者拒绝。真实Edit消费者只使用合成FS端口，不访问用户文件
