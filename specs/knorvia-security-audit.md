# Knorvia Studio 数据与凭据安全审计

2026-09-24，T0.6。验收只使用虚构凭据、本地文件和进程替身；不调用模型或已登录 CLI。

## 所有权与边界

- Credential Service 持有模型与创作密钥。创作服务仅在发起供应商请求时读取；模型与任务 RPC、SQLite 记录和 UI 不返回密钥。设置已有密钥时只显示“已配置”状态。
- 日志写入者在持久化前隐藏已识别的凭据值。诊断导出负责二次脱敏和文件白名单；预览与最终导出必须使用同一份生成数据。崩溃元数据只保留有界的非敏感故障信息，不能把原始凭据或任意异常正文写入归档元数据。默认不启动会写入原始内存转储的本地 Crashpad 捕获；保留进程退出事件和脱敏元数据。
- Studio Runtime 持有外部内核单轮临时 MCP 配置。配置只放在 Knorvia 数据根下，权限仅限当前用户；正常完成、失败、取消都删除单轮目录。启动恢复只清理由已死亡进程拥有的目录，不删除其他仍在运行的 Host 的配置。
- 外部内核和供应商的错误、工具输出与回复均视为不可信文本；进入 Studio SQLite 的公开投影前隐藏已识别的凭据形态。用户主动输入的正文仍是其会话数据，不得静默删除整个消息。
- 用户对话正文可能刻意包含任意字节序列，不能把“所有 SQLite 文件绝无任何类似密钥的字符串”当作可证明保证；本项断言配置、任务状态、日志和诊断不复制凭据字段，且不会把测试密钥从配置路径传播到这些产物。以前版本留下的原始崩溃转储可包含进程内存，须隔离在本机数据目录，绝不导出或自动复制；不能声称历史文件已脱敏。

## 时序与失败语义

```text
模型配置 → Credential Service 加密持久化 → 创作运行时按需读取 → 供应商请求
                                      └→ 模型/任务公开投影仅含 configured

外部内核单轮 → Studio Runtime 写私有临时配置 → 进程替身读取 → finally 清理
                                                           └→ 崩溃留下目录 → 下次 Host 启动检查所有者 → 清理

日志事件 → 本地脱敏 → 落盘 → 诊断预览/导出再次脱敏 → 用户指定文件
```

- 生成目录采用随机名并记录进程所有者；恢复只能删确认不再存活的旧进程目录。无法确认存活状态时保守保留并记录待处理，不能误删活跃 Host 文件。
- 恢复不接纳或执行任务；重复运行安全。清理失败必须可诊断，不把“已清理”假报给 UI。
- 导出时任何敏感文件或无法安全判定文本的文件都必须跳过；扫描发现虚构凭据仍在包内时测试失败。
- 日志导出不收集 Studio 会话数据库、创作状态、临时 MCP 配置或原始崩溃转储；未知二进制内容默认跳过，避免仅因编码无法识别就按字节原样复制。

## 离线验收

1. 用不同形态的虚构 API Key、token、SSH 密码及私钥片段，验证日志、崩溃元数据和诊断导出不含原值；导出预览与归档一致。
2. 用隔离数据根和本地 Provider 替身保存创作密钥，核对模型/任务 RPC、SQLite/JSON 状态、日志和导出不回显；不发真实请求。
3. 外部内核替身验证临时配置在运行中可读，成功、失败、取消后被删除；模拟进程崩溃并重建 Host，核对死进程目录被清理且活进程目录不受影响。
4. `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 与相关离线测试均实际运行。审计结果写入 `docs/knorvia-security-audit.md`，未能证明的范围明确列出。
