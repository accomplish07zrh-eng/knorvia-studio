# 中英文文案对齐闸门（T3.3）

日期：2026-09-25。运行时只使用 `en-US`、`zh-CN` 两套消息表；主表会展开 Studio 各模块的消息对象。当前运行时合并后英文 5221 键、中文 5220 键，中文缺 `settings.memory.viewer.disabled`；两侧已有同名键的简单 `{name}` 占位符集合一致。

## 规则、所有者与失败语义

- 已加载的两份运行时消息对象是唯一核对来源，包含各模块 spread 的最终有效键；检查器不另维护一份人工 key 清单，不改变 UI 文案读取路径或语言状态所有者。
- 每个键须同时存在于两种语言，值一般为非空字符串。两处英文拼句片段 `automations.form.schedule.minuteSuffix`、`chat.empty.description.afterWorkspace` 有意留空，列为明确例外；新空值仍失败。对共同键，形如 `{name}` 的简单占位符名称集合必须相同；顺序可不同，重复使用同一占位符可接受。`{{nodeId}}` 一类双括号是向用户展示的工作流语法，不参与替换键核对。检查器不做机器翻译或语义等价判断。
- `pnpm i18n:check` 在缺键、空值、占位符不一致或加载失败时以非零码结束，并按键名给出可修正的诊断。将它接入根 `pnpm typecheck`，使新增单语文案不能通过现有 Windows CI 类型检查入口。
- 检查器只读取仓库消息模块，无网络、凭据、用户配置或持久化副作用。模块别名按已有 UI tsconfig 解析；测试用固定对象验证缺键、空值与占位符故障，再对真实两套目录跑检查。

## 验收

补齐现存缺失键后，两套运行时消息表键集合相等。运行 `pnpm i18n:check`、根 `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 和相关离线测试，记录真实数量与结果。此任务不新建角色或记忆页面，也不改变模型提供商字段。
