# 群聊任务进展与用量（T2.1）

2026-09-25。沿用现有群聊页、Studio Runtime 和黑白视觉语言；本轮只用本地成员替身验收。

## 产品规则

- 任务模式的最近一次运行在聊天区上方显示可折叠进展：主持人当前计划轮次、每位成员的真实状态、当前派发项、最近一次复核结论及工作目录证据入口。旧运行的详情继续由运行历史查看；自由讨论不显示任务计划。
- 状态来自 Host 持久化的 run checkpoint、turn 和待答交互。尚未派发、依赖未完成、执行中、待审批、已完成、失败、已停止与结果未知要区分；不能从成员文字猜测进度。主持人重排时保留上次计划的已知记录，新的派发以已保存的 plan 为准。停止或断线后，仍在执行而未取得终态的成员显示结果未知。
- 文件证据只展示 Host 观察到的工作目录与变更摘要，并链接到现有运行历史中的逐文件审阅入口；没有变更记录时明确说明，不把成员回复当作文件证据。
- 群聊输入卡下增加紧凑统计栏，显示最近一次群运行的每位成员与合计的已上报 Token 和成员执行耗时。合计耗时为成员 turn 耗时之和，可因并发大于墙上时间。缺失用量、旧数据缺少时间戳、仅报告最新模型请求或查询截断时标记为部分数据；未知值显示 `—`，绝不补零或按字符估算。

## 状态所有权与接口

- Studio Runtime 继续独占运行、计划、步骤、交互及用量的持久状态。群聊 UI 只从同一 `StudioTimeline` 快照生成只读投影，不新增前端计费累计器或任务状态副本。
- turn 在派发时写入成员 ID 与开始时间，确认终态时写入结束时间；旧 turn 字段可缺失。最新群运行的统计从持久 turn/usage 按 turnId 读取，重复 usage 通知不重复相加。最多读取最近 2000 个 turn；超过时明确标记部分数据。运行中耗时只计算已观察到的时间，未知终态不补猜测时长。
- checkpoint 的 `plan` 继续由主持人执行器写入。新字段 `review` 保存最近一次有效复核的轮次、状态与摘要；旧 checkpoint 没有该字段时显示“尚无复核”。复核声明完成而实际成员失败时不能记录为通过。
- 界面只使用现有 `data-testid`、语义色与圆角 token；中英文文案对应，窄窗口可换行；无新页面或第二套导航。

## 本地验收

1. 多成员本地替身覆盖长任务、成员排队与并发、待审批、补充说明重排、停止、断线恢复；进展区与持久快照一致，旧响应不覆盖新计划。
2. 注入重复用量、缺失用量、旧 turn 无时间、运行中与未知终态，验证按成员/合计聚合、部分数据标记和无伪造耗时。
3. 运行 `pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed` 与相关离线测试；不发送真实模型请求，不连接 SSH 或生产服务。
