## 1. 统一模式

### 产品规则

- 删除「界面模式」概念：设置页、侧栏底部菜单、引导、快捷键表都不再出现「办公模式／编程模式」。
- 统一模式以原编程模式的能力为底（终端、Git、审查面板、工具卡可展开、命令与输出、文件变更统计、全部编辑器打开入口、任务内查找全部范围、状态面板 Git 摘要），吸收原办公模式中对所有人有益的部分：
  - 输入框工具区：项目型工作区显示 Git 分支切换；非项目工作区显示插件预览入口（原办公模式独有）。
  - 主动任务推荐不再受模式限制，作为普通开关直接可用（默认关）。
  - 自动上下文压缩使用「上下文优化」文案（原办公模式文案），手动压缩仍为「上下文压缩」。
  - 空会话问候使用按时段的问候。
- 存量用户：本机 `knorvia-interface-mode` 旧值不再读取，也不迁移；无论旧值为何都进入统一模式，不丢失其他设置。
- 已存的 `shortcutBindings.toggleInterfaceMode` 覆盖条目保留在设置文件中但不再生效（记录为 `string → string[]`，校验不受影响）。

### 状态所有者

- 删除 UI store 的 `interfaceMode` / `setInterfaceMode` 字段、广播字段与 `useIsOfficeMode` hook，不另设替代状态。
- 工具渲染上下文 `isOfficeMode`、状态面板模型 `isOfficeMode` 输入一并删除，行为固定为统一模式。
- 引导记录文件结构不变：`interfaceMode` 字段保留以兼容历史记录，新写入恒为 `null`（统一模式不再询问）。服务端 `syncSettingsFromRecord` 本就不读此字段。

  - 窄屏：左栏收起，顶部显示步骤进度条。
- 三步：
  1. 欢迎：语言（跟随系统／简体中文／English，即时生效，写入既有语言偏好）与外观（跟随系统／浅色／深色，即时生效，写入既有主题偏好），并列出三项能力（单聊与群聊 Agent、工作流、创作）。
  2. 工作方向：职业选择（沿用原 12 个选项与原持久化字段 `onboardingOccupation`）。

### 保存语义（不变）

- 「开始使用」：`update({ onboardingOccupation, memoryEnabled, proactiveSuggestionsEnabled })` 成功即完成，先 `markOnboarded()` 取消旧判定，再关闭引导，随后追加本机记录（失败或超时只记 warn，不撤销完成）。
- 「跳过」：第 1、2 步跳过仅前进一步；第 2 步跳过时职业记 `null`；第 3 步跳过直接以保守默认值（职业 `other`、偏好全部关闭）完成，记录里偏好记 `null`。
- 再次打开时用最近一条记录预填职业与偏好；用户已交互后异步预填不覆盖。

```text
用户点击「开始使用」
  → settingsService.update(职业/记忆/推荐)   ← 完成事实源
  → markOnboarded()（取消旧判定 RPC）
  → 关闭引导（setRequested(false) / dismissed）
  → 勾选迁移时打开迁移对话框
  → onboardingRecord.appendRecord(...interfaceMode: null)（失败只记录）
```

## 4. Windows 任务栏图标

### 原因（已确认）

1. Windows 窗口图标直接使用 1024×1024 的 `icon_windows.png`。Windows 的 HICON 最大帧为 256，Electron 由单一超大位图生成任务栏／Alt+Tab 图标时可能得到空图标，表现为任务栏按钮无图标（便携版与开发态没有快捷方式可回退，最明显）。
2. AUMID 被设置两次：最早 bootstrap 固定写正式 appId，app ready 后又按 flavor 改写为 preview／dev 身份。进程中途换 AUMID 会使任务栏按钮、快捷方式与通知分属不同应用，Shell 找不到对应快捷方式图标。
3. `win.icon` 未显式声明（依赖 buildResources 默认值），不利于核对。

### 修复

- Windows 窗口图标改用多尺寸 ICO（16–256），打包为 `resources/icon_windows.ico`（源 `build/icon.ico`）；开发态直接读取 `build/icon.ico`。
- AUMID 只在 `desktopEarlyDataBaseDirBootstrap` 中按构建期 flavor 与是否打包设置一次，取值与 electron-builder appId / `resolveWindowsAppUserModelIdForFlavor` 一致；`index.ts` 不再改写。
- `electron-builder` 的 `win.icon` 显式指向 `build/icon.ico`；打包图标检查增加 `icon_windows.ico`。

### 第二轮修复（0.8.4，已确认原因）

用户在 0.8.3 实机反馈任务栏仍无图标。核对已发布的 0.8.3 便携包：`icon_windows.ico`、AUMID 与窗口图标代码都符合预期，但 exe 内嵌图标与所有 ICO 的 16–128px 帧全部是 PNG 压缩（0.8.1 之前的旧图标同样如此）。Windows Shell 取任务栏/Alt+Tab 小图标时走 DIB 路径，PNG 小帧无法解码，于是显示通用应用图标；PNG 只在 256px 帧上可靠。

- `scripts/generate-product-icons.py` 改为自写 ICO：16–128px 为 32 位 BMP（BGRA + AND 掩码），仅 256px 为 PNG；其余 31 个产物逐字节不变（锁定 CairoSVG 2.9.1 / Pillow 12.3.0 复现验证）。
- NSIS `customInstall` 结束时调用 `SHChangeNotify(SHCNE_ASSOCCHANGED)`，让升级安装后 Shell 丢弃缓存的空白图标。
- 离线测试锁定 `icon.ico` / `icon_installer.ico` 的帧格式（<256 为 BMP，256 为 PNG）。
