# 第三方来源清单对账

2026-09-30。本批修复迁移中的声明输入失配及材料漏报，不修改产品运行时、数据、UI、许可证正文或历史发行。

## 唯一所有者与输入

`third-party/copied-components.json`、`npm-overrides.json`、`embedded-components.json`、`native-search/sources.json` 和 `licensing/evidence/material-icon-theme.json` 是各自已有来源事实的所有者。`third-party/inventory.json` 的输入摘要、声明投影和 `reviewRequired` 是派生结果，消费者必须从上述登记重新推导，不能把空数组当作材料完整证明。

```text
保留的来源登记 + 当前文件字节 → 离线对账 → 输入问题 / 投影缺口 / 材料阻塞
                               └→ 非严格检查确认清单一致；严格检查拒绝未解决材料
```

原始版权、NOTICE、许可及已留存的 npm 声明全文保持原字节。历史保守依赖合集保留，不将不在当前生产图的包删除来消除例外。来源与授权分别判断；路径移动、摘要更新、文件在上游存在和目录许可都不构成原创或 MIT 资格。

## 输入迁移

- 64 项原失配逐项记录旧路径/摘要、当前路径/摘要、固定上游基线关系及依据。2 项为内容相同的移动，22 项移动且内容改变，40 项原路径修改。真实删除与缺失来源是单独类别，不自动把 ENOENT 当成删除。
- 只补入已核实的 CLI 路径、两个包 manifest、V4 wire codec 及 AboutLogo 对应关系，不泛化映射所有同名目录。改名后的碰撞必须拒绝。
- 内容修改继续显示上游/第三方或混合来源事实；不授予新的产品许可。旧摘要及旧清单 Git blob 永久记录在对账证据中。
- 普通核验必须报告所有失效输入，不能在第一个 ENOENT 处中止而隐藏后续问题。UTF-8 仅容许 CRLF/LF；二进制逐字节核验，符号链接不得当成普通文件授权。

## 材料完整性

- 从来源登记重新收集复制组件的 reviewRequired、npm 的 evidenceKind/acceptedMissingNotice、嵌入组件及无 notice 的原生组件。清单遗漏、增删投影或 reason 不一致都是对账错误，即使非严格检查也拒绝。
- 15 项 npm 材料例外全部保留，包括不在当前生产依赖图的历史例外。现有 React 技能、Skia、QuickJS-NG 和 Rust 标准库材料缺口同样保留。
- 图标证据必须绑定当前原始/归一摘要；匹配和未解决集合不得重复，必须覆盖声明目录中的全部当前文件。移除未解决记录、添加未审资产、已匹配资产改变或未解决资产变动而不刷新证据均拒绝。
- 五份来源登记必须在输入清单中绑定摘要；原生来源登记自己的配置输入也必须核验。删去登记摘要或只刷新外层摘要不能掩盖原生版本输入失配。图标固定参考版本必须与复制声明一致。
- 对每个未解决图标记录当前字节、固定发布者出处、上游保留关系、缺少的版本/生成或修改证据，以及保留界面的替代方案。生成变体的名称不是来源证明；未复现相同字节前保留阻塞。已匹配图标仍须保留发布者许可，不改称 Knorvia 原创。
- `readVerifiedNotices` 与声明生成共享同一材料推导；`provenance:check` 在安装依赖之前也执行对账，防止生产依赖检查先失败而掩盖材料漏报。非严格门槛允许准确列明的未解决材料；现有 `licenses.mjs check --strict` 继续拒绝它们。

## 验收

先冻结并运行失败测试：空 reviewRequired 漏报、异常被从清单删除、来源注册遗漏、同时多个输入失效、二进制与 CRLF、资产漏列/重复/改变、未解决资产的缺少摘要、固定许可改变、路径映射及碰撞。再实现并保持这些断言。

执行专项、既有 provenance、根类型/lint/格式/架构、CLI 构建及完整离线测试。严格许可门槛的剩余失败必须真实报告，不放宽平台依赖或材料要求。Windows 和 Electron UI 当前不可运行时单列，不用离线来源测试冒充原生验收。
