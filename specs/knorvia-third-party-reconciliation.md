# 第三方来源清单对账

2026-09-30。本批修复迁移中的声明输入失配及材料漏报，不修改产品运行时、数据、UI、许可证正文或历史发行。

## 唯一所有者与输入

`third-party/copied-components.json`、`npm-overrides.json`、`embedded-components.json`、`native-search/sources.json` 和 `licensing/evidence/material-icon-theme.json` 是各自已有来源事实的所有者。`third-party/inventory.json` 的输入摘要、声明投影和 `reviewRequired` 是派生结果，消费者必须从上述登记重新推导，不能把空数组当作材料完整证明。

```text
保留的来源登记 + 当前文件字节 → 离线对账 → 输入问题 / 投影缺口 / 材料阻塞
                               └→ 非严格检查确认清单一致；严格检查拒绝未解决材料
```

原始版权、NOTICE、许可及已留存的 npm 声明全文保持原字节。历史保守依赖合集保留，不将不在当前生产图的包删除来消除例外。来源与授权分别判断；路径移动、摘要更新、文件在上游存在和目录许可都不构成原创或 MIT 资格。

## 输入迁移

- 64 项原失配逐项记录旧路径/摘要、当前路径/摘要、固定上游基线关系及依据。2 项为内容相同的移动，22 项移动且内容改变，40 项原路径修改。真实删除与缺失来源是单独类别，不自动把 ENOENT 当成删除。
- 只补入已核实的 CLI 路径、两个包 manifest、V4 wire codec 及 AboutLogo 对应关系，不泛化映射所有同名目录。改名后的碰撞必须拒绝。
- 内容修改继续显示上游/第三方或混合来源事实；不授予新的产品许可。旧摘要及旧清单 Git blob 永久记录在对账证据中。
- 普通核验必须报告所有失效输入，不能在第一个 ENOENT 处中止而隐藏后续问题。UTF-8 仅容许 CRLF/LF；二进制逐字节核验，符号链接不得当成普通文件授权。

## 材料完整性

- 从来源登记重新收集复制组件的 reviewRequired、npm 的 evidenceKind/acceptedMissingNotice、嵌入组件及无 notice 的原生组件。清单遗漏、增删投影或 reason 不一致都是对账错误，即使非严格检查也拒绝。
- 15 项 npm 材料例外全部保留，包括不在当前生产依赖图的历史例外。现有 React 技能、Skia、QuickJS-NG 和 Rust 标准库材料缺口同样保留。
- 图标证据必须绑定当前原始/归一摘要；匹配和未解决集合不得重复，必须覆盖声明目录中的全部当前文件。移除未解决记录、添加未审资产、已匹配资产改变或未解决资产变动而不刷新证据均拒绝。
- 五份来源登记必须在输入清单中绑定摘要；原生来源登记自己的配置输入也必须核验。删去登记摘要或只刷新外层摘要不能掩盖原生版本输入失配。图标固定参考版本必须与复制声明一致。
- 对每个未解决图标记录当前字节、固定发布者出处、上游保留关系、缺少的版本/生成或修改证据，以及保留界面的替代方案。生成变体的名称不是来源证明；未复现相同字节前保留阻塞。已匹配图标仍须保留发布者许可，不改称 Knorvia 原创。
- `readVerifiedNotices` 与声明生成共享同一材料推导；`provenance:check` 在安装依赖之前也执行对账，防止生产依赖检查先失败而掩盖材料漏报。非严格门槛允许准确列明的未解决材料；现有 `licenses.mjs check --strict` 继续拒绝它们。

## 锁文件补丁登记补充（2026-09-30）

生成器的根 `package.json.pnpm.patchedDependencies` 读取已失效：当前两个活动补丁在 pnpm workspace 和固定 lockfile 中，历史声明还有一个已停用补丁。以固定锁文件的 `patchedDependencies` 为当前精确版本/路径/摘要所有者，离线来源门不能静默漏掉它们；依赖安装的 frozen-lockfile 门负责 workspace 与锁文件一致性。

活动补丁必须出现在清单中且版本、相对路径、原字节摘要一致；补丁文件与锁文件都必须绑定输入摘要。历史补丁记录继续保留且验证其文件，不从当前图移除来清空声明。生成器收集锁定补丁并保留历史补丁合集。此处只解析固定 pnpm 锁文件的平铺补丁段，不是通用 YAML 解释器；重复、未支持的结构/字段、非精确版本及不安全路径明确拒绝，不能按空集合继续。

先在已有声明消费者上观察到「清单漏掉活动补丁」「路径矛盾」「锁摘要不符」的失败断言，再实现共享读取及生成路径，执行来源专项和质量检查。

## 验收

### 实装平台与历史声明合集

依赖只读审核全文 `Knorvia-dependency-license-evidence-2026-09-30.txt`（Library version 1）确认 15 项 npm 仍开放：10 项当前生产路径、2 项开发路径、3 项历史 ARMS。现有 `unsupportedCanvas` 名称集合遗漏 libc，导致 glibc 配置错误要求两个 musl 包；不能按名字补豁免。

精确锁文件包的 os/cpu/libc 是目标约束所有者，pnpm 的有效 supportedArchitectures/optional/ignoredOptionalDependencies 配置与本次主机描述是选择所有者。生产图遍历保留 optional 路径属性：只有所有可达路径均 optional 的包才可因明确配置或不匹配平台省略；任何非 optional 路径仍必需。可省略项保留精确版本、约束、有效选择与原因，不能写作实装/发布物覆盖。当前目标缺失、实装过期版本、未知或未支持平台元数据均拒绝。只读取需要的 pnpm 配置键，不读取/复制认证配置；不改变 install、允许列表或支持平台。

锁元数据读取只支持已固定 pnpm 9.0 lock 的包段和平铺 os/cpu/libc 数组，不是通用 YAML；重复/未支持结构必须明确失败。主机 libc 只从 Node 运行时报告中有证据的 glibc/musl 判断，Linux 无法判断时拒绝推测。扫描 node_modules 的可选安装开关与当前配置要一致；源码规则或下载缓存不能证明实际发行 payload。

再生成先验证已有通知文本与来源清单。按当前生产图收集新的声明，再保留 prior verified package union 中的历史/开发记录及其原 notice 字节、出处、例外和 inactive patches。当前同版本记录也合并历史 notice，而不是仅保留当前扫描结果。每份原文本按原摘要校验；当前依赖独立核验，历史声明不能为缺失当前包提供豁免。当前图外的 override 要有已有被核验记录及补充文本支持，没有历史依据仍失败；不直接删除或放过所谓 stale override。生成时保留 originals 并记录覆盖类别，严格义务仍由原来源登记推导，不清除 15 项。

回归先覆盖 glibc 排除/musl 显式包含、配置改变、非 optional 缺失、过期版本、未知平台形态和磁盘缺包；历史 notice 保留与原字节改变拒绝另有专门夹具。Skia/QuickJS-NG/Rust 等链接未决继续开放，17 原通知及 jcarith 前缀抽取不刷新摘要。

### 多固定版本的资产证据

独立只读研究提供两个补充出版者提交，本写入环境重新从 Git 对象逐字节验证：v5.24.0 `1ce779521ad70ee653c46d95b3ec50d48884e536` 的 238 个 `folder-*-open[_light].svg` 名称各两份共 476，原添加提交 `146ded17af5d4a77aa416fd86699aac50fba900f` 的 `agent.svg` 两份。两份 LICENSE 与已有保留文本逐字节相同。不修改 SVG、原始导入声明或原固定参考 `cb1dfb6d9cb73b15681a93939983d75dbba7bf5b`。
