# 聊天输入与待办入口打磨（2026-10-08）

用户在 0.11.0 实机反馈：

1. 「待办」并入工作台顶栏，不再单独占窄工具栏入口。
2. 对话底部的 token 与缓存命中统计有时不随轮次变化。
3. 思考强度控件改成 Codex / Claude Code 那样的强度轴。
4. 「选择项目」「插件」移到输入框下方。
5. 空会话问候语字体过于冷硬。
6. 以上 GUI 调整对所有内核生效，不能只改 Knorvia 内核。

## 适用范围（所有内核同步）

Knorvia 原生会话、外部内核会话（Codex、Claude Code、Grok、ACP 等）以及工作台格子共用同一组呈现组件，本轮只改这些共享边界，不为某个内核另做分支：

| 呈现             | 共享组件                                                   | 使用方                                                           |
| ---------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 输入卡与上下文行 | `prompt-editor/ConversationComposerSurface.tsx`            | `ConversationComposer`（原生）、`StudioExternalChat`（外部内核） |
| 空会话问候       | `v4/ConversationDraftEmptyState.tsx` + `styles.css` 钩子   | 原生 `SessionPane`、`StudioExternalChat`、工作台格子             |
| 思考强度         | `chat-input-toolbar/ThoughtLevelCycleControl.tsx` 滑杆模式 | `V4ComposerToolbar`（原生）、`StudioChatModelControls`（外部）   |

## 规则

### 待办并入工作台

- 窄工具栏移除「待办」入口，`attention` 页面路由一并移除。
- 工作台顶栏新增「待办 (n)」按钮，n 为待处理与未读之和（与原待办页筛选计数口径一致）；点击展开浮层，复用原 `StudioAttentionInboxView`（筛选、显示已读、标为已读、打开）。与任务列表、已收起三个浮层互斥。
- 打开待办项沿用原 `openAttentionTarget`（原生会话进入聊天，Studio 会话补开项目后导航），打开后浮层收起。待办事实来源、已读语义与离线提示不变。

### 思考强度滑杆

- 聊天输入框（原生与外部内核）的思考强度改为弹出式强度轴：标题「推理强度」与当前档位名，单条轨道按配置顺序从低到高排列档位，可拖动、点刻度名或用方向键即时切换；回车或点外部收起。
- 只用黑白深浅表示强度，不引入彩色渐变。2026-10-08 起外观与排序以 `knorvia-ui-polish-20261008.md` 为准（未到最高档白色填充、最高档黑白渐变动效、档位按强弱从低到高）。
- 档位列表、默认值、存储、发送与校验均不变；单档模型仍为不可交互显示；外部内核仍可显示已失效的保留值，并支持重新点当前档位以固定该值。设置页（自动化、子 Agent、工作流运行）保留下拉选择。

### 对话底部用量统计

已确认原因与处理（原生会话由 CLI 投影提供，外部内核由 Studio 运行时提供，二者共用 `ChatMetricsBar`）：

| 现象                                       | 原因                                                                                        | 处理                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 原生 tok/s 恒为「—」，步数在轮次结束前不动 | 流式请求完成事件 `model_request_completed` 不带用量与首内容耗时，会话调试统计算不出生成速度 | 流式路径与非流式一致上报 `usage`、`finishReason`、`timeToFirstContentMs`                  |
| OpenAI 兼容服务商 token 与缓存不变         | 未请求 `stream_options.include_usage`，流式响应不返回用量，累计值恒加 0                     | `createOpenAICompatible({ includeUsage: true })`                                          |
| 缓存命中偶尔变回「—」                      | 无命中率的请求与上下文压缩成功会重建 `contextWindow` 并丢弃 `cache`                         | 沿用上一次累计命中率                                                                      |
| Claude Code 轮次中 token／缓存停在「—」    | 计费用量只在轮次结束的 `result` 上报                                                        | 每条 assistant 消息以 request 口径上报计费用量与缓存读写，`result` 再以 turn 口径整体替换 |

保留的口径：原生缓存命中为会话累计加权值（悬停说明为「累计缓存命中率」），单次请求对长会话影响小属预期；子 Agent／工作流子请求不计入主会话用量；ACP 内核协议本身不提供缓存数据，仍显示「—」。

### 输入框下方的上下文行

- `ConversationComposerSurface` 的上下文行（项目选择、插件或 Git 分支、外部内核项目菜单）移到输入框下方，仍在同一张输入卡内。项目菜单向下展开（空间不足时由弹层自动翻转）。

### 问候语

- 问候字重由 600 改为常规，字距由收紧改为略放开，前景色略浅；字体优先 Segoe UI Variable Display / 较圆润的中文系统字体（HarmonyOS Sans、MiSans、苹方），再回退雅黑。三道笔画母题保留。此项更新 `knorvia-visual-language.md` 中「问候加重、收紧字距」的取值。

## 验收

- 窄工具栏无「待办」；工作台顶栏「待办 (n)」浮层可筛选、标为已读并打开目标。
- 原生与 Codex 草稿：上下文行位于输入框下方，两者输入框与问候位置一致（`studio-page-layout-smoke`）。
- 思考强度：原生与外部内核均弹出强度轴，选择后发送使用所选档位；设置页仍为下拉。
- 用量：流式完成事件带用量与首内容耗时（适配器契约测试）；缺少命中率的完成事件后缓存命中保持（投影测试）；Claude Code 轮次中即有 request 口径用量（内核用量测试）。
- typecheck、lint、fmt、架构、来源清单、UI 测试与工作台冒烟。
