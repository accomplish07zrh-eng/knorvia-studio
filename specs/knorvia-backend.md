# Knorvia Studio 后端实现规格

2026-09-22。用户已授权全面补齐当前前端的后端。本规格取代前端壳规格中的“仅草稿、不可执行”阶段限制，不恢复已作废的旧仓库、旧 GOAL 或另一套界面。使用仓库 architecture-governance 约束实施。

## 产品边界

- 保留原 GUI、白色默认主题、四内核统一聊天布局、当前已确认的小机器人和透明应用图标。管理入口在设置中；自动化、工作流保留当前主侧栏入口。
- Knorvia 为默认内核，Codex、Claude Code、Grok Build 接入本机已有 CLI。提供真实探测、路径配置、安装、更新、卸载和能力说明。只自动管理 Studio 自己安装的副本；已有系统安装可连接、定位和显示对应管理方式，不静默卸载用户全局 CLI。
- 换内核创建独立会话，不复制旧会话、私聊或私有记忆。原有 Knorvia 单聊继续通过原 V4 通路；外部单聊沿用同一输入框和消息呈现组件。
- 单聊在原输入框工具栏直接选择当前内核实际支持的模型和思考档位，采用原 GUI 的选择器样式。模型列表、档位与参数映射以本机 CLI 的能力响应为准，不伪造可选能力；不支持或当前无法探测应明确显示。选择属于对应会话与草稿，发送时冻结参数，不能把排队中的旧消息悄悄换成新模型。Knorvia 继续使用原模型设置与思考控制。
- 联网验收优先使用用户指定的 GPT-5.6 Luna 与低思考档；先查能力和精确 ID，不可用不自动回退昂贵模型。离线夹具优先，实际推理使用最少短输入验证必需链路。
- 群聊平时按用户 @ 指定成员或全部成员；没有 @ 时交给主持人。用户明确启动任务后，主持人可以规划、派发、复核、返工。成员不得通过回复里的 @ 隐式启动无限接力。
- 群上下文仅含群摘要、明确共享说明和群内消息。每个群成员使用独立原生会话，不查询单聊或其他成员私有会话。成员变化不复制私有记忆。
- 群聊和工作流默认在各自隔离目录修改项目；可显式选择共享目录。隔离修改应可查看差异并显式应用，存在基线冲突时拒绝覆盖用户修改。不新建成果页面。
- 工作流运行当前画布：串行、并行、条件、汇合、人工确认、有限重试、停止、历史与恢复。条件使用受限表达式或结构化规则，不执行任意 JavaScript。
- 关闭主窗口仍按现有托盘行为后台运行。完全退出先保存状态，停止仅由 Studio 启动的进程。重开恢复已确定步骤；原生调用结果不确定时标为中断，显式重试前不得重新发送。
- 本轮不新增角色与记忆页面、成果页面、插件市场或账号登录。保留去登录、去上游产品身份、独立数据目录、进程标识及原开源声明。
- Claude Code 不要求代用户登录实机验收；Grok 的余额耗尽 402 保留为联网验收例外。协议和本地错误、审批、取消仍需测试。其他失败不得借这些例外跳过。

## 状态所有权和边界

新增 managed `studio-runtime` 模块，位于 services 包。Host 内的 StudioRuntimeService 是外部会话、群聊、工作流运行的唯一写入入口；Renderer 仅持有编辑草稿和服务快照，不维护另一份已接收队列。内置单聊状态仍归原生 V4 owner。

公共浏览器安全契约经 services/index 导出，Node 工厂经 services/node 导出。域层只做纯校验与调度决策；应用层通过端口安排执行；SQLite、进程、文件、时钟由 adapters 执行。Main 不持有运行业务状态。远程工作区不能误调用本机 CLI，明确拒绝不支持的跨主机执行。

所有 Host 访问同一应用数据根下的独立 studio SQLite 数据库（WAL、事务、schema 版本）。服务以事务接收 commandId，保存结果以去重；相同 ID 不同负载拒绝。数据库租约选出一个执行 owner，使用随机 owner token 隔离每次接管；其他 Host 通过同一命令日志提交和读取。活跃执行在每次写入前验证租约，过期结果不得覆盖新 owner 的状态。

```
原 GUI → typed command → Host 服务事务接收 → 持久状态 / 事件序号
                                    ↓
                          执行 owner → 内核适配端口
                                    ↓
                         审批 / 工具 / 文本 / 终态
```

桌面和 Web 使用相同的有序状态源；事件只通知变化，完整快照与单调 revision 修复断线和缺口。不能把 ACK 当完成。原生 Knorvia 调用须等 terminal 与 ready 后才交给下一轮。

## 事件、恢复与权限

- 接收命令、创建 user message 和 queued run 在同一事务提交；再启动进程。输出按 run/turn/event identity 归属并保存。失败、取消、已结束后的迟到事件不再修改终态。
- 原生 session ID 在获取时即持久化，按 kernel + conversation/member + workspace 隔离。下一轮走原生 resume，不以拼接全部旧消息冒充恢复。
- 内核托管版本记录独立的所有者、版本、路径和哈希收据。显式配置的受管路径也必须校验，包括升级后保留的旧版本；升级先保证旧路径可运行，再提交配置切换。卸载只清理已验证所有权的该内核版本，未知目录不删除。无有效版本收据时明确提示重装，不静默追认。
- 一个会话/群成员同一时刻只有一个输入轮次，其他输入排队。全局并发和单批派发数量有上限；按用户最新要求，不设群任务总轮次、总派发数量或总耗时门槛，不要求按固定轮次点继续。主持人持续规划、派发、检查直至验收完成、真实失败、等待必要用户输入或用户主动停止。
- 停止先冻结当前运行的后续派发和重试，再取消其活跃子任务并等候真实终态；未确认停止的操作记录为结果不确定。停止不能通过成员迟到消息或旧待执行项再次唤醒，也不能影响别的项目或手工启动的 CLI。完成须有复核结论和真实工作目录证据，成员自称完成不等于整个任务通过。
- 持续群任务运行中用户补充说明使用独立 steer 命令，持久保存到当前任务与群消息。后续旧派发立即冻结，已经执行的成员先在安全边界收口；主持结合原目标、已完成结果和新指令重排。新计划保存后才确认消耗对应说明，后到说明仍待处理，停止优先于任何补充。普通群消息继续按成员排队。
- 长任务完整成员结果分条保存；活动检查点只保留调度必需的有界投影，旧结果通过持久记录读取，不能因累计输出突破单条记录大小而伪装成需要用户继续。界面可加载更早消息，断线重连通过周期快照校正。
- 审批和用户提问先保存，再显示；响应是独立、幂等命令。取消和进程退出使待答请求失效；旧 request ID 不能作用于新轮次。未知权限、CLI 不支持的强制能力明确拒绝，绝不静默升级权限。
- 只读、询问、完全访问映射到内核真实能力。Studio 的配置不得绕过内核限制；若某内核不能强制只读，应拒绝该档执行而非仅写一段提示词。
- 正常退出先关闭接收，持久保存中断原因，取消原生调用与模型/版本探测，等待已接收的文件应用、管理操作和任务全部收口，再释放租约并关闭数据库。探测也持有受管安装租约，不能在其进程活跃时卸载对应版本。崩溃接管将遗留运行中的原生调用标为结果不确定；用户确认重试后创建新 attempt；已完成的节点不会重复执行。
- 人工确认节点在同一次 attempt 内持久保留稳定 ID 与答案，自动恢复不能重复提问或消费答案。用户明确重试被拒绝或失败的运行时创建新 attempt，尚未完成的确认节点重新询问，已完成节点不重复执行。节点自动重试只对确定失败适用，不自动重试未知结果或取消。
- 外部进程仅继承正常环境和自身原有认证方式，不复制、打印或改写用户凭据。日志不保存 token；命令参数通过 spawn 数组，不拼接用户输入进 shell。

## 草稿迁移

现有 localStorage 是未提交草稿。保留原始 envelope；首次成功导入通过稳定 commandId 记录。配置、群定义、工作流定义由后端接收后成为唯一正式版本；编辑中的文本仍由 UI 保留。损坏草稿不得隐式覆盖或删除。会话内容只在服务器接受发送后清空输入。

## 验收矩阵

1. 真实探测本机版本和路径；管理操作验证副本所有权、错误反馈、互斥和取消，不改系统 CLI 设置。
2. Codex 实机双轮对话、流式、工具与取消；Claude/Grok 做完整协议夹具与可用的实机验收，列明已授权例外。
3. 换内核新会话；重开会话继续原内核；共同聊天组件无另一套界面。
4. 手动 @、@all、主持规划与复核，成员并发与排队，权限交互；重复消息、停止、迟到事件、上下文隔离有实质测试。
5. 工作流串并行、真假分支、汇合、审批、确定失败重试与取消可执行；无效图拒绝；历史和重启恢复可验证。
6. 隔离目录差异、用户改动冲突、显式应用；路径遍历与危险文件链接拒绝。
7. 多 Host 去重与租约、事务故障、崩溃未知结果、已答审批和已完成节点不重复执行。
8. 根 typecheck、renderer 类型、lint、architecture 检查通过；必要服务/协议/调度测试；真实桌面导航、发送、审批、历史与状态验证。
9. 更新现有桌面便携目录，保留 data；验证包内服务、图标、无登录、独立身份。桌面留下当前实现与验证文档。
