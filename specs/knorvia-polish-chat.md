# 单聊与 Agent 管理精细修复

2026-09-23。只打磨既有统一聊天和设置内 Agent 管理，不改变布局或新增页面。

## 已确认问题与规则

- 会话列表由正式会话和本机未发送草稿投影合成。正式会话的内核、项目与标题归后端所有，本机文本不能覆盖它们；排序时间取最新实际修改。删除正式会话必须说明删除的是对话入口，后端执行记录和原生 CLI 文件保留，不能冒称只删除草稿。加载和连接失败不是“没有草稿”。
- 读取正式会话不创建空草稿，不刷新排序时间。后端快照确认相同模型选择后，可回收已无未发送文本的对应草稿缓存，防止正式会话元数据占满 100 份草稿额度。草稿新文本、未确认模型选择和显式默认选择必须保留；正式项目列表直接从后端读取。
- 输入内容的唯一所有者仍是 `studioAgentStore`。发送前同步锁定本轮，模型参数按现有路径冻结。ACK 清空通过 store 比较提交文本与当前文本，不读取已卸载组件的过期 ref；重开同一会话后写入的新草稿绝不能被旧 ACK 清掉。当前编辑器跟随外部 ACK／显式重置变化；连续提交不得重复接收，错误仅呈现于发起会话。
- 运行停止由既有 cancel 命令负责；请求中／已请求停止期间显示停止中并防重入，不伪装已经停止。
- 模型能力属于 service 实例 + 内核 + 项目 + 连接配置。换 service 或权限后不得展示旧能力；同一来源暂时刷新失败可以保留最后有效目录，但保留错误提示，不自动选模。
- Agent 普通配置保存，模型未变时保留既有 reasoningEffort；显式换模型或恢复默认才清除旧档位。模型 ID 的长度和字符规则与实际发送契约一致。
- 检测结果属于发起的连接与配置，旧来源迟到响应不可成为新来源状态。管理期间按钮防重入；长模型标识、路径、错误可换行，操作在窄窗口仍可达。
- 草稿存储的重试／重置按钮是普通操作，嵌入 Agent 配置表单时绝不能触发表单保存。窄输入框中权限沿用原工具栏的图标折叠规则，并保留可访问名称。

## 顺序与验收

```text
编辑 → store 当前草稿 → 提交时冻结 → Host 接收
                               └→ ACK → store 比较当前文本 → 仅清空已提交内容 → 当前编辑器同步
能力请求 → service + 配置来源 → 当前请求结果 → 菜单（旧来源丢弃）
```

测试覆盖：旧 ACK 与重新挂载后新草稿、失败保留、相同文本防重复、正式元数据与排序、删除语义、普通保存保留档位与换模型清除。实际 GUI 验收由主代理在隔离资料中检查。此分工不调用模型、不安装或卸载真实 CLI、不修改桌面数据。
