# 工作台与各内核对话（2026-10-10）

用户在 0.11.3 实机反馈：「已收起」只能恢复、不能消掉，一直占着顶栏。期望：

1. 工作台是摆放对话的桌面，对话属于各自内核；可以把各内核已有对话放进来，工作台里新建的对话也记在对应内核的会话记录里。
2. 不要「已收起」；但上次留下的布局下次打开时直接恢复，不用重新打开。
3. 单聊与工作台不冲突：同一会话可以同时在单聊打开、在工作台占格，不需要「转为单聊」机制。
4. 移出工作台与删除对话分开。

本规格替代 `knorvia-task-workbench-20261008.md` 中「已收起」列表、64 项上限、重载后逐格核对后重新加入，以及 `knorvia-workbench-usability-20261008.md` 中「新建任务满格换出聚焦格」「在此格新建任务原格入收起」的规则。

## 状态所有者

| 状态                       | 所有者                                     | 本轮变化                                               |
| -------------------------- | ------------------------------------------ | ------------------------------------------------------ |
| 布局、格子引用、缩放       | Renderer 工作台 store（localStorage v1）   | 删除 `shelved`；旧存档中的收起列表读取时丢弃           |
| 会话本身、记录、标题、删除 | Controller（原生）／Studio runtime（外部） | 不变；工作台只引用，不复制、不删除                     |
| 「添加对话」列表           | 同一次 `useWorkbenchTasks` 读取            | 新增投影 `workbenchConversationRows`，不另开查询或轮询 |
| 视图与 Host 绑定           | `workbenchConnection`（窗口内存）          | 重载不再标记 unknown；窗口内 Host 换代仍拒绝旧格重绑   |

## 规则

### 移出工作台

- 格子右上角「×」为「移出工作台」：只删除视图引用，不停止任务、不删除会话；会话仍在原内核记录（单聊侧栏）中，可从「添加对话」再放回。
- 「在此格新建任务」：原格移出工作台，原位换成同内核同项目的待命格。
- 任务列表的「加入 / 切换当前格」换下的格子同样只离开工作台。
- 「新建任务」：有待命格时聚焦它，有空位时自动分格；已满 8 格时不换下任何格子，提示先移出一个格子。
- 未发送的原生工作台草稿随格子移出而不再保留（工作台专用草稿作用域）；外部内核草稿仍由原草稿存储保存，切回该内核时恢复。

### 添加对话

- 顶栏「新建任务」右侧为「添加对话」，以浮层展开，与任务列表、待办互斥。
- 列出已被 Host 受理的对话：原生会话取 Controller 未归档列表（全部已知工作区），外部内核取 Studio 概览；未发送草稿与归档会话不列。同一真实会话（Studio 内置单聊同时出现在 Controller 中）按目标键去重，原生项优先。
- 按内核分组（顺序跟随内核登记顺序，ACP 等其后），组内按更新时间倒序；每行显示标题、项目名、相对时间。搜索匹配标题、项目名与内核名。一次最多渲染 200 行，超出提示继续输入筛选。
- 圆形勾选可多选；已在工作台的显示「已在工作台」且不可选；来源离线的不可选。底部显示「已选 n · 还可放入 m」，m 为空余位置加待命格；超出时禁用加入并说明。
- 加入按顺序先填待命格再自动分格，只改视图引用，不发送 create/send/resume/approval。用户从当前 Host 列表显式挑选，视为已核对连接。

### 布局留存与恢复

- 布局、格子引用、比例、缩放、视图模式照常持久化。
- 重新打开时直接恢复上次布局：各格首次渲染由当前窗口 Host 认领；原生格经 `PaneRestoredGuard` 在按工作区身份（含远程连接）解析出的 endpoint 上核对会话存在，外部格核对 Studio 概览中同 ID 会话的内核与项目一致。核对不通过时保留格子并显示原因，不自动启动任务。
- 窗口内 Host 换代（同一窗口运行中 service 对象变化）时旧格不重绑，提示移出后从「添加对话」重新放入。
- 依据：此前重载后把所有格子标为「未核对」，用户每次都要逐格重新加入；而两类格子在渲染时本就按身份键核对当前 Host 的真实索引，会话 ID 为 UUID，工作区身份包含远程连接，足以区分来源。

### 单聊与工作台

- 同一会话可同时在单聊打开并在工作台占格，两边共用原会话运行时与记录；单聊「加入工作台」保持不变，不新增「转为单聊」。
- 工作台里新建并发出的对话就是对应内核的普通会话，出现在该内核单聊侧栏。

## 验收

- 单元：移出/在此格新建/换格后状态无 `shelved` 且不保留被换下引用；满 8 格新建返回失败且布局不变；旧存档含 `shelved` 时正常读取并丢弃；`workbenchConversationRows` 去重、排序、排除无会话 ID 的 Studio 原生项；`addMany` 填待命格、计数、满格停止。
- 浏览器冒烟：顶栏无「已收起」；「添加对话」按内核分组、搜索、多选加入；移出后会话仍可再次加入；重载后已打开格直接显示会话而非核对提示。
- typecheck、lint、fmt、架构、来源清单、UI 测试、工作台冒烟。
