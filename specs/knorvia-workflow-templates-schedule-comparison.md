# 工作流模板、计划触发与运行对比（T2.3）

2026-09-25。沿用现有 Studio 工作流画布、运行历史与主侧栏自动化调度器；不新增独立工作流应用或第二套计时器。

## 产品规则

- 内置发版前检查、代码审查、文档整理三个可执行模板。新建时复制为用户自己的工作流，节点与指令可编辑；模板本身不写入用户数据、不启动内核。空白与结构模板继续保留。模板图在未配置真实模型时也通过静态图校验，运行前仍检查内核和项目可用性。
- 工作流可以创建计划任务；计划、暂停、立即运行与历史继续由主侧栏自动化管理。计划项持久记录工作流 ID 和项目归属，不能退化成给普通会话发送一段提示词。定时器只负责认领和派发，Studio Runtime 是工作流定义、运行快照、节点进度及命令幂等的唯一所有者。
- 每次计划触发用既有 automation run ID 派生稳定 Studio 命令 ID。Host 在派发时核对工作流存在、属于同一项目且图有效，然后将自动化的指令作为本次输入提交。定时器重试同一 run ID 只取得原有 Studio 运行；重启后不重复执行已完成节点。若工作流缺失、项目不符或提交失败，应明确记录派发失败，不改走普通聊天。
- 同一工作流的两次运行可按节点比较状态与输出。以每次运行保存的定义和 checkpoint 为准；节点增删、跳过、失败、未知或未执行都分别呈现，不从新画布重建旧运行结果。长输出截断时标注截断，不把摘要当完整内容。

## 边界与验收

- 创建模板与运行比较只读本机快照，不发送消息。计划派发本轮仅用本地服务及内核替身验收，不调用已登录 CLI、真实模型、SSH 或第三方服务。
- 模板各自通过编辑器与 Host 图校验。调度器的本地故障注入覆盖认领后重启、同一 run ID 重试、工作流删除或跨项目、已完成节点的续跑幂等与结果未知。原自动化仍按原逻辑运行。
- 运行根类型检查、lint、架构检查及相关离线测试；未做真实模型和目视复核时如实记录。
