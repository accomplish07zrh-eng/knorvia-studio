# Studio 跨内核资源投影

2026-09-23。Studio 中已启用的技能、插件技能和 MCP 应在接入的内核会话中可用；原生插件钩子、命令、代理不是通用协议，界面及错误不得把它们描述成已跨内核执行。

## 唯一所有者与边界

- SkillsService 仍是技能发现、启停与插件技能的事实来源；McpSyncService 仍是 Studio MCP 配置来源。外部 CLI 原有配置和凭据不由 Studio 修改。
- StudioRuntime 的 Node 适配层只在每次外部内核 turn 派发前读取这两个服务，生成一次不可变投影。Knorvia 内核仍用本来的技能、插件和 MCP 运行时，避免双重注入。
- 已启用技能给每个外部 turn 一个有界目录（名称、简介和 SKILL.md 路径）；显式 `$skill` 引用时复用 SkillsService 的正文展开结果。技能目录不是工具权限；无法读取路径时内核须说明，不能伪称已执行。
- 启用的 Studio MCP 按 workspace 优先于 user、同名遮蔽规则生成快照；即使 workspace 中该项停用，也不能重新启用同名 user 项。配置缺失、传输不受支持或带无法转换的字段时，在原生发送前明确报错，并将此类前置失败记为结果已知。凭据不可写入提示词、状态警告或日志。
- MCP 只通过内核原生的本次会话参数注入，不修改 `~/.codex`、`~/.claude` 等外部配置。Codex 使用 app-server 线程配置覆盖；Claude Code 使用本次进程 `--mcp-config` 指向 Studio 私有临时文件并在执行结束清理；ACP 内核使用 `session/new` / `session/load` 的 `mcpServers` 并核对原生传输能力。
- 插件贡献的 SKILL.md 与普通技能共用上述路径。已启用插件中无动态变量、私有认证或 broker 的标准 stdio/HTTP MCP 可投影为外部会话工具；原 manifest 里明确写出的字面量环境变量和 HTTP 请求头仅进入本次原生协议，不进入提示词、状态警告或日志。插件的启用状态与名称使用原插件服务结果。不能安全投影的插件 MCP 在模型选项页显示名称与原因，群聊和工作流再记录一次运行进度提示。插件钩子、命令、子代理不跨内核执行。

```text
Studio 技能 / MCP 配置（单一事实源）
    → 外部 turn 的有界快照 → 各 CLI 原生会话配置 → 执行 / 明确拒绝
    → 内核完成后清理本次临时配置
```

## 验收

- Skill 启用/停用、用户与项目作用域、插件提供的 skill、显式 `$skill` 均以同一服务结果为准；普通 turn 只有目录，正文不会全量灌入。
- 同名 MCP 按项目优先；禁用项不会漏到内核；无效或内核不支持的传输不得静默丢失。投影不接触外部 CLI 全局配置。
- 对 Codex/Claude/ACP 的参数映射有协议级单测；无凭据输出；临时文件清理和停止路径可验证。
- 启用插件的静态标准 MCP 可注入；需要插件私有凭据、官方认证、专属 broker、动态变量或其它传输的 MCP 保持 Knorvia 内核专用，并在所选外部内核的资源兼容提示中列明。
- 根类型、lint、架构检查及目标服务测试按实际结果报告。
