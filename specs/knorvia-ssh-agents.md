# SSH Agent 与原生命令接入

更新：2026-09-23。延续 `knorvia-backend.md`、`knorvia-cli-expansion.md` 的单聊、群聊、工作流所有权与原 GUI 约束。

## 产品规则

- Agent 管理提供明确的「连接 SSH」入口，复用现有远程工作区向导及密码、私钥、SSH 配置认证。连接成功并选择远端项目目录后，检测远端 Host 中真实安装且通过协议探测的 CLI。不可只根据 `PATH` 命中就显示可用。
- 每个远程 Agent 的身份由稳定的 SSH 工作区身份与原生内核 ID 组成；同一个群允许本机与多台服务器的同类 CLI 同时加入。显示名称含主机与项目，图标继续映射原生内核。SSH 凭据只归连接层所有，不进入群定义、Studio SQLite、日志或模型提示。
- 本机 Studio Host 拥有单聊、群聊、工作流的定义、队列、时间线、审批、停止与结果不确定状态。远端 Host 只执行绑定到该 SSH 工作区的成员。远端离线时不回退本机 CLI，不把其他服务器同名目录或同名 CLI 当作替代品。远端重连后按稳定身份恢复；结果不确定的派发仍需人工明确重试。
- 每个远程工作区使用其已选择的远端绝对项目目录。跨主机文字上下文由本机群聊编排器提供；文件修改留在各自项目/隔离目录并标明主机来源。不得把远端路径当成本机路径扫描、应用或打开。共享目录模式只在用户明确选择且目标确实是共享文件系统时使用。
- 原生命令目录必须来自实际 CLI 协议或其明确的命令接口，按当前内核、会话和工作区展示。未提供命令目录的 CLI 不显示猜测的命令。命令发送应走原生协议支持的路径；不能把 UI 自身 `/` 命令或其他内核命令误送给当前 CLI。远端内核采用远端提供的命令目录。

## 状态与接口

`WindowRemoteConnectionRegistry` 是 SSH 认证、连接及工作区绑定的唯一所有者。`StudioKernelRegistry` 从桌面 Host 注入的只读远端环境解析器发现可用远端 Studio 服务；复合 Agent ID 仅是稳定路由键，不携带密钥。远端 Host 的 Studio runtime 负责原生 CLI 运行、模型与命令目录；本机 Studio runtime 负责汇总、持久化和本地 GUI 投影。Web/手机连接桌面 Host 时读取同一本机 Studio 状态；SSH 连接只属于桌面窗口 Host，手机不能自行创建另一套远端执行进程。

```text
Agent 管理 → 现有 SSH 向导 → window-scoped connection registry → 远端 Host
                                       │ 已绑定稳定 workspaceIdentity + path
                                       ▼
本机 Studio Host → 远端内核目录探测 → 复合 Agent ID → 单聊/群聊/工作流
本机 run owner → 隔离项目准备/远端路径绑定 → 远端派发 → 远端时间线轮询
             ← 增量事件/审批/结果 ← 远端 Host；本机时间线持久化
用户停止 → 本机 run owner → 远端 cancel → 终态确认；失联则保留未知
```

所有命令使用稳定请求 ID；网络丢失不能凭超时宣称远端未执行。每次群聊成员轮次冻结远端身份和项目目录。重连只接受同一身份，不能按路径或内核名称盲配。远端原生审批通过本机群聊交互转发，取消须传到远端并观察终态。

## 验收

- Agent 管理一键打开既有 SSH 向导；连接与认证不另造表单。远端实际可用 CLI 在管理页和内核选择器出现，并显示来源；断线显示离线，禁用新派发。
- 在同一个群里选择本机 Codex、SSH A 的 Codex 和 SSH B 的 Codex，身份不冲突，主持人能调度各成员；单聊选择任一远端 Agent，保持原 Knorvia 聊天界面。
- 远端工作区与本机路径相同或不同、两台远端路径相同、断线与重连、审批、停止、运行中关闭主窗口、未知结果及重试均按对应身份处理；无本机静默回退。
- ACP 原生 `/` 命令出现在单聊输入建议，其他 CLI 只展示已核验的命令；切换内核后目录随之更换，命令与模型选择保留该内核原生语义。
- 相关自动测试、类型、Lint、架构检查及桌面便携包 GUI 验证均实际执行；没有可用 SSH 目标时用可控协议夹具验证，并记录实机 SSH 验收限制。
