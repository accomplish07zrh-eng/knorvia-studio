# 群聊第二遍端到端打磨

2026-09-23。后端仍是正式定义与运行 owner。

1. 发送开始时捕获停止 epoch。保存定义等待期间发生过任何停止，即便终态快照已经解除输入冻结，该次旧发送仍不得继续派发。
2. 群定义保存与删除 ACK 的 revision 记录在草稿 store。未追上 ACK 的 overview 不能覆盖已确认模式/成员/项目，不能复活已删除群，也不能暂时隐藏刚创建的群。群列表和发送都读取同一投影；等 overview revision 追平后回到服务正式定义。
3. ACK 不改变未提交输入。重开保留 revision 收据，未知旧格式没有收据则按原迁移方式处理；损坏原记录保持禁止覆盖。
4. 工作流复制、导入、新建等异步操作绑定触发时的页面代次和服务。操作可完成已提交的保存，但切换到其他定义、离开后返回、服务变化或卸载后，旧回执不得抢走选中项，也不得把旧错误或导出成功提示显示到新页面。删除自身导致选中项清空仍应正常关闭原确认框；旧操作不能关闭后来打开的确认框。

```text
编辑 → command → ACK(revision) → store 收据 → 群列表/发送投影
overview revision < 收据：使用已确认定义；追平后：使用服务定义
发送捕获 stop epoch → save-group → 检查同 epoch → send
```

验收：停止、终态快照、旧 save ACK 的交错顺序；模式 ACK 后旧 overview 中立即发送；新建与删除 ACK 后旧快照；收据重开；更新定义不清草稿。只运行针对性离线回归，不调用模型、不操作用户数据。
工作流补充验收：普通 ACK 可导航；等待期间选择另一定义及离开后返回时禁止导航/提示；服务变化和卸载后禁止旧 UI 回执；成功删除原确认框可关闭而新确认框不会被旧完成回执关闭。
