# Knorvia Studio 阶段 1：Windows 本地交付

2026-09-25。按《Knorvia Studio 下一步规划》T1.1–T1.4 执行；只在本机和隔离夹具中验收，不使用真实模型、已登录 CLI、远端 SSH 或账号。本规格先于实现。

## T1.2 只读更新检查

- Settings Service 是 `releaseInfoUrl` 与 `releaseChecksEnabled` 的唯一持久状态所有者。URL 默认为空、开关默认开启；空 URL 必须显示“尚未配置更新源”且不能联网。只接受 HTTPS 地址，或用于本机测试的 loopback HTTP 地址。URL 不得携带用户名、密码或 fragment。
- Desktop Main 是检查结果的唯一运行时所有者。它读取设置与当前构建版本，按需向 URL 发送一条无凭据 GET 请求；响应只接受有界 JSON（GitHub Release 的 `tag_name/html_url/prerelease`，或等价的 `version/url/prerelease`），按 semver 比较。正式版用户不收到预发布版提示。畸形版本、畸形 URL、HTTP 错误、超时、限流、离线都返回“检查失败”，不能伪称已是最新。
- App ready 后 30 秒进行首次检查，此后每 24 小时检查一次；设置中“检查更新”调用同一逻辑。关闭开关后定时和手动检查都不发请求。检查只提醒，不下载、不安装、不打开登录或发布页面。
- 更新可用时仅在本地提醒一次同版本（单进程内）；设置页显示最近手动结果和真实错误。状态不写入配置，以免旧结果跨重启伪装为新结果。
- 离线测试覆盖未配置、关闭、已是最新、可用更新、正式版屏蔽预发布版、404、429、离线、超时和畸形 JSON。测试通过替代 fetch，不访问真实更新源。

## T1.3 首次启动引导

- 新配置且尚未完成第一条消息时显示三条路径：连接现有供应商模板、选择已真实探测到的本机 CLI、稍后再说。引导显示状态由 Settings Service 持久化；供应商清单和 CLI 探测各由现有服务持有，不复制凭据或伪造连接。
- 选择供应商打开现有设置；选择 CLI 只选已探测项并沿用原有设置；跳过和中途退出不会提交消息。第一条消息被接受后持久标记完成，之后不再显示。
- Knorvia 中转可作为普通模板，不能置顶、默认或预填 Key。新配置、已有配置、跳过和中途退出都用本地替身验收。
- `studioFirstRunGuideStatus` 由本机 Settings Service 独占：全新配置默认 `pending`；升级前已有设置文件而缺少此字段时迁移为 `legacy`，不对老用户补弹引导。`pending` 仅在现有偏好引导结束、进入本机工作区且设置页未打开时显示。`legacy` 和 `complete` 不显示；用户明确“稍后再说”写 `deferred`，关闭窗口或转入设置/CLI 只在本次运行隐藏，下次启动仍可继续。
- 引导从本机 Studio 内核目录读取探测结果，只列 `installed=true` 的本机 CLI；检测中、失败、未安装与“已登录/可用额度”不能混为一谈。选择 CLI 仅切换到现有对话入口，不自动发送、登录或执行。连接供应商跳至现有模型设置页，不创建默认供应商或预填凭据。
- 内置单聊、外部 CLI 单聊和群聊的发送命令获得接受回执后，向应用根层报告第一条消息已接受；根层将 `pending/deferred` 写为 `complete`。被阻止、需确认、失败、空草稿、取消、仅创建会话均不得完成引导。若本机设置写入失败，保留待完成状态并在下次启动重试。

## T1.4 手动诊断包

- Desktop Main 生成唯一的诊断清单：版本、系统、内核探测状态、最近三天脱敏日志。预览和最终导出读取同一份冻结清单，防止查看后文件变化导致内容不一致。用户必须主动触发；无自动上传。
- Host 的 Studio 内核目录仍是探测结果的事实源。设置页只把本机内核的 ID、显示名、安装状态、版本和来源投影给 Desktop Main；不传可执行路径、认证状态或原始错误。Main 校验有界投影，生成随机预览 ID，将脱敏日志与系统摘要冻结到私有临时目录；导出只能引用这个 ID，不能让 renderer 选择任意本机路径。
- 原日志文件名可能含私人信息，冻结包中的日志按应用、CLI、辅助进程来源编号为 `logs/app-*.log`、`logs/cli-*.log`、`logs/helper-*.log`，不暴露源文件名；内核显示名、版本和 ID 在写入 JSON 前再次脱敏。
- 预览列出冻结包内每个文件的名称、字节数、SHA-256 与开头摘要；摘要截断时明确标识。导出 ZIP 与预览记录的哈希逐项相同，源日志后续轮转也不改变此包。临时目录在导出后或到期后清理；应用不主动上传。
- 只收允许的诊断文本，不收用户会话、凭据、临时 MCP 配置、创作任务、旧转储或二进制。预览显示文件名、大小及正文摘要；导出 ZIP 的内容与预览清单一致，测试注入虚构密钥后扫描 0 命中。

## T1.1 最终本地交付

- 最终版本固定为 `0.8.0-preview.1`（对用户显示 0.8.0 预览版）；所有阶段功能与检查完成后，设置 `KNORVIA_ENV=production` 构建 Windows 安装包、便携版 ZIP、`SHA256SUMS` 和发行说明。构建前不得取走或覆盖用户数据。
- 安装包构建时不设置 `KNORVIA_PORTABLE_BUILD`，避免安装后的程序误把安装目录当成便携数据根；便携 ZIP 从同一份已验证的 `win-unpacked` 字节复制到隔离产物目录，仅在那里添加 `resources/knorvia-portable.json`。安装版与便携版均须验证版本和数据根。
- 本轮不申请代码签名证书，不登录签名平台，不上传发布仓库。发行说明必须标明未签名可能触发 SmartScreen、真实模型/CLI/SSH/更新服务与跨设备未验证。
- 使用独立 Windows 测试数据根和本机服务替身，验证安装/便携启动、设置保存、一次模拟对话以及卸载与数据保留规则；最终交付后再核对安装包和 ZIP 散列。若覆盖桌面便携目录，先确认应用未运行，并在前后逐文件校验 `data` 散列，不创建多余备份。
