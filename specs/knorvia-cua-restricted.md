# Knorvia Studio 受限电脑控制契约（T12）

本规格定义**受限（restricted）**电脑控制的契约：观察是什么、允许哪些动作、目标窗口如何界定、
过期观察如何拒绝、停止为什么必须先禁止后续动作、结果未知为什么不得自动重放，以及状态所有者是谁。

**前提事实（必须先读，避免把占位实现当成能力）：** 当前构建里的 `@knorvia/cua` 是**故意 fail-closed 的占位包**。
`createComputerUseRuntime().execute()` 固定返回「not available in this build」；`callBrokerMethod` /
`dispatchRequest` 直接抛错；`isReadOnlyBrokerMethod` 硬编码为 `false`；`probeHelperHealth` 只返回 null；
PiP 客户端被禁用；`isScreenCaptureProbeSuccess` / `shouldRunCuaScreenCaptureProbe` 恒为 `false`；
`launchStandaloneCuaHelperForStatus` 仅 darwin。**因此本规格描述的是契约与门禁，不是已具备的能力：今天在本仓库任何平台上都做不出一次真实观察，也发不出一个真实动作。**

## 1. 唯一所有者

| 职责                                          | 所有者                                                          |
| --------------------------------------------- | --------------------------------------------------------------- |
| run / turn 状态、审批请求、动作结果、审计记录 | Studio Runtime Host（现有运行时，`specs/knorvia-backend.md`）   |
| 观察采集与动作执行的进程监督、转发            | 桌面 Main（只监督 Driver 进程，不保存会话业务状态）             |
| 观察、审批与停止入口的展示                    | Renderer                                                        |
| 本机 Driver / Helper 的可用性事实             | 既有 CUA 装配（`packages/services/src/cua-permission-broker/`） |

硬规则：

- **不新增第三个 Agent、第三个运行时或第二个决策服务。** 审批、结果记录与终态读取都留在现有
  Studio Runtime Host 内；本规格不引入任何新的状态所有者，也不让模型获得无限制的桌面入口。
- 模型只能提出「受限动作请求」，不能自行扩权、不能自行提高权限模式、不能自行决定前台化。
- 门禁判定是**纯函数**：输入是已经存在的事实（Driver/Helper 可用性、观察记录、权限模式、目标窗口、
  run/turn 标识），输出是 `allow` / `refuse` + 机器可读原因码。门禁不做 IO、不启动进程、不申请系统权限。

## 2. 观察（observation）契约

一次观察是对**某一个窗口**在**某一个瞬间**的可复核快照，它是后续动作的唯一坐标来源：

```text
observation = {
  observationId      唯一标识
  observationVersion 单调递增的版本号；同一个窗口上每次重新观察都会 +1
  capturedAt         采集时刻
  expiresAt          失效时刻（必须显式给出；不允许「永不过期」）
  runId / turnId     归属的 run 与 turn
  windowId           目标窗口标识（与动作请求里的窗口必须一致）
  contentRef         快照产物引用（图像/无障碍树）；本构建不会产生
}
```

硬规则：

- 观察**必须带版本**。动作请求必须引用它使用的 `observationVersion`；版本对不上就是过期。
- 观察**必须带失效时刻**。没有 `expiresAt`、或 `expiresAt <= 当前时刻` 的观察一律按过期处理。
- 观察不是权限：拿到观察不等于获得执行权。执行权仍由权限模式 + 审批共同决定。
- **本构建不产生任何观察。** 占位实现没有采集路径，`observation` 只能由调用方合成的夹具提供，
  用于验证门禁逻辑，不能当作产品能力。

## 3. 允许的动作与目标窗口

允许的动作是**有限白名单**，每一条都必须显式声明目标窗口：

| 动作类别   | 允许的内容                                | 说明                      |
| ---------- | ----------------------------------------- | ------------------------- |
| 观察       | 读取目标窗口的界面状态                    | 只读；不改变被观察应用    |
| 定点输入   | 对已观察到的元素做单次点击 / 单次文本输入 | 必须引用该元素的观察版本  |
| 结构化读取 | 读取无障碍树 / 控件值                     | 只读                      |
| 停止       | 停止当前 run 的后续动作                   | 见第 5 节，优先级高于一切 |

硬规则：

- **动作必须携带 run/turn、目标窗口、观察版本与请求 ID，并在派发前重新校验。** 任何一项缺失即拒绝。
- **不得静默扩大范围。** 动作请求里的窗口与观察窗口不一致 → 拒绝；目标不在观察可见范围内 → 拒绝。
  门禁不提供「就近匹配」「取第一个窗口」这类猜测路径。
- **不得自动取得前台/焦点。** 后台默认不移动鼠标、不切换前台窗口、不改变键盘焦点。
  需要前台的路径必须由用户针对**本次运行**显式批准；后台路径失败时**不得**静默改走前台路径。
  `isReadOnlyBrokerMethod` 当前恒为 `false`，因此本构建里没有任何方法被判定为只读可用。
- 权限模式只由可信启动者设定，**模型不能提高权限**。模式不足即拒绝，不做「降级尝试」。

## 4. 过期观察的拒绝规则

- 观察过期（`expiresAt` 已过）、版本不匹配、来自其他 run / turn / 窗口：门禁**必须拒绝**，原因码分别为
  `observation_expired` / `observation_stale_version` / `observation_scope_mismatch`。
- **绝不重放过期坐标。** 拒绝后不得用旧坐标重试、不得让模型「猜一个位置」、不得退回截图定位的隐式路径。
  正确做法是重新观察一次，拿到新的 `observationVersion` 后重新走审批。
- 过期拒绝是**可预期结果**，不是错误重试条件：面板/日志应明确显示「观察已过期，需要重新观察」。

## 5. 停止优先（stop-first）

停止请求的处理**顺序固定，不可重排**：

1. **先禁止后续动作**：把该 run（必要时到子任务）标记为停止中，此后任何新的动作请求一律拒绝
   （原因码 `run_stopped`），包括已经进入队列但尚未派发的请求。
2. **再取消当前请求**：取消正在派发/正在等待回执的那一个请求。
3. **最后读取真实终态**：重新读取目标窗口与 Driver 的实际状态，把结果写成 run 的真实终态，
   **不**沿用请求侧的乐观状态。

硬规则：

- 顺序不可交换：先读终态再禁止动作，会在读取窗口期内继续派发新动作。
- 需要前台权限的动作在停止时，**不得**为了「收拾干净」而临时前台化目标窗口。
- 停止**不能**被表述成「动作已撤销」。停止只保证「不再派发新动作 + 取消当前请求」，
  已经下发但未收到回执的动作按第 6 节处理。

## 6. 结果未知（unknown result）

- 已下发但无法确认是否生效的动作，结果记为 **`unknown`**，并且**永不自动重放**。
- 自动重放会产生重复点击、重复提交、重复删除等不可逆副作用；`unknown` 必须交给用户决定
  （重新观察后再确认，或人工处理），并提供可复核的证据引用。
- `unknown` 不是失败也不是成功：不得据此判定任务完成，也不得据此判定任务失败。
- 本构建不派发任何动作，因此**不会产生真实的 `unknown` 结果**；该规则只由纯逻辑测试覆盖。

## 7. 本构建能力的如实陈述

**当前构建无法观察任何东西。** 具体地：

- 没有可启动的 Helper / Driver 进程（`start` / `restart` / `checkHealth` 全部 reject；`running` 恒为 `false`）。
- 没有观察路径：`probeHelperHealth` 只返回 null，`isScreenCaptureProbeSuccess` 恒为 `false`。
- 没有真实点击或输入：`callBrokerMethod` / `dispatchRequest` 直接抛错，`isReadOnlyBrokerMethod` 恒为 `false`。
- 没有真实模型决策、没有按内核的运行时验证。

因此本规格的验收**只能是纯逻辑的**：门禁在 Driver 不可用、观察过期、run/turn/窗口不符、权限不足时拒绝；
停止优先会禁止后续动作；结果未知不会被自动重放；实验开关默认关闭且打开时不启动任何东西。
**任何「已经能看屏幕 / 已经能点一下」的表述都是不成立的。**

## 8. 实验开关（默认关闭）

设置页「电脑控制」分区上的受限实验开关满足：

- **默认关闭**，且只影响本进程内的偏好，**不写入插件状态、不写入任何持久配置**。
- 打开时不启动 Helper、不发网络请求、不触发任何操作系统权限弹窗、不改变 `@knorvia/cua` 的任何导出取值。
- 面板必须同时显示当前诚实状态：`不可用 / 无法观察`，并列出停止优先规则（先禁止后续动作、再取消当前请求、
  最后读取真实终态）。
