# 全量布局与界面打磨（2026-10-09）

用户要求全量打磨布局与 UI，各处都要照顾。本轮先用真实 Web 客户端（同一套 UI 组件）在浅色／深色、1440／1280／900 宽桌面与 390 宽手机下逐页截图审查：首次引导三步、单聊（Knorvia 与外部内核）、工作台、群聊、自动化、工作流、创作、插件，以及设置全部 13 个分区。

## 审查结论

| 位置                           | 问题                                                                                                       | 处理                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 手机／窄屏 Web（< 768px）      | 内容侧栏固定占约 250px，主内容被挤到约 140px，问候、输入框、自动化与创作页被截断；且窄屏没有收起侧栏的入口 | 侧栏改为覆盖内容的抽屉：窄屏默认收起；左下角圆形按钮打开；遮罩点击或切换页面／会话后收起 |
| 工作台待命格                   | 内核选择与项目目录为原生方角控件，与全局胶囊输入不一致                                                     | 胶囊外观、自绘下拉箭头、标签改为次级文字                                                 |
| 创作页描述框                   | 原生拖拽角露在圆角卡片右下                                                                                 | 随内容自动增高（上限 16rem），去掉拖拽角，卡片圆角与聊天输入一致                         |
| 深色主题、设置各分区、桌面宽窄 | 未发现对比度、错位或溢出问题；设置各分区共用同一内容宽度                                                   | 无需改动                                                                                 |

未在本轮处理：内置插件、技能、子智能体的描述来自各插件自带的英文清单，中文界面下仍显示英文，需要单独补充清单的中文字段。

## 规则

- 窄屏判定沿用活动栏断点（`min-width: 768px`）：宽屏与桌面应用行为完全不变。
- 侧栏可见性仍由 `useAppPanels` 唯一持有；窄屏首次挂载默认收起。抽屉开关只调用既有 `handleToggleSidebar`，不新增状态。
- 抽屉收起的触发：点遮罩、主视图变化、当前会话或外部会话变化。

## 验收

- 390×844：首页主内容占满宽度；打开抽屉后侧栏覆盖内容、遮罩变暗；点遮罩收起（截图验证）。
- 桌面 Electron 侧栏与布局冒烟全部通过（宽屏行为不变）。
- typecheck、lint、fmt、架构、来源清单与 UI 测试。
