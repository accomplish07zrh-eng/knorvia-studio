# Knorvia Studio 视觉语言

2026-09-24。用户要求 Studio 摆脱 ZCode 的面貌、建立自己的视觉语言，并明确：以纯净白黑为主，不要粉色/紫色；不要左黑右白，同一色系以深浅区分；视觉语言不能只是颜色。不受官网（海边玻璃房）风格影响。本规格取代 clean-base 中「保留上游白色主题取值」的部分，其余 GUI 结构、组件与交互不变。

## 语言：从 Knorvia 图标长出来

1. **色彩（黑白、同色系）**：所有中性色为零色相灰阶。浅色：白色工作区（纸）落在 #f3f3f4 浅灰外框与侧栏上；深色：#131313 工作区落在 #0a0a0a 更深的外框与侧栏上；卡片、菜单、输入框依次提亮一级。主操作浅色纯黑、深色纯白；提示气泡反相。无紫色、粉色、玫红；语义色（成功、警告、危险、差异、git）保留语义，只调色温。
2. **丝带（形状）**：K 由两条两端圆润的丝带构成 → 操作是胶囊或圆形（按钮、导航项、分段/标签、单行输入与下拉触发器、发送按钮）；承载内容的容器是大圆角「软板」（圆角刻度 sm 6 / md 9 / lg 12 / xl 16 / 2xl 22 px，层级规则不变）。拼接成组的按钮保留连接形状；菜单项保持紧凑。
3. **纸片（层次）**：选中不是灰色色块，而是一张微微浮起的纸片（浅色白纸、深色 #222 灰片），带极细描边与阴影；工作区面板同样是一张纸。
4. **三道笔画（母题）**：图标上的三道光化为三段深浅递减、带 K 斜度的短画，只用黑白；用在空会话问候上方。
5. **细线与轻动效**：图标线条统一 1.6；悬停/按下使用统一缓动 `cubic-bezier(.2,.8,.2,1)`，按下轻微回弹（scale .97）；尊重减少动态效果。
6. **字体**：Windows 优先 Segoe UI Variable Text，中文依次回落 PingFang SC / HarmonyOS Sans SC / MiSans / 微软雅黑 UI；问候等标题加重、收紧字距。
7. **引导主视觉**：黑白银灰；标语为 Knorvia 自己的文案（「一张安静的工作台。」）。

## 实现与所有权

- 取值唯一来源：`packages/ui/src/styles.css` 中 `.theme-knorvia-light` / `.theme-knorvia-dark`（色彩与 `--knorvia-*` 变量），以及文件末尾「形状、层次、笔画与动效」一节。按 2026-09-24 用户追加要求，主题 ID 与 class 名统一为 `knorvia-*`，界面仍只显示「浅色 / 深色」。CSS 选择器更名不改变任何颜色、圆角、图标或布局取值。
- 主题偏好唯一读取规则位于 shared：接受新 ID、light/dark/system，以及已有存储中的旧主题 ID；旧 ID 只在读取边界映射到新值，不再写出。React 初始化时持久化归一后的偏好；Desktop/Web 首屏内联脚本在 bundle 之前同样识别旧深色偏好，避免迁移时白屏闪烁。系统跟随仍随媒体查询变化。
- 验收覆盖旧浅/深色与 system 偏好、无偏好时浅色、Desktop/Web 首屏及 CSS class 一致；比较更名前后 CSS 声明正文完全相同。浏览器截图或应用级切换测试补充验证，无可用浏览器时明确记录。
- 形状与层次通过既有稳定钩子统一实现，不引入新状态：`data-slot`（button、tabs、input、select-trigger）、`.bg-selected`、`data-knorvia-composer`（主输入框与群聊输入框外壳）、发送按钮的既有 test id、`data-v4-draft-greeting`、导航按钮的 `aria-pressed`。
- 引导主视觉配色：`openWorkspacePageThemeHero.tsx`（`KNORVIA_LIGHT_HERO` / `KNORVIA_DARK_HERO`）。

## 验收

1. 浅色与深色都是同色系深浅分层，无左黑右白、无紫粉色。
2. 胶囊/圆形操作、纸片选中、三道笔画、细线图标在主页、工作流、群聊、设置、引导页可见且一致。
3. 输入框聚焦、发送可用/禁用、导航选中、提示气泡、键盘焦点在两套主题下正确；减少动态效果时无动效。
4. 在隔离配置中截图核对；原有功能与数据不受影响。
5. 根 typecheck、lint、architecture 检查按实际结果报告；更新便携包时保留 `data`。
