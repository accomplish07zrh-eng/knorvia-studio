## 已确认的修正

1. 单聊原生会话标识回执只合并其拥有的 `nativeSessionId` 和更新时间。会话选择由命令接收拥有，后到原生回执不得以开始执行时的旧快照覆盖后来排队消息的模型、思考档位或标题。排队运行已冻结参数保持不变。
2. 内核撤销单个问题时，适配器通过 `StudioKernelSink.ask` 的可选单问题取消信号通知 Host。该问题立即过期，拒绝迟到答案；其余问题与原生轮次继续，不把局部撤销升级为全轮失败。原生取消和终态也使用同一信号收口问题等待，不能遗留轮询。
3. 画布与执行器通过公共浏览器安全契约共享现有 `validateStudioWorkflow`、`studioConditionReferences`，保持单一语法、图结构和祖先引用规则；不引入第二个解释器或状态副本。
4. 审批接收端检查本次请求真实提供的 choices，拒绝未提供的“本会话允许”等选项；不能依赖 UI 隐藏按钮作为唯一限制。
5. 工作流公共校验与接收边界统一为 200 节点、800 连线。
6. 群插话收件箱查询必须先筛选 pending 再按最早接收排序取有界批次，已消费历史不能挤掉旧待处理说明。等待与过期判断同样先筛选 pending 交互，不受最近 1000 条历史页影响。
7. 文件应用失败时，Host 先调用已有差异／恢复路径确认日志是否已安全收口。恢复仍失败则保留项目锁并标记需要恢复，阻止新任务进入；用户重新查看修改可再次恢复，只有成功后清锁，不要求退出应用才能处理。成功应用和已安全回滚的失败正常释放锁。
8. RPC 边界要求未知副作用重试确认是实际布尔值，不能把字符串 `"false"` 当成同意；内核管理操作在任何探测或安装之前检查固定 action 与 kernel，未知 action 不得落入安装分支。

```
用户排队选择 → command admission → 当前 conversation.selection
原生 session 回执 ─────────────────→ 只合并 nativeSessionId

原生撤销请求 → KernelRun 单问题 AbortSignal → Host expire interaction
                                              └→ UI 同一 revision 快照
```

验收使用离线夹具：暂停原生 session 回执后排队不同模型、撤销问题后保持轮次存活并尝试旧答案、重复请求幂等、取消不影响其他问题与运行。真实推理、安装及用户数据不属于此独立工作区验收。
