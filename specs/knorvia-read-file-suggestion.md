# Read 缺失文件建议

2026-09-30。仅替换 Read 的缺失文件名候选算法与私有端口适配，不改变读取、权限、缓存、UI 或用户文件。固定编辑距离阈值为3，用有界动态规划判断是否在阈值内，不计算无用的完整距离。仍保留来源暴露与过渡许可，不作MIT或整份Read独立完成判断。

调用 Read → 原not_found错误 → 当前FileSystemPort列举父目录 → 名称候选选择 → 原错误消息与cause。只有文件和符号链接参与，排除目标同名项，使用JS默认UTF-16字典排序。先全局寻找同stem（宿主basename/extname规则）候选，再取排序后第一个UTF-16 Levenshtein距离不超过3的候选，不改成最近距离或locale排序。不遍历子目录、不尝试打开候选、不增加IO。

新算法以长度差先排除，保留每行对角线左右3格；使用饱和值和有限行缓冲，只回答阈值谓词。UTF-16 code unit行为与旧算法一致，不能换成Unicode码点、转置距离或大小写归一化。当前端口缺失或列目录抛错（包括取消）仍不附建议；原Read not_found错误转换和可恢复性保持不变，信号和原五字段trace传给单次列目录。

验收先跑原handler端到端合成端口测试，固定同stem优先、排序、类型过滤、空/大小写/Unicode与阈值边界、列目录失败、动态端口、错误cause。新候选函数以完整矩阵参考实现做穷举/种子随机差分，再验证真实Read source/dist、根与CLI质量门及全量。实际磁盘和原生平台结果另行验证，不用计时阈值代替功能断言。

显式lint暴露原Read入口仍超过400逻辑行。为遵守仓库限制，本步将原模型内容格式化函数完整迁到私有read-model-content模块，函数体和字符串不改，入口仅改import；这是机械保留/迁移，不计作独立重写。原文本、图片、视频、PDF消费者及fallback行为一起回归。测试参考矩阵也避免含义不清的新数组单参数写法。

Edit 事务替换复用同一候选入口（见 `knorvia-edit-transaction.md`），不另建第二套阈值算法。该私有模块保留既有名称以免扩散改名；它只返回候选名称，Read 与 Edit 仍各自拥有原始错误/cause 或失败 envelope。现有 Read 合同不变，Edit 的缺失文件与列举失败合同另行覆盖。
