# 执行宿主的构建与产物提交

2026-09-28。独立替换 node-repl-host 的构建入口，保留调用者使用的 `buildNodeReplHostBundle({ outfile?, cuaHelperBuildId? })`、默认目标、ESM/Node 24、依赖打包、尾部合法声明和 CommonJS require 兼容横幅。编译器仍是已署名的 esbuild，不宣称编译器属于 Knorvia。

## 所有者与顺序

每次构建调用独占自己的内存编译结果和临时文件；最终路径只有一次完整文件替换。构建入口不成为运行时会话或插件配置所有者，也不改变 CUA 驱动来源与审批。

```text
参数与既有环境默认值 → esbuild（write:false）→ 核对单一预期输出
                                                ↓
                                  同目录独占临时文件 → rename 最终路径
                                                ↓
                                      失败时只清理自己的临时文件
```

- 缺省输出仍为此包 dist/mcp/server.js，显式相对路径按调用进程 cwd 解析；返回的 outfile 保持调用者传入的原写法。入口源码位置不随 cwd 改变。
- 缺省 helper build id 取现有 KNORVIA_CUA_HELPER_BUILD_ID 并 trim，未提供时为空。显式参数不做额外清洗；使用 JSON 字符串编码注入定义，不能拼接可执行代码。没有新增环境变量。
- 编译先只写内存。要求恰好一个输出且目标与请求一致，再创建父目录、独占写入同目录临时文件并 rename。依赖编译失败或输出不符时不发布；写入/rename 失败保留既有目标，删除本调用临时文件。
- 临时文件使用不可复用的随机名和 exclusive 创建；不写 .bak、不递归删除目录、不清理其他构建的临时文件。并发构建仍各自发布完整结果；不声称拥有跨进程业务锁或断电持久性。
- 正常返回仍为 outfile/cuaHelperBuildId；发生错误向调用者传播。清理失败与原失败均可见，不用成功状态掩盖。导入脚本不自动构建，直接执行脚本才使用默认参数开始构建。
- 构建时没有 UI、产品用户数据、网络推理、浏览器/桌面操作或安装步骤。现有实际宿主测试仍构建并验证 stdio/Worker；Windows helper 的构建身份不得丢失。

## 验收与来源

先建立公开函数参数、编译选项、返回值和未授权发布的失败场景，再实现内存编译与提交顺序。离线替身覆盖默认/显式参数、编译异常、非单一/错误目标输出、提交前旧文件可见、写入及提交失败、临时文件所有权和直接入口判定；实际构建及原宿主功能测试验证可运行性。运行根/CLI 类型和 lint、架构、全量离线回归，失败如实记录。

新实现与对应测试按逐文件记录使用 MIT。已有源码访问明确披露，兼容接口与 esbuild 配置常量不作为原创证明；包内配置和标准许可正文另外审查，不因本脚本替换而自动改判整包独立。
