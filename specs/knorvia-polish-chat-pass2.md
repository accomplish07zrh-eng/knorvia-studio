# 第二遍：单聊与设置交互完整性

## 范围与所有者

继续复用原 GUI。单聊空态使用原生 `max-w-2xl` 宽度，移除额外一层 16px 左右内边距；已发送对话保留原底部内边距。停止操作继续只依赖 service 可达，不能因 overview 失败而失效。

- 内核管理路径归 Host 的 `manageKernel` 所有。UI 安装/更新/卸载后只刷新，不再用请求前 config 整包覆盖服务最新字段。用户显式指定的外部 CLI 路径继续保留，安装受管副本不偷换路径。
- 终端字体、HTTP 代理、绕过规则、CA 路径使用同一小型异步字段控制：按设置服务和字段标识保存窗口内控制器，切页保留 pending、错误和未保存输入；不同服务隔离。保存期间同步防重、可继续编辑、旧成功响应不覆盖后续编辑、失败显示错误且保留输入；Enter 与按钮共用入口，IME 确认不提交。
- `studioAgentStore` 继续是外部单聊草稿唯一所有者。编辑和粘贴保持完整内容；20,000 字符限制用于持久化和发送，不截断。超限草稿保留在当前窗口内存，切换会话/设置回来仍完整；超限时整份本机草稿快照暂不落盘，不覆盖上次有效保存。缩短到范围后正常一次性保存，重试不能谎报超限内容已经保存。提示明确区分内存暂存与本机保存，关闭窗口前存在未保存内容时发出关闭确认。

```text
字段输入 → 字段控制器(draft/baseline/pending) → 单次设置写入
                                       ← ACK: 更新 baseline，保留 ACK 后的新 draft
管理按钮 → Host manageKernel → 服务原子维护路径 → UI refresh
聊天输入 → 草稿 store(完整内存文本) → 限额校验 → 本机持久化
                                          └→ 明确未保存提示/阻止发送
```

## 离线验收

1. 字段保存 A 未完成时编辑 B，A 的 prop 回流/ACK 均不擦掉 B；连点和 Enter 重复调用只有一次服务写；失败后保留文本并可重试；归一化只影响已确认值，不提前改用户输入。
2. 内核管理只调用 manageKernel，不提交旧 config；先前外部路径和期间修改的模型/权限由服务既有语义保留。禁止实际 CLI 安装和调用模型。
3. 超限文本逐字保留，保存/重试失败时旧磁盘值不变，切页读取仍为完整文本，发送入口阻止超限；缩短后恢复保存；旧发送 ACK 不清空新长草稿；关闭拦截在未保存时生效、保存或明确重置后撤销。
4. 原生与外部空态只有共同布局 padding，无额外 32px 缩窄；有消息时底部 padding 与停止可用条件保持。
