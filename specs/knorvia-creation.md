# Knorvia Studio 创作

2026-09-23 用户要求在原 GUI 加入“创作”，范围只含普通图片与视频生成。主侧栏在工作流后提供一个紧凑入口；页面继续使用原窗口、标题栏、颜色、字号和控件体系，不建立第二套壳。图片与视频是页内两种模式，不增加音乐、角色、素材市场或成果页。

## 所有权与边界

- Renderer 只持有当前模式、表单草稿和展示状态；配置、已接纳任务、生成文件由本机 Host 的 Creation Service 持久管理。入口切换或窗口关闭不能把已接纳任务变成前端假任务。
- Creation Service 通过独立 RPC contract 暴露模型配置、创建／查询／取消任务。API 密钥使用现有 Credential Service 加密保存；模型与任务列表绝不返回密钥。生成文件保存在 Knorvia 独立数据根下，不能触碰其他应用或旧配置的数据。
- 图片首批使用 OpenAI Images 兼容协议；图片和视频均可使用可配置 JSON API 或 ComfyUI API 工作流。主页面仅保留提示词、模型与生成；协议参数收入模型配置。没有配置模型时展示明确的配置入口，不能假装生成成功。
- 工作流画布可使用“创作”节点选择同一图片／视频模型；节点通过同一个 Creation Service 提交与查询生成任务，输入支持上游文本引用，输出文件路径进入节点结果，模型来源保留在创作任务记录。工作流的重试／恢复不得重复提交有未知结果的收费任务。
- 图片支持文生图与图生图：页面可附参考图；工作流创作节点可填当前项目的图片路径，或引用上游创作节点的输出路径；Agent 可通过创作 MCP 工具提交图片／视频任务、查询与取消，图生图参考图限当前项目或已有创作成果。各入口共用模型配置、任务记录和文件保存。Studio 群聊及外部 CLI 使用每轮注入；原生 Knorvia 单聊在建立本机会话时注入同一工具。没有安全每会话 MCP 注入能力的 CLI 明确提示不可用，不改写其全局配置。
- Studio Agent 在 `ask` 权限下每次生成都通过 Studio 交互确认，`read-only` 不能提交生成；原生 Knorvia 单聊沿用原内核 MCP 工具权限审批，生成工具标为有副作用，计划模式不得提交。工具使用本机桥接令牌，密钥和供应商请求留在 Host。Agent 只能获得任务状态与成果路径，不获得 API 密钥。
- 一次生成带稳定 idempotency key，避免应答丢失后重复收费。Host 接纳后异步执行，状态及文件落盘；重启时将未完成且结果未知的任务标记为中断，不自动重复提交。取消只能中止本地等待，界面需说明已提交的远端任务可能继续计费。
- 输出经 MIME 与大小校验后保存在本机。桌面预览复用已有授权媒体协议，导出复用现有平台保存文件能力。不得直接从 Renderer 携带密钥调用第三方接口。

## 页面

- 图片／视频切换、模型选择、简洁提示词输入、生成按钮、近期任务与预览在一页内完成。支持取消、查看失败原因和复用提示词；任务历史按时间倒序。
- 仅展示所选模型实际支持的参数。模型配置面板提供名称、协议、模型名、地址、密钥及 ComfyUI 工作流 JSON；密钥只写不读。禁用或配置不足的模型不能被提交。
- 使用 `text-ui-*` 字号与主题语义色；窄窗口和键盘可用。原侧栏、群聊、工作流、设置及聊天流不变。

## 验收

1. “创作”入口可进出、后退／前进；图片／视频页面与原桌面壳连续，亮暗主题无异常。
2. 无模型时不能提交，配置模型后能出现真实任务；失败、取消、中断均有真实状态，没有假预览或无限加载。
3. API 密钥在模型／任务 RPC 响应、日志和 UI 中不回显；便携版与其他应用各自使用独立数据。
4. 使用本地 HTTP fixture 验证图片与视频生成、图生图、幂等、取消、重启状态和输出校验；用真实 stdio MCP 握手验证 Agent 创作工具、权限标注、会话撤销与原生 Knorvia 单聊连接，不调用付费模型。完成 typecheck、lint、构建、架构检查与桌面 GUI 验证；更新便携包并保留 `data`。
