# 群聊与工作流隔离修改的差异审阅（T2.2）

2026-09-25。复用现有运行历史、原 GUI 的 `DiffViewer` 和 Studio Runtime 的隔离工作区；不新增页面或自动合并。

## 产品规则

- 群聊和工作流的隔离步骤结束后，用户从运行历史逐文件打开差异。文本文件显示真实隔离基线与成员产物的增删；新增/删除文件仍标明文件类型与路径。二进制文件不伪造文本预览，只说明不可预览。大文件按需展开，不在对话刷新时反复同步计算 diff。
- 每个文件保留独立的“应用此文件”操作。源项目自隔离基线后有其他修改时，显式显示冲突原因并禁用该文件的应用。预览后的竞态仍由 Host 在应用时重新校验，失败保留当前源文件并展示真实错误；重新读取可获得当前冲突状态。
- 不接受 Renderer 自选绝对目标路径。Host 的运行/步骤收据确定源与隔离目录，用户仅选择 Host 返回的相对文件路径；路径穿越、ADS、保留名、大小写别名及危险链接在 Host 拒绝。多成员改同一文件时，先应用的真实结果会使另一个版本成为冲突，不能后写覆盖。
- 共享目录模式没有隔离差异与应用边界，显示“没有文件修改”或真实错误，不暗示可以无冲突合并。保持 Knorvia 黑白层级与原有语义差异色。

## 状态与验收

- Studio Runtime 是工作区基线、变更扫描、源文件重校验和应用锁的唯一写入者。`StudioRunHistory` 仅持有当前打开的审阅弹窗与请求状态；DiffViewer 读取同一 `workspaceChanges` 快照，应用仍调用现有 `applyWorkspaceChanges`。
- 本地夹具覆盖两成员编辑同一文件、用户修改基线、二进制文件、路径穿越、部分应用与应用期间源文件竞态。界面投影区分文本、新增/删除、二进制和冲突；不调用真实模型或远端 SSH。
- 运行根类型检查、lint、架构检查和相关离线测试；未做目视复核时如实记录。

## 2026-09-27：多文件接纳与重开验收

- 在打包应用、临时项目和临时数据根中，经真实运行时及本地模型协议夹具产生三个隔离文件修改。未接纳时源项目不变。
- 从既有运行历史进入审阅，先修改源项目中的一个文件制造冲突；该项不可勾选且不能应用，全选只选可应用项。
- 多选接纳两个无冲突文件，独立核对磁盘字节；冲突文件保留用户修改。未调用真实模型或外部 CLI。
- 接纳后核对唯一持久收据的业务 runId/stepId、operationId、两个路径与 afterHash、host-verified/complete 状态。审阅继续保留相对于隔离基线的历史差异；不能用文件条目消失代替接纳成功。
- 真正退出并重开：运行与交付状态保留，已接纳文件不重复应用，冲突仍明确可见，模型夹具请求数不增长。
- 所有必须步骤缺失均使脚本失败，不能将 INFO、未执行或按钮不存在记为通过。

```text
界面发送 → Studio Runtime → 隔离执行 → 审阅只读投影
用户选择 → applyWorkspaceChanges → Host 重验冲突/写入 → 重读结果
重开 → 同一持久运行与文件事实（不重新执行）
```
