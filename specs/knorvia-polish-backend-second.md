# 第二遍：队列安全边界与群工作目录身份

## 已确认问题

1. 先后接收的 A、B 任务中，A 在执行后变成未知中断，B 已越过 send 校验。派发与重启恢复没有再次检查未知结果，会继续修改同一会话项目。
2. 群聊完成后可编辑项目和隔离方式，但隔离目录仅按群和成员命名。修改后复用原目录会被快照校验拒绝；共享目录重新切回旧项目还可能恢复陈旧原生上下文。
3. 主代理实机确认：同一事务的所有记录共用 revision 作为 sequence。分页一次截取 500 条时，相同 sequence 的未返回记录永远被下一页的 `before` 排除。

## 行为约束

- 接收、显式恢复、实际派发均检查同一 target 的未知中断。数据库先过滤未知结果再限制返回数量，不能只看最近 100/1000 条历史。已排队消息保留，待用户明确重试并结清未知任务后按原顺序派发；其他 target 仍可工作。
- 恢复其他失败任务不能绕过当前未知任务。对未知任务本身的明确确认可以排队重试。
- 旧版遗留多个未知运行时，可逐个明确确认重试；尚有未确认未知运行时不派发，全部确认后按原顺序执行，避免互相阻止确认形成死锁。
- overview/timeline 在最近 100 条之外合并仍未知的运行，去重并保持原倒序，确保被安全屏障拦住的运行能从现有历史直接检查和确认。
- 群项目或 isolated/shared 方式改变时，持久化新的 workspace generation。已入队运行冻结该 generation；快照和原生会话身份均使用它。
- A→B→A，以及 isolated→shared→isolated 必须得到新身份；名称、目标、摘要等普通编辑不重置目录。既有未带 generation 的运行保留原身份，旧运行修改记录始终引用旧目录。
- 不删除项目、旧隔离目录或原生会话，不触发真实 CLI/联网推理。
- SQLite 单独持有持久化单调 sequence，新增记录取得唯一值，更新保留原位置。timeline 的数字 before 契约不变。schema 1→2 在单一事务按原 sequence、rowid 重排已有记录；相同旧 sequence 的顺序恢复为原始插入顺序，不用 ID 字典排序。保留原 payload、ID、scope 和 revision；初始化游标计数器。旧版本应用重开时拒绝 schema 2，迁移失败回滚。

## 验收

- A 未知中断后 B 保持 queued，恢复后已有 B 仍被拦截；已明确重试的 A 成功后 B 才派发。
- 未知记录落到历史分页之外时 send/resume/dispatch 仍生效。
- 真实临时目录中同群切项目、切隔离方式及来回切换成功，原生会话不串用；同配置普通后续消息继续沿用目录与原生会话。
- 原运行历史仍可查看原目录修改；仅对受影响运行/数据库/隔离工作区测试及 services 类型、scoped lint、架构检查做验证。
- 同一事务超过 500 条、分页恰落在批次内部、消息更新及版本 1 迁移后的分页均无遗漏或重复；新游标严格高于迁移后所有记录。

## 收尾：同毫秒 FIFO 与 Windows 路径别名

- 派发顺序由持久化 run 记录的唯一插入 sequence 决定。不得用相同的 createdAt 或随机 ID 打破平局；恢复时 active 记录重新插入不改变原 run 的接收顺序。数据库提供已排队运行的只读投影，应用仍唯一拥有执行状态转换。
- 快照复用的 source identity 使用现有 studioProjectKey 比较，仅统一 Windows 路径大小写和分隔符。safePath、目录存在检查、链接拒绝和隔离模式一致性检查全部保留；不同真实目录仍拒绝复用。
- 回归：固定同一毫秒接收两次消息，初次队列和反序确认后的重试均按原接收顺序；Windows 原目录大小写/斜杠别名复用原快照并保留改动，其他目录和隔离模式仍拒绝。

## 实机反馈：人工确认等待的主动停止

- cancelRequested 落库可早于下一次 tick 的 AbortSignal。人工确认轮询必须先校验真实 owner/lease，再将有效 owner 的用户停止明确标记为已知取消；不能把普通执行权错误都转成取消。
- 尚未批准的人工节点停止为 cancelled/resultKnown=true，问题过期，后续节点不运行；审批等待期间丢失 owner/lease 的异常仍为 interrupted/resultKnown=false，已派发原生调用未知结果处理保持不变。
- 回归刻意在 cancel 后不再调用 tick，覆盖确认轮询先醒来的真实竞态；另外用实际临时数据库的 lease 丢失与 cancelRequested 同时出现验证不会误报已知停止。
