# 群聊与工作流精细打磨

2026-09-23。继续 `knorvia-backend.md`，不更换原 GUI、不增加角色记忆或成果页。

## 状态与交互规则

- 后端仍为定义、运行和消息的唯一正式 owner。群输入、工作流画布及本次运行输入由各自草稿 store 按实体 ID 保留。保存或发送 ACK 只能清除本次提交内容，不能覆盖等待期间输入的新文字。
- 停止是独立的高优先操作，不能因发送、保存或目录选择等待而禁用；同一停止提交幂等且保持忙碌反馈。停止提交后禁止新发送，待快照证实运行结束后才恢复。运行中及停止中不允许修改群定义、工作流节点、项目、连线或通过键盘绕过冻结。
- 停止不依赖 overview 是否暂时刷新成功。停止回执失败时仍冻结发送，但允许重试停止；旧停止请求的迟到回执不修改后来运行的控件状态。
- 群新增 @ 全部成员入口；群编辑保存期间锁定表单，提交失败仍保留全部配置。切群后清除属于旧群的错误及弹窗。窄屏详情作为覆盖面板，不挤掉输入与停止控件。
- 工作流局部草稿跟随已确认的服务快照；只有已观察到后端版本且本地干净的已删除定义可以移除。保存 ACK 记录 revision，旧快照不得回滚 ACK；脏草稿与损坏原记录保留。撤销历史不得跨服务版本复活旧图。
- 运行对话框本次输入按工作流保存；失败、关闭、切页、重开均保留，后端接受后只清除相同提交文本。创建、重命名、删除的等待期间不能再次提交或改变表单。
- 工作流锁定覆盖鼠标、键盘与右侧编辑；结构无效时打开校验面板定位，检查条件语法及前置节点引用使用服务公开的纯校验，不复制运行时解析器。
- 运行徽标从持久结果派生，包含失败、拒绝、取消和中断，不将已结束任务显示为运行中。失败确认或条件节点不能因没有原生 turn 而失去状态。

```text
输入 → 实体草稿 owner → 提交快照 → 后端 ACK(revision) → 只清理相同草稿
                               ↘ 后端快照(不早于 ACK) → 正式定义投影
停止 → 独立提交通道 → 后端冻结派发 → 终态快照 → 恢复操作
```

## 工作流导入导出

- 列表与画布操作菜单提供 JSON 定义导入/导出。导入是保存独立的新定义，绝不执行。
- 文件为带 `format: "knorvia-workflow"`、`version: 1` 的 envelope；大小最多 8 MiB，节点最多 200、连接最多 800，严格字段/枚举/ID/有限坐标校验。拒绝未知版本及损坏结构，保留当前内容。
- 导出只含已知配置与布局，排除运行历史、状态、用户输入、凭据、本机项目绝对路径；导入重新分配工作流、节点、连线 ID，重写内部节点引用，项目由当前本机明确选择。
- 未完成但可编辑的结构可导入为草稿；说明具体校验问题，禁止运行。不能将不完整模板误宣称已通过运行校验。
- 文件选择用浏览器标准文件输入（跨平台）；导出优先现有平台 saveFile，浏览器采用 Blob 下载，不直接访问 Electron 或后端文件系统。

## 验收

离线测试覆盖停止与发送并行、ACK 草稿保护、切页运行输入、冻结、非法图/引用/端口、上限连线替换、定义删除与迟到快照、失败徽标、JSON round trip/未知版本/超限/恶意字段/重映射/排除路径。执行 UI 类型、lint、架构检查；主任务整合后检查真实桌面创建/编辑/连线/导入导出/保存/运行等待/停止/历史及窄屏键盘。不调用真实模型。
