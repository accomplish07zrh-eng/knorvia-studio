# Knorvia Studio：保留原 GUI 的产品账号清理

本次以 fresh 上游检出为基础，保持 Root、App、WorkspaceShellLayout、侧栏、聊天输入框、消息区域、设置页的布局、尺寸、主题与组件体系。禁止恢复已废弃的多内核实现，禁止增加替代工作台。

## 行为

- 启动进入原工作区，不恢复产品账号、不轮询 OAuth、不构造虚假登录用户。没有模型时沿原模型配置入口设置用户提供的 API Key。
- 删除 Welcome / 产品登录、产品账户菜单、退出账户、套餐购买、升级促销、套餐额度、产品远程反馈与更新入口及其实际 hooks/state 调用。
- 删除依赖上游账号的云闲时任务与云分享入口；本地定时任务、本地用量统计、SSH、第三方 MCP 授权保持原功能。
- 模型配置保留原 provider 列表、手动添加、编辑 API URL / Key / 模型表单及原设计组件。不得向上游申请免费 Key 或自动同步账号 provider。
- 用户可见产品名为 Knorvia Studio。用用户提供的 K/机器人图片替换应用品牌图标，保留尺寸与边框；供应商和插件品牌图标保持原样。
- 首次启动没有保存主题时固定使用原白色主题；以后尊重已保存的深色、浅色或跟随系统选项。沿用原主题切换入口。

## 所有权与边界

现有 Host 模型服务仍是模型配置的唯一状态所有者。UI 通过现有 services/hooks 调用手动配置；移除 OAuth 状态与账号服务依赖，不增加认证兼容 stub。

```text
原 Root 启动 → 本地工作区恢复 → 原聊天界面
                           → 原模型设置 → 用户手动保存模型 → 现有模型服务
```

没有跨账户迁移与状态恢复。第三方 MCP 授权不是产品登录，保留其协议、UI 与正常授权流程。

## 验收

运行类型、lint、架构检查；静态检索确认已删除账号服务 import 与自动 OAuth hooks；核对主框架差异只含删除入口和品牌替换。集成后由主任务构建并在干净配置实际启动，验证无登录可进入工作区、原模型设置可达、原 GUI 样式未变。

本次验证覆盖：手动 API 模型仍可选择、陈旧账户模型不会回到菜单；命令面板保留新任务/项目/设置；产品登录和云分享源模块确已从磁盘删除；首次白色且以后尊重用户保存的主题。第三方 MCP 授权源路径完整保留。

UI 单独类型检查、4 项回归测试、改动文件 lint 和架构检查通过；Web 生产构建通过。隔离工作区仍使用上游 shared 平台接口时，Web 类型检查会报告三个已被主任务删除的产品 OAuth 平台成员；主任务合并 shared 后完成最终类型与桌面启动验收。构建保留上游已有的大块体积和重复静态/动态导入提示，此轮不重构原 GUI 的打包边界。
