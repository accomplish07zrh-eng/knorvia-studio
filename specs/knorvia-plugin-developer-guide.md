# 插件与技能开发者入门（T3.2）

日期：2026-09-25。交付一份可以在本地十分钟走完创建、预检、来源登记与设置页安装的中文指南，以及一个独立的 skill-only 示例插件。示例不加入八个内置插件，不自动启用，不连接在线市场，也不改变当前插件运行时或 UI。

## 产品规则与所有者

- `plugin-creator` 的脚手架负责生成开发目录；`skill-creator` 的规则负责技能触发、输入、输出、失败和验证说明。开发目录归用户所有；示例目录只供复制与学习。
- `.knorvia-plugin/plugin.json` 是插件功能清单，`skills/<name>/SKILL.md` 是技能入口；本地来源索引由 `upsert-dev-marketplace.mjs` 写入，插件安装、更新、启停仍由当前 Host 的插件服务和 Settings → Plugins 管理。指南不能把预检或来源登记说成已安装、已启用或已执行。
- 本地 `validate-plugin.mjs` 默认只读，不运行技能、命令、Hook 或 MCP，也不调用任何 PATH 上的 CLI；仅显式传入当前 Knorvia CLI 的绝对路径时才追加 Host schema 校验。文档里的命令不能覆盖已有开发目录或来源索引。
- 已启用技能在外部内核的单聊、群成员和工作流轮次中按有界目录投影，显式技能引用使用同一技能正文；标准且可安全转换的静态 MCP 可按内核实际传输能力接入。插件私有 Hook、命令、子代理行为不跨内核执行，无法安全转换的 MCP 明确不可用。具体运行边界以 `specs/knorvia-shared-capabilities.md` 为准。

## 流程与验收

```text
用户选择开发目录 → 创建器生成文件 → 作者填写示例技能
→ 只读预检（可选：绝对 CLI 路径 Host 校验）
→ 本地来源索引 → Settings → Plugins 安装/启用
→ 当前 Host 发现技能 → 每次外部 turn 取有界快照
```

指南和示例须通过真实创建器产物比对、预检、可用时的 Host schema 校验，以及路径含空格、重复创建拒绝、来源索引登记与复跑检查。示例技能只读取用户指定项目并给出带来源的简报；它不执行项目命令、不写文件、不联网、不选择模型。没有实际调用模型时，不能声称技能内容已通过真实对话验收。根类型、lint、架构检查和相关创建器测试均记录真实结果。
