# Knorvia 独立实现与许可迁移

2026-09-27。以 `a748e31e6cf6088a11aff2d1410d6908196c7b7f` 的现有产品能力为迁移起点。用户要求消除对 ZCode 实现的依赖，并保留现有功能、数据和 UI 细节；只有全部替换、验收和新版本发布完成，才能结束本目标。

## 产品与完成条件

- 官网及中英文 README 介绍 Knorvia 的多内核、协作、工作流、创作和插件能力，版本和限制必须与已发布产物一致。来源、版权和许可另在许可文档中准确记录。
- 独立实现不等于改名、格式化、翻译注释或逐行改写；不得把未在基线中找到的文件自动认定为原创。
- 每个现存文件都进入来源清单；分别记录上游关系、第三方声明和经复核的许可决定。这三者不能合并成一个可能误导的标签。
- 结束时，产品源码和构建产物不得再含未替换的 ZCode 实现，也不能通过依赖、代码生成、打包缓存或运行时下载重新引入。所有未审查文件都须完成来源确认；测试、文档、模板、图标和其他资产也在范围内。
- 可独立授权的 Knorvia 文件使用 MIT。第三方库、运行时、驱动和资产继续保留各自许可、版权及来源，不能宣称为 Knorvia 原创。通用开源依赖不等于 ZCode 实现依赖。
- 不降低功能来减少待替换量：保留现有导航、黑白视觉语言、玻璃材质、图标、动画、聊天布局、交互、快捷键、无障碍和中英文行为，以及桌面/Web 与多平台边界。
- 使用新版本发布最终许可调整；现有 tag、Release、附件及其许可记录保持不变。过渡期间根 LICENSE 不提前改成覆盖全部源码的 MIT 声明。

此规格替代旧规格中“保持上游实现/Agent loop/原业务组件不变”的实施限制；保留当前产品行为、数据隔离和已完成界面的要求继续有效。不得恢复 2026-09-22 前已废弃的实现。

## 文件来源清单

来源基线固定为 `FORK-NOTES.md` 记录的 `zai-org/ZCode@872ad960de7ec172591f7e1952f7849229f94521`。从仓库外的只读 Git 对象库提取路径、mode、blob id 和内容摘要；不把原源码复制回当前工作区。

审计工具位于 `scripts/provenance/`，由构建许可审计模块维护。它不接触产品数据、凭据、模型或应用业务状态。唯一可编辑的来源决定是 `licensing/reviews.json`，基线和文件报告是派生产物：

```text
固定上游提交 → 上游文件摘要 ────────────────┐
当前 Git 文件集合 → 不跟随链接的内容摘要 ──┼→ 纯分类 → 当前文件报告
逐文件复核记录 + 既有第三方声明 ──────────┘
```

- 枚举已跟踪及未忽略的未跟踪文件，排除已删除文件；不递归进入 `node_modules`、数据目录或缓存。符号链接只读取链接文本，禁止读取指向工作区外的内容。
- 对合法 UTF-8 文本仅归一 CRLF/LF；二进制保持原始字节。记录原始与归一摘要，品牌替换不能归一成“原创”。
- 路径相同、已知 CLI 目录改名或相同内容的复制/移动都必须识别。旧基线无对应关系的文件为 `unreviewed`，不能因为新增路径就授予 MIT。
- 第三方 inventory 的目录范围只代表“可能包含对应第三方内容”；尤其 UI 和 RPC 是混合来源，不能把整个目录直接归属 shadcn 或 Microsoft。保留精确摘要是否匹配和原范围说明。
- 原创/独立替换的确认必须绑定具体路径、摘要、行为规格、实现依据和验收证据；后续字节变动使复核失效，必须重新审查。许可正文自身和自动生成清单单独记录性质，不用自引用摘要制造假校验。
- 清单只包含路径和摘要等审计信息，不包含源码正文、个人路径、凭据或历史聊天。生成动作不联网，不修改其他文件；基线提取单独显式执行。
- 摘要匹配是来源证据，不是完整的著作权判断；算法无法识别的片段复制仍须人工复核。统计数字为迁移进度，不能单独证明最终独立。
- 质量工作流在依赖安装之前离线核对来源清单及复核摘要；跨系统检查只允许 UTF-8 的 CRLF/LF 差异，二进制须相同。此检查是清单新鲜度门槛，不是全量独立完成证明。

## 替换顺序和验收边界

| 阶段 | 替换边界               | 必须保留的行为与证据                                                                              |
| ---- | ---------------------- | ------------------------------------------------------------------------------------------------- |
| 1    | 来源与产品介绍         | 完整文件清单、准确 README、官网链接及当前版本能力                                                 |
| 2    | 内置内核契约与工具执行 | 模型流、工具权限、取消、命令 admission、上下文、会话恢复、子任务与工作流；Host 仍为业务状态所有者 |
| 3    | 浏览器 SDK 与 REPL     | 浏览器选择、tab/locator API、截图及来源、防越权 bridge、执行隔离、异步结果、超时/取消、错误语义   |
| 4    | 桌面与通信基础         | 窗口、安装/便携路径、凭据、Host 生命周期、stdio/RPC、身份、远控 replay、SSH、升级保护             |
| 5    | 共享 UI 与剩余实现     | 当前全部页面、交互、布局尺寸、主题、玻璃、动画、内核切换、草稿、创作、插件、Diff、终端和移动端    |
| 6    | 发布闭环               | 来源/依赖/产物扫描无未解决 ZCode 实现，新版源码与安装/便携包一致，许可与贡献文档、官网发布完成    |

阶段可以按独立边界交错推进，但不能以完成一个 SDK 子文件代替整个核心模块完成。每次切换生产调用入口前，先写行为规格与契约测试，再独立实现；旧实现只用于提取行为与对照验收，不能作为逐行重写模板。删除旧实现时同时验证所有调用者和构建输入，不能留下运行时 fallback。

现有 `studio-runtime`、creation 等功能是否可直接列入自有范围，以文件证据为准；不是按目录或修改日期推定。`IPlatformService`、workspace identity、owner/lease、stale run、desktop continuous 与 mobile replay 的业务不变量继续有效。

## 验证与发布门槛

- 每个实现边界执行相关离线测试、`pnpm typecheck`、`pnpm lint`、`pnpm architecture:check --changed`。新审计工具测试覆盖改名、复制、二进制、换行、复核过期、混合第三方、符号链接及未审查文件。
- 完整切换执行 CLI 构建、`pnpm test:studio`、应用交互/几何回归、升级与数据保护、已支持系统的 CI；失败和平台跳过分别记录。不能删除或放宽既有验收条件来让替换通过。
- 产品功能清单与 `specs/`、现有测试逐一对应；新增契约测试检验结果和外部行为，避免只镜像新实现。
- 打包仍使用生产身份。安装版、便携版均检查真实启动、插件能力、源码摘要和许可正文。覆盖真实便携目录仍须先退出程序、排除 data 并逐文件核对散列。
- 实际模型调用、未支持平台或人工目视未执行时如实标注，不伪造能力等价。现有手动目视跳过授权继续适用；自动化界面验收继续执行。
