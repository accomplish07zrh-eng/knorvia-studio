# Studio runtime

Host owns accepted external conversations, groups and workflow runs. SQLite transactions admit idempotent commands; one fenced executor lease drives native calls. Renderers consume revisioned projections and never own an accepted run queue. Native Knorvia single chat retains its existing V4 owner.

Public browser contract: `contract.ts`. Node composition: `node.ts`. Domain is pure, app uses explicit ports, adapters own I/O. Acknowledgement is admission, not completion. Unknown native side effects become interrupted on recovery and require explicit retry. Member sessions and workspace identities remain separate. See `specs/knorvia-backend.md` for invariants and acceptance.

`StudioTimeline.usage` optionally exposes the latest run/turn's native usage snapshot. Supplied fields replace previous values without summing duplicate notifications; unknown token counts and context capacity stay absent. `scope` distinguishes a model request, a native turn, and vendor-reported values. Input tokens include cache reads/writes where the provider reports them separately. SSH forwards the matching remote run's usage through the existing fenced sink. See `specs/knorvia-chat-metrics.md`.

The browser contract also exports the pure `validateStudioWorkflow` and `studioConditionReferences` validators so editor and executor share graph and condition semantics. A native interaction can supply a question-scoped cancellation signal to `StudioKernelSink.ask`; the Host expires that persisted interaction without cancelling sibling questions or the turn.

Queued dispatch rechecks unresolved native outcomes across all history. Group runs freeze a workspace generation, rotated when project or isolation mode changes; historical directories remain addressable. Timeline `before` remains a numeric cursor over unique, stable insertion sequences. SQLite schema 2 atomically migrates schema 1 records without changing their IDs or payloads; schema 1 binaries reject the upgraded store on reopening.

Kernel identities include the built-in candidates and bounded `acp:<slug>` identities supplied by Studio-owned custom ACP manifests. The registry owns detection and handshake results; the runtime owns accepted tasks and persisted configuration. `config-index` is written with each custom configuration in the same transaction so a newly configured adapter remains visible after restart. A missing configuration defaults to `ask` and an empty executable override, not a globally selected CLI path. Group and workflow validation use the shared identity predicate; availability is checked by the adapter before native execution. Resource projection snapshots Studio skills and MCP for the turn, without changing external CLI global settings. Details and compatibility limits are in `specs/knorvia-cli-expansion.md`.
