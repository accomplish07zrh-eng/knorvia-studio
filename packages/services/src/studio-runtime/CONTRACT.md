# Studio runtime

`workspaceChanges` optionally reads one version-bound PNG/JPEG pair from the owning snapshot, returning `imagePreview` alongside the existing change shape. Binary projections expose real file versions; image bytes remain transient and browser decode proves displayability. Existing apply methods optionally recheck `reviewedVersions` against the actual journal/staging bytes before writing. Public methods remain 12; legacy requests and text comments retain their behavior. See `specs/knorvia-workspace-image-compare.md`.

`StudioOverview.attention` derives pending interactions and terminal events across all persisted history. `attention-read` admits a version-bound read receipt through the existing command transaction; it never answers, dispatches, resumes or cancels a task. Duplicate facts share one version, later attempts remain unread, and missing/retired targets retain historical identity. Native Knorvia unread remains with its V4 task-index owner. See `specs/knorvia-studio-attention-inbox.md`.

`workspaceRuntime` queries or explicitly controls a runtime belonging to an existing run/step workspace. The app owner admits approved argv, persists token-fenced lifecycle facts, and delegates process/port IO to the Node adapter. Commands, environment and process output are never persisted. Recover verifies process birth identity before cleanup; failures retain truthful failed/interrupted/cleanup-required states. See `specs/knorvia-workspace-runtime.md`.

Host owns accepted external conversations, groups and workflow runs. SQLite transactions admit idempotent commands; one fenced executor lease drives native calls. Renderers consume revisioned projections and never own an accepted run queue. Native Knorvia single chat retains its existing V4 owner.

Public browser contract: `contract.ts`. Node composition: `node.ts`. Domain is pure, app uses explicit ports, adapters own I/O. Acknowledgement is admission, not completion. Unknown native side effects become interrupted on recovery and require explicit retry. Member sessions and workspace identities remain separate. See `specs/knorvia-backend.md` for invariants and acceptance.

Node composition issues per-turn `knorvia_studio_agents` MCP grants. The runtime binds ownership to the persisted run/turn/attempt, reuses command admission and isolated workspace placement, and enforces configured kernel capabilities, human permission gates and chain budgets. `agent-task`, `agent-run-link` and `agent-operation` are scoped admission metadata; `agent-event`/`agent-result` are immutable attempt-derived outbox/result receipts. Native run/turn/step records remain the execution owner. Event delivery ACK never settles a native task. See `specs/knorvia-studio-agent-tools.md`; no mobile or arbitrary account configuration API is added.

Agent discovery uses the existing live kernel inspection owner rather than an unpopulated local status store. Caller ownership and configuration snapshots are rechecked after asynchronous discovery/options, human approval and workspace preparation. Workspace process helpers receive the same bounded environment through optional Node process-tree options, including stop/recovery; omitted options preserve existing provider behavior. Environments are neither persisted nor logged. No browser method or second state owner is introduced.

Windows workspace inspection selects direct OS WMI through the existing process helper, preserving PID/parent/UTC birth tokens and the 2,500 ms query budget. One timed-out read may retry once outside absolute cleanup deadlines; provider CIM defaults and cleanup clamps remain unchanged. Native netstat grants listener attribution only for the exact owned loopback TCP LISTENING row, followed by existing HTTP health checks. No query failure grants process ownership or successful recovery.

`StudioTimeline.usage` optionally exposes the latest run/turn's native usage snapshot. Supplied fields replace previous values without summing duplicate notifications; unknown token counts and context capacity stay absent. `scope` distinguishes a model request, a native turn, and vendor-reported values. Input tokens include cache reads/writes where the provider reports them separately. SSH forwards the matching remote run's usage through the existing fenced sink. See `specs/knorvia-chat-metrics.md`.

The browser contract also exports the pure `validateStudioWorkflow` and `studioConditionReferences` validators so editor and executor share graph and condition semantics. A native interaction can supply a question-scoped cancellation signal to `StudioKernelSink.ask`; the Host expires that persisted interaction without cancelling sibling questions or the turn.

Queued dispatch rechecks unresolved native outcomes across all history. Group runs freeze a workspace generation, rotated when project or isolation mode changes; historical directories remain addressable. Timeline `before` remains a numeric cursor over unique, stable insertion sequences. SQLite schema 2 atomically migrates schema 1 records without changing their IDs or payloads; schema 1 binaries reject the upgraded store on reopening.

Kernel identities include the built-in candidates and bounded `acp:<slug>` identities supplied by Studio-owned custom ACP manifests. The registry owns detection and handshake results; the runtime owns accepted tasks and persisted configuration. `config-index` is written with each custom configuration in the same transaction so a newly configured adapter remains visible after restart. A missing configuration defaults to `ask` and an empty executable override, not a globally selected CLI path. Group and workflow validation use the shared identity predicate; availability is checked by the adapter before native execution. Resource projection snapshots Studio skills and MCP for the turn, without changing external CLI global settings. Details and compatibility limits are in `specs/knorvia-cli-expansion.md`.

`save-group` and `save-workflow` accept an optional `baseUpdatedAt`: the server `updatedAt` the editor started from. When supplied, admission rejects the save inside the same transaction if the stored definition is missing or has a different `updatedAt`, so concurrent windows or the mobile client cannot silently overwrite each other; omitted keeps last-write semantics for creates and legacy imports. See `specs/knorvia-definition-ownership.md`.

Windows recovery uses the existing 2,000 ms process-owner grace so a reconstructed handle receives fresh birth verification before forced termination. Normal stop and POSIX grace are unchanged. A changed birth remains unkillable and uncertain cleanup is retained. Non-detached Windows children may already be stopped by Host exit; persisted interruption and explicit recovery remain required.

`command` accepts `workspace-review` draft mutations and preview-confirmed feedback. The Host stores one revision-checked review per business run/step, exposes optional `reviewDrafts` / `reviewDraft`, and binds annotations to optional real `workspaceChanges.version` hashes. Feedback is a single original member/step in the existing run/receipt/lease executor, with the original native session and physical workspace revalidated before dispatch. A missing remote version/session capability fails closed. Unaccepted UI text remains a separate versioned edit overlay; legacy composer comments retain their format. See `specs/knorvia-workspace-inline-review-feedback.md`.
