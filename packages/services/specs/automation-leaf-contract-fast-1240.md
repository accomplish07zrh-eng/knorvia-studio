## Frozen behavior

- Existing exports/signatures/error names/messages remain. Cron validation catches parser errors and returns false, including native runtime-invalid input. Cron computation propagates parser errors. Croner's supported six-field expressions, aliases and timezone behavior remain accepted despite the old comment describing five fields.
- Definition serialization ignores anchorAt, numerically sorts copies of weekdays/monthDays/months, retains duplicates and JSON null semantics, and preserves positional field order. Input arrays are unchanged.
- Relative delays retain seconds/milliseconds in their anchor. Generated object key order and cron display fields remain unchanged. Minute inference accepts only a trimmed five-field `*/N * * * *` with a nonzero decimal-leading integer, with no added range validation.
- Minute recurrence floors/clamps interval to at least 1, begins at anchor plus one period, and advances strictly after from. Hourly starts at the anchor hour with configured minute and zero seconds, permits that first aligned occurrence, and advances in elapsed hours. Nonfinite arithmetic and invalid dates keep historical NaN/null behavior.
- Daily candidates start on the anchor day at configured local time, use index\*interval day offsets and inspect indices 0..36599. Weekly anchors to Monday, traverses sorted numeric-token weekdays in the historic array order (Sunday 0 first), uses default Monday for missing/empty lists and inspects week offsets below 5220. It returns the first eligible visited candidate, not the minimum across an unordered week's dates.
- Monthly offsets 0..1200 inclusive use interval stepping. Weekday mode uses only the first supplied weekday/default Monday. Date mode sorts copied monthDays/default [1] numerically, skips month overflow and retains duplicates. Yearly offsets are below 400, wrap the first supplied month into 0..11, use only the first month day/default anchor date, and skip month overflow. Unknown runtime units historically use the yearly branch; no added validation belongs in this calculator.
- Next run is strictly greater than from. Search exhaustion returns null. Local Date normalization, including DST gaps/folds and month/year overflow, remains observable.
- One-shot fixed numeric month/day cron catches a previous target age greater than zero and less than 60000ms by returning from; ages 60000..1800000 inclusive reject with the existing localized StaleOneShotAutomationScheduleError. At the exact target Croner's previousRuns excludes that occurrence, so the next calendar occurrence is retained. Older targets roll to the next occurrence. Recurring, explicit rules and other expression forms bypass that special case.
- Carrier parsing tolerates extra fields, but fewer than five fields falls back to anchor defaults. Number conversion and integer filtering retain empty comma tokens as zero and discard ranges/steps. Per-unit object field order, defaults and invalid-unit error remain.
- Carrier validation preserves pairing -> range 1..200 -> relative-delay conflict -> direct-rule conflict (including null) -> recurring=false -> numeric maxRuns rejection order. Absence means undefined, not null. Unit membership remains the caller's rule validator responsibility. Recurring projection shallow-copies, forces true and maxRuns null, and retains extra fields/references.
- Rule validation retains unit -> positive integer interval -> monthly 1200 cap -> hour -> minute -> monthlyMode -> optional weekdays -> weekly requirement -> monthly-specific lists -> optional months -> optional monthDays order. Existing sparse-list `.every` acceptance and native errors on malformed list objects remain. anchorAt is not validated; yearly/day/hour intervals have no added cap.
