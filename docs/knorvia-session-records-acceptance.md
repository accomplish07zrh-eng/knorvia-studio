# 会话元数据存储验收

基线 `d430a2b`，按[先行合同](../specs/knorvia-session-records.md)隔离重建十个仓储入口。SQLite 是唯一状态；update/revert/clear 在写锁内同步读取、标题判断、补丁、保存并解码结果，自有事务成功后才返回，外层事务只借用。列表中的路径通配字符按字面匹配，保留既有大小写与目录边界。未修改表结构、facade、UI 或真实数据。

## 先行回归和实际修正

旧版最终 **38 项：26 通过、12 预期失败**。失败包含同一轮并发更新的标题/权限保留、生成标题 gate、反向顺序和借用事务，以及同步执行、锁内读取、结果解码失败的自有回滚、真实延迟外键 COMMIT、两连接锁竞争和三个路径通配场景。不是十二个独立产品缺陷，也不把旧版通过断言改记为新发现。

最初夹具把 SQLite 无原型行与普通对象直接比较，并试图写入 schema 不接受的 titleSource；修正夹具后才确定产品失败集合。严格测试类型还发现权限夹具不符合实际 PermissionRuleset，改用公共规则对象并重跑旧版；没有改生产类型或放宽断言。后补一项有限历史 null 合同在旧版通过，再由作者按文字合同保留。最终相关组合 **52/52 通过**，含既有 codec-store 和消息原子性测试。

原生 SQLite 验证触发器、延迟外键、自动回滚、已有外层事务、坏结果解码、authorizer 观察及新建临时文件的两个独立连接。后者确认锁竞争失败前不读取当前行，释放锁后显式重试保留最新标题；不声称跨进程压力或自动重试。临时路径按解析后的固定前缀和父目录检查后清理，没有打开用户数据库。

只读复核发现单独 `title:null` 的标题时间回退：已有组合用例同时给 titleSource:null，掩盖了这一差异。补强原用例后，新实现先 **10 通过/1 失败**，再由隔离作者根据行为例子修正；不把组合用例最初通过当成完整覆盖。修正前一次全量 **1,949/1,949 通过**、0 失败/跳过、323.39 秒，不用于证明后续修正版。

补强后的合同文件也通过测试专用解析钩子指向仓库外固定旧模块，确认 **11/11 通过**且实际命中冻结模块；未覆盖工作区源码。第一次钩子参数使用 Windows 路径而非 file URL，测试未启动便报 ESM scheme 错误；改用 file URL 后才取得此结果，没有修改生产 loader。
