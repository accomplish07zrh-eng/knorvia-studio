# Synchronous turn-state projection contract

Implement the complete TurnMachine / TurnMachineImpl API in api.d.ts. The state declaration module remains an unchanged dependency. Private representation and helper decomposition are author choices. No IO, async boundary, policy service, cache, sidecar or automatic state commit may be introduced.

Construction retains the exact state reference. Every operation reads the current public state (which callers may replace), returns a projection, and does not assign this.state. Unchanged nested references remain shared. Callers typically wrap each returned projection in a new TurnMachineImpl. Static create uses nullish fallbacks for the optional turn ID then trace ID, delegating initial state construction to the existing state factory. Generated IDs use createTurnId and crypto.randomUUID; supplied IDs including empty strings are preserved.

A phase transition is validated by the existing canTransitionTo protocol. Rejection calls createCoreError(CoreErrorType.InvalidTurnPhase, `Cannot transition from ${current} to ${target}`, {context:{current,target},recoverable:true}); the result is thrown. It returns a shallow state projection with the target phase. start targets ProcessingInput; receiveModelResponse and addStreamingContent each validate Streaming before appending the supplied text to the existing streamingContent; aggregateResults targets AggregatingResults. complete validates Completing, then supplies finalResponse, resultType (default success) and a new Date. fail bypasses validation, returns Error phase, exact error reference and a new Date.

startModelRequest permits only ProcessingInput or AggregatingResults. Otherwise throw the same error category with message `Must be in ProcessingInput or AggregatingResults phase`, context {current}, recoverable true. Admission happens before ordinary transition validation to AwaitingModelResponse. The new modelRequest has model then messages, with the input message-array reference.

scheduleTools validates SchedulingTools before reading/mapping calls. Each input call becomes a new plain object with id,name,input,status='scheduled',scheduledAt in that field order; one new Date per element. Input extras are not carried. The supplied schedule is retained by reference. Returned state fields phase,toolCalls,scheduledTools preserve the standard shallow-spread insertion behavior.

startToolExecution selects AwaitingPermission if any call is waiting_permission, otherwise ExecutingTools; validate before timestamp effects. Every call is cloned. Waiting calls preserve status and startedAt (including undefined); every other status becomes running and gets a distinct new Date. Added keys status then startedAt have ordinary object spread/override insertion order.

completeTool has no phase guard. On failure, modelMessageContentToText(content) occurs before any tool projection/timestamp. All matching duplicate IDs get cloned with status (completed/failed), a distinct completedAt and result {success,content}; nonmatches preserve their references. One result is appended regardless of whether IDs matched: {success,content,error}, where success has explicit undefined error; failure error is {type:'tool_error',message:convertedText ?? '',recoverable:true}. New content is shared, existing result entries remain shared. No output grant or execution policy changes.

queuePendingInput returns a state with a new pendingInputs array containing existing references followed by the supplied reference. drainPendingInputs returns {inputs,state}: inputs is the original array; state is a shallow projection with a distinct empty array. Neither operation mutates the receiver state.

requestPermission validates AwaitingPermission before projection; all matching call IDs are cloned with waiting_permission status; other calls keep identity. It appends the exact request reference to a new pendingPermissions array. No authority grant occurs.

resolvePermission has no phase guard. Matching calls are cloned with status permission_denied only for deny, otherwise the previous status, and input modifiedInput ?? previousInput (false/0/empty string are replacements; null/undefined fall back). It removes every matching pending request and appends {toolCallId,decision,modifiedInput,resolvedAt:new Date()} to a new resolvedPermissions array. Other call/request/previous-resolution references are unchanged. All four public decision values retain their current projection behavior; this class does not implement granting.

getNextPhase reads phase,toolCalls,streamingContent from current state. Streaming with calls selects SchedulingTools; Streaming with no calls and truthy content selects Completing. ExecutingTools selects AggregatingResults only when there are no running or waiting_permission calls. AggregatingResults selects Completing if any failed/permission_denied call, otherwise AwaitingModelResponse. Other cases return phase unchanged. isComplete delegates existing terminal-phase facts.

All existing API/error/runtime strings remain fixed. Observable field presence and plain-record key order, duplicate matching, reference sharing, Date count/order and original thrown helper errors must be preserved. Ordinary supported record inputs only; no broad hostile getter or patched-builtins compatibility redesign. No real files/tasks/providers/permissions/processes used during authoring.
