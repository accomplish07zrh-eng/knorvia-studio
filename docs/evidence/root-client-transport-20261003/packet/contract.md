## MessagePort

`createMessagePortServiceConnection(port)` synchronously returns own `services`, then `dispose` fields. Emit debug-1; construct MessagePortProtocol with the identical port; construct ChannelClient with that protocol; register initialization listener; emit debug-3; construct RemoteServiceAccess with client. Initialization listener emits debug-2 whenever invoked. Each debug independently calls `isRendererProductionBuild()` first; true suppresses console, false calls `console.log` with the exact text in error-text.json. No caching of production state and no extra logger/debug calls. The initialization subscription return is not separately retained/disposed by this owner.

The connection owns a one-way disposed latch. First dispose captures that state before calling `client.dispose(reason)` with unchanged Error/undefined identity, then `protocol.disconnect()`. Later disposals do nothing. A client disposal throw propagates, prevents disconnect, and still leaves the latch set. No try/finally recovery is specified. Client owns settlement/cancellation of pending RPC; protocol owns port disconnection. `connectViaMessagePort` is the thin synchronous facade returning only the newly created connection's services; no extra connection or readiness promise. No timeout/AbortSignal/reconnect exists here. Constructor/listener/log/accessor exceptions propagate synchronously.

## WebSocket

`connectViaWebSocket(url,options?)` creates a Promise and exactly one `new WebSocket(url)` inside its executor. Constructor throws reject the Promise normally. Register outer listeners in order error, close, open. Before any open, error rejects with error template-1; close reads the current options.onClose, calls it with a fresh plain object containing own code/reason/wasClean in that order, then rejects using template-2 if reason truthy or template-3 otherwise. Error/close do not change the opened latch; normal Promise settlement determines eventual outcome. All close events call onClose, including after settlement. Close callback throw prevents the subsequent rejection on that event. Browser-listener exceptions propagate through the platform event mechanism, not an added catch/reject wrapper.

On every open event set opened latch first; invoke current options.onOpenSocket as an options method with the identical WebSocket; then adapt socket, construct SocketProtocol, call connectViaProtocol, and resolve that accessor. This does not wait for RPC Initialize. A callback or construction throw interrupts this sequence; no retry or automatic close is added. A prior error rejection still permits a later open to build these collaborators; repeat open events repeat the sequence even though Promise resolution is already settled. Later error/close do not reject after the latch is true. Options fields are read at event time and method receiver identity is preserved.

Socket adaptation happens only after onOpenSocket. Set ws.binaryType to arraybuffer before registering inner listeners in order message, close, error. Message delivery wraps `new Uint8Array(event.data as ArrayBuffer)` through VSBuffer.wrap and fires onData. No Blob/text handling/conversion or new validation. On every inner close/error, fire onClose then onEnd with undefined; an onClose throw prevents onEnd. Outer close callback/rejection precedes inner close forwarding according to listener registration. No once flag or deduplication between error and close events. Events use the existing Emitter implementation/lifetime.

ISocket.write reads readyState each call and sends the identical VSBuffer.buffer only when equal to WebSocket.OPEN; other states silently drop writes. end and dispose each call ws.close every invocation. drain returns an already-resolved Promise<void>, not bufferedAmount polling. No listener removal, explicit Emitter disposal, cancellation, timeout, reconnect or new backpressure behavior is owned here. SocketProtocol owns framing; ChannelClient owns RPC cancellation. `connectViaProtocol(protocol)` is a thin synchronous one-client/one-accessor construction with unchanged protocol identity.

## RemoteServiceAccess facade

Retain all readonly public fields and service descriptor/runtime imports. Constructor eagerly constructs each proxy in the exact descriptor sequence in service-bindings.json. For each item, read its descriptor.channelName, call the identical channelClient.getChannel with its method receiver, immediately pass the returned channel to ProxyChannel.toService<Type>, then assign to the indicated own field before proceeding. No laziness, memoization, descriptor hardcoding, callback wrapping, optional-service omission or fallback. ProxyChannel owns call/listen/cancellation/method serialization; this facade neither executes service methods nor changes permissions. If any read/getChannel/toService throws, propagate synchronously and stop further bindings. Actual service descriptors remain existing shared data. Optional IServiceAccessor members are still eagerly present as required readonly fields in this concrete class.
