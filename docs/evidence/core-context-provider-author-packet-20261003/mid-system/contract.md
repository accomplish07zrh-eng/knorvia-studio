Projected marker: any truthy entry with present midSystemProjection property and truthy value; public projected message subtype has midSystemProjection:{fallbackBody:string}. Recognition is not a role/metadata test. Array identities/entry references and origins mapping order below are observable. Functions return new output arrays; unprojected entries retain identity. projectMidConversationSystemEntries has complete first projection phase then complete position-validation phase; all collaborators/errors happen in that order. Iterate input as ordinary live for-of traversal, not captured-length map. Request-local pending items contain original entry plus text. At each entry: first compute whether any pending item isPresentedInput (some short circuit), then nextIsUser=!attachment(entry)&&entry.message.role===user. If pending nonempty and [isPresentedInput(current entry) OR (pending contains presented input AND nextIsUser)], flush pending before attempting current text projection. Do not call isPresentedInput(current) in this gate when pending empty; preserve short circuits.

Current entry is projectable text only when attachment, then metadata.source accepted by actual isKnownSystemReminderSource, then accepted by actual isMidConversationSystemSource, in that order; text is exact entry.content, including empty string. Nonprojectable=>undefined. If text !==undefined, append pending{entry,text} and continue without pushing original. Otherwise, if pending nonempty and current nonattachment role assistant OR system, flush pending before current entry. Tool/ordinary user/other attachments don't trigger this second flush. Push current original entry. Flush at end.

Flush no-op when pending empty. Otherwise remove all pending items before collaborator work; body=texts joined two newlines, including empty values. Observe last projected entry. If it has truthy marker, first origins.set(previous,[previous,...pending originals]) with method receiver; then replace previous.message by shallow spread of then-current previous.message with content = then-current previous.message.content string interpolation + two newlines +body; then mutate then-current previous.midSystemProjection.fallbackBody by same separator+body. Do not replace marker object/entry, sanitize/wrap this merge or clone ancestry. This existing projection-entry mutation is retained behavior.

If previous has no marker but can anchor (nonattachment role tool OR user, including synthetic/model-only users), construct fresh {message:{role:system,content:body},midSystemProjection:{fallbackBody:body}}; origins.set(newEntry,pending originals) before pushing it. Other previous/end-empty positions push pending original entries unchanged, with no origins writes. Cache/metadata/kind fields are absent on newly constructed system entry.

Validation scans all first-phase output in order into a second fresh array. Nonmarker passes identical. Marker retained only if previous already-validated output exists and is anchor tool/user, AND next first-phase item is absent OR has truthy marker OR nonattachment assistant (this exact precedence; next attachment blocks unless marker branch already accepts it). Otherwise construct fresh fallback {message:{role:user,content:wrapSystemReminder(sanitizeSystemReminderBody(entry.midSystemProjection.fallbackBody))},metadata:{source:legacy_synthetic}} in that order. Sanitize then wrap exact fallback string, once each; origins.set(fallback,[marker entry]) after construction then append. No tokens/cache/queryScope/marker extras carried to fallback. Return fresh own {entries:validatedOutput}. Errors propagate and earlier projection-entry updates/origins writes remain; no transaction/rollback introduced.

moveLegacySystemRemindersAfterToolResultRun: separate ordinary for-of pass with new output and pending reminders. Legacy reminder = any attachment, else role user +metadata?.source===legacy_synthetic. Tool-result entry = truthy nonattachment, role tool OR isToolResultUserMessage(message). The public message predicate checks role===user && Boolean(toolCallId||toolName), preserving falsy empty IDs/names.

For each entry first check legacy reminder; if true AND (pending nonempty OR last output is tool-result), enqueue it and continue. With pending nonempty, current tool-result is pushed immediately while pending remains; any other current entry flushes pending originals in order before pushing current. Without pending just push current. Flush pending at end. This moves queued reminders past contiguous tool-result run without dedup/clone/projection/origin calls; markers are not automatically legacy. Return new output array with original objects. Do not change input/history/payload or add wrapping/sanitation to this pass.
