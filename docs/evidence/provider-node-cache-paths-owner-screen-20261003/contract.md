# Complete cache identity/path owner

Own only `packages/provider-node/src/builtin-cache-paths.ts`: four synchronous functions and two readonly interfaces. This is a pure identity/path-policy owner, with no mutable state, IO, cache read/write, credential lookup, endpoint request, expiry, migration, locking or source selection. Endpoint-scoped source is an unallocated consumer; D's upper owners and root's download/release owners are outside scope. Root may later freeze a complete independent candidate; preparation is not allocation, authorship or rights acceptance.

`resolveKnorviaBuiltinClientPlatform()` reads process.platform and process.arch each invocation. Map win32 to windows; all other platforms pass unchanged. Map arm64 to aarch64 and x64 to x86_64; every other architecture passes unchanged. Return platform plus hyphen plus architecture, with no validation, case change, special fallback, stored cache or caller options. This resolver does not run inside cache-path resolution: the latter uses its own supplied platform string.

`normalizeKnorviaBuiltinEndpointOrigin(value)` trims the supplied string. Empty trimmed input throws exactly `Knorvia Studio Built-in Endpoint Origin 不能为空`. Parse using the platform URL constructor; malformed URL errors propagate unchanged. Allow only parsed protocols http: and https:, else throw exactly `Knorvia Studio Built-in Endpoint Origin 只支持 HTTP(S)`. Return URL.origin under canonical URL semantics. This removes path/query/fragment and URL credentials and applies normal hostname/protocol/default-port/IDN normalization. It does not reject an otherwise valid URL because it contained credentials, require HTTPS, impose a host allowlist, append a slash or store the complete endpoint input. Those stricter CDN download rules belong to root's separate download owner. Original non-string/malformed URL errors are not sanitized or translated here; preserve the typed-string boundary.

`createKnorviaBuiltinEndpointKey(knorviaEndpointOrigin)` invokes that exact normalization, hashes the resulting origin string as UTF-8 with SHA256, takes the first 32 characters of lowercase hexadecimal output, and prefixes endpoint-. Origin equivalence therefore gives the same key despite path/query/fragment/credential spelling; different platform/version selection is handled by the next owner function. This 128-bit prefix gives the existing bounded collision risk, not an injectivity guarantee. Do not switch to a slug, raw URL/host, URL encoding, different length/digest or second normalization policy. No real endpoint or credential is in fixed data. Native hash is the existing dependency, not new security certification.

`resolveKnorviaBuiltinCachePaths(options)` normalizes supplied platform first, appVersion second, then derives the endpoint key from supplied knorviaEndpointOrigin. Each segment trims the string and rejects empty, exact dot, exact dot-dot, or any forward/back slash. Use a new Error with exact template `Knorvia Studio Built-in ${name} 不是合法路径段`, where name is platform or appVersion. Internal whitespace and every other character remain unchanged; do not add rejection of percent escapes, colons, reserved device names, NUL, Unicode, extra dots or separators beyond the current two slash characters. These are existing rules, not comprehensive OS filename certification. Validation order is observable when more than one input is invalid.

Construct directory with native node:path join from environmentConfigRoot, runtime, provider, normalized platform, normalized appVersion, endpoint key, in that order. environmentConfigRoot is a caller-owned opaque string: no extra trim/validation, resolve/realpath, HOME discovery, directory creation, existence check, containment assertion or default. Native join retains host-OS separator/normalization and error semantics. Derive activeFilePath by joining builtin.json and controlFilePath by joining builtin-refresh.json under that directory. Return a fresh plain object with these own enumerable properties in that order. Readonly API typing is not a runtime freeze, clone or asynchronous result. Native URL/segment/hash/path errors propagate; no fallback to another cache bucket, version, platform or endpoint.

| Dependency | Exact retained relationship |
| --- | --- |
| node:crypto | createHash SHA256; update canonical origin string using default UTF-8, hex output then fixed prefix length |
| node:path | join only, host-OS rules; never perform filesystem IO or substitute a portable separator string |
| process.platform/process.arch | native current invocation values for client platform function only |
| Native URL and string trim | canonical absolute URL/origin parsing and the described trim/segment rules; no new parser/library |

Public API signatures and readonly fields are in public-api.d.ts; original source has explicit returns. The declaration file is a reading input, not a relocated/typechecked package. Native globals are retained; full type/runtime/OS closure is not claimed.

Later bounded acceptance should cover platform/arch mapped and passthrough values; trimming and ordered platform/appVersion/endpoint errors; equivalence of normalized origin spellings; HTTP versus HTTPS/ports as distinct origins where canonical rules distinguish them; credentials/path/query/fragment removal; non-HTTP(S)/malformed/empty origins; exact hash prefix/length and fixed path order/names; no runtime freeze, filesystem access or invented fallback. None of those target functions was executed during preparation.
