# Runtime MCP methods — functional contract

Implement the complete exported API in api.d.ts. imports.txt is available dependency wiring, not required private decomposition. Use existing runtime fields/ports; private representation is author choice. Do not read predecessor source/history/compiled oracle/tests or other implementation files. No execution of credentials/ports. Preserve all literal protocol/log values below. No new trust or connection policy.

## Authority projection

computeOfficialCuaServerNames returns a fresh Set in server entry order. Read captured credentials once to obtain pluginAuthority before inspecting servers. Missing/falsy authority produces an empty Set without inspecting entries. Only a name in trustedServerNames, a stdio config, plugin env identity trimmed/lowercased equal to KNORVIA_CUA_OFFICIAL_PLUGIN_ID, and authority env trimmed exactly equal to the captured authority is admitted. The plugin env key is KNORVIA_PLUGIN_ID_ENV_KEY and authority env key KNORVIA_CUA_PLUGIN_AUTHORITY_ENV_KEY. Short circuit those conditions in that order. Do not infer trust from names alone. Exceptions propagate synchronously.

## Startup lifetime

startMcpStartup is synchronous, returning the runtime's tracked native promise or undefined; never make this public method async. If mcpInitialized is true return mcpStartupPromise without other work. Otherwise mark initialized before admission. If mcpPort is absent or config.mcp.enabled is false, mark mcpToolsRegistered and return undefined. Original state/partial effects survive synchronous port/logger/track errors.

Use config.mcp.servers or an empty record. If no keys, invoke the current MCP port's status() then listTools() immediately with their port receivers. Both run before promise settlement. Successful discovery yields a new object with keys statuses,tools and exact returned references. An async discovery rejection yields {statuses:{},tools:[]} after warning; no clock calls on this path. Pass the resulting promise to runtime.trackResidencyBlockingWork with runtime receiver, assign its return to mcpStartupPromise, and return that exact tracked reference. This discovery path has no scheduled log.

Configured startup captures Date.now before invoking connectConfiguredServers with servers identity and options ordered oauthAuthorizationTimeoutMs=15000,trace=the trace reference,workingDirectory=runtime.workingDirectory,workspaceIdentity=config.workspaceIdentity?.toString(). No abort signal or new timeout. On native success, build counts of each status.status in Object.values order, info-log completion, then preserve exact snapshot identity. On async rejection (including success callback failure), warning-log failure and yield fresh empty statuses/tools. These callback/error stages preserve native promise continuation ordering: success callback follows connection settlement; catch follows the success continuation. Track the final outcome promise, assign mcpStartupPromise, debug-log scheduled, and return tracked promise identity. Debug/track and initial port throws are synchronous, not normalized into async fallback. A throwing failure logger rejects the tracked outcome.

Log messages/fields in insertion order (traceContextToLogContext spreads first):
- discovery warning: "MCP existing tool discovery failed"; error (Error.message or String), event="mcp.existing_tools.failed",module="core.runtime",status="failed".
- success info: "MCP startup completed"; durationMs=Date.now()-start,event="mcp.startup.completed",module="core.runtime",serverCount=current Object.keys(captured servers).length,status="completed",statusCounts,toolCount=snapshot.tools.length.
- failure warning: "MCP startup failed"; durationMs, error,event="mcp.startup.failed",module="core.runtime",status="failed".
- scheduled debug: "MCP startup scheduled"; event="mcp.startup.scheduled",module="core.runtime",serverCount=Object.keys(servers).length,status="started".
Optional logger/method evaluation retains optional chaining; logger absent skips argument computations.

## Registration admission

initializeMcp is native async. If mcpToolsRegistered return with no effect. Call this.startMcpStartup(trace), then capture this.mcpPort. If either absent mark registered and return without await. Capture current configured server count before recoverable try/await. Await startup once. Register exact registry, captured port, snapshot.tools and ordered options: allowedTools=config.toolAllowlist,disallowedTools=config.toolDisallowlist,trustedWindowsComputerUseServerNames (fresh Set, only configured names when runtimeFeatures.computerUse===true),officialCuaServerNames (compute helper with current servers and fresh trusted official names Set). More than zero registrations invalidates runtime cache through its method. Info-log registration (trace spread,event="mcp.tools.registered",module="core.runtime",registeredToolCount,serverCount,status="completed"). Error from awaited startup or registration/invalidation/info callback marks registered before warning "MCP initialization failed" (trace,error,event="mcp.initialization.failed",module="core.runtime",status="failed"). Finally mark registered on ordinary settlement. A throwing catch logger propagates. Synchronous startup and server-count failures precede this recoverable boundary. Concurrent callers may both await the same startup and register twice; do not add a lock/retry/cleanup or silent policy repair.
