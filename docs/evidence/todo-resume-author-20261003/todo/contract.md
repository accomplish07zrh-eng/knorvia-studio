# Todo handler owner functional contract

Implement both exported ToolEntry values from api.d.ts. Public metadata/strings/field order and original schema identities are specified by declaration.json; use these fixed data without changing permissions or product prose. Dependencies are imported contracts/types in imports.txt. Do not read predecessor source, history, tests or compiled oracle. All service calls must stay owned by the supplied context sessionStore, with its receiver. No new cache/state/abort policy.

TodoRead native async handler parses input with TodoReadInputSchema before checking the store. Missing store throws createCoreError(CoreErrorType.ConfigurationError,"SessionStorePort is not configured for TodoRead",{context:{toolCallId:context.toolCallId,toolName:"TodoRead"},recoverable:false}). Read the current context.sessionStore.readTodos({sessionID:context.sessionId}) once, await once, return new object {todos:exact returned reference}.

TodoWrite native async handler parses TodoWriteInputSchema and retains the parsed todos array reference (schema may clone input). Parse precedes missing-store error, whose corresponding toolName/message use TodoWrite. Await current store.readTodos({sessionID:context.sessionId}) to obtain oldTodos reference; only after success call current store.updateTodos({sessionID:context.sessionId,todos:parsedArray}), await it, ignore its result. Then return ordered {oldTodos,todos,summary}. No cloning of oldTodos/parsed todos, no added signal/trace/options, no retries, no early cancellation check. Store methods and context fields are re-read at their actual phases, not globally captured.

Summary is computed after successful update settlement (so port mutations remain visible). Its ordered fields are total=todos.length,pending,count of status===pending,inProgress,count of status===in_progress,completed,count of status===completed. Status reads are three complete array-order passes: pending, in-progress, completed. No stronger schema/cardinality policy than imported schema; multiple in-progress is currently accepted. Unknown input/item handling stays owned by schemas.

Synchronous/async read and update failures propagate their original values/references; update is never called after failed read. An update may have already modified port-owned state when rejecting; do not roll it back or publish new events. Direct handlers do not inspect abortSignal; actual unchanged executor/deadline owns cancellation and result/telemetry publication. Keep only the original one/two native awaits, with no awaited orchestration wrapper. Read/write outputs and declaration are retained model/UI contracts, not originality evidence.
