## Public error and synchronous boundary

All public operations are synchronous. UnsupportedProviderConfigVersionError extends Error and accepts message:string plus version:number|null. Construction calls the ordinary Error constructor with the supplied message, then owns name with the exact retained class name and version with supplied value. version is readonly at type level, not runtime-frozen; no cause, new error code or property normalization is added. Preserve standard Error/prototype behavior rather than returning a plain issue record.

Decode accepts unknown and returns a shallow-frozen ProviderConfigLayerUpdate. Encode accepts that public layer type and returns a fresh plain versioned object without freezing. No JSON parse/stringify, hash, filesystem, locks, timers, callbacks, provider transport or persistence is executed by this owner. Repository owns durable validation round-trip and IO. Imported parser/schema/facade errors propagate synchronously without catch, fallback, masking or recovery.

## Version checks and error precedence

First inspect version of the supplied input. A record is any non-null typeof-object that is not an array; functions/arrays/null/primitives are not records. Do not require a plain prototype or normalize object identity. A schemaVersion key may be inherited because the presence test uses in. Missing/non-record returns the missing sentinel. A present version must satisfy Number.isInteger and must not be negative; otherwise throw UnsupportedProviderConfigVersionError with the invalid-version text and version:null. No coercion from strings, bigint, NaN, Infinity or fractions; -0 is not rejected by this numeric check.

Decode throws the exact missing-version error with version:null when the sentinel is returned. Version greater than1 throws the future-version error with that actual version before any strict object/rule validation. Thus unsupported/missing/invalid version errors precede extra-field or payload errors. Do not first apply a broad schema that changes error identity/order.

Current supported version is1 and the private migration catalog has zero registered entries. For a lower version, look up its specific next migration; when absent, throw the exact missing-step error with that current version. At current bytes version0 therefore cannot migrate successfully. There is no exported registration or fallback conversion API. Preserve the existing bounded one-step protocol without inventing a v0 importer or skipping directly to1.

If a genuine retained step were available, call it as an ordinary unbound local function with the current candidate, retain its returned candidate and require a versioned record. Missing version uses the migration-output error with version:null; invalid version uses the same nonnegative-integer error. A next version not exactly previous+1 throws the retained generic Error, not the unsupported-version class. Repeat only while below1; migration/candidate getter exceptions propagate. This protocol does not authorize adding a step to the currently empty catalog.

## Version1 strict envelope and parsing order

After version checks, use the retained strict stored schema: root schemaVersion literal1 and config object, both strict. Config includes optional providerOrder array of nonempty strings, providerConfigRules and modelConfigRules slots with unknown schemas, and optional canonical ModelSelection. Do not substitute a permissive schema, require trimming/uniqueness for order entries, add a default empty order, loosen null handling or silently strip extra root/config fields. Rule-slot presence/undefined handling remains canonical Zod behavior; the two personal parsers own meaningful rule payload validation.

Provider order allows empty arrays and duplicate/whitespace-only nonempty strings according to the unchanged array/string schema; no codec sorting, deduplication, provider existence lookup or extra constraints. Canonical ModelSelection trims and requires nonempty providerId/modelId, permits optional strict options containing optional trimmed nonempty reasoningLevel, rejects extra fields and does not execute the selection. Canonical parse copies/transforms are retained; do not reuse raw input order/selection as a substitute for the parsed output.

Once the envelope parses, construct result fields in the fixed observation order: parse personal providers first; normalize legacy manual model rules, then parse personal models; project parsed providerOrder; include defaultModelSelection only when parsed value is not undefined. Provider failures prevent model normalization/parsing. Model failures prevent returning the result. The returned object always owns providers/models/providerOrder even when order is undefined, has optional-own defaultModelSelection, excludes schemaVersion/config/providerTemplates and is shallow-frozen. It retains the exact returned provider/map-rule instances and parsed array/selection references, without deep freeze or a second reconstruction.

## Narrow legacy manual-rule recognition

Legacy compatibility is a file-boundary model-rule operation, not a whole-format version migration. If the supplied model-rule slot is not a record or its manualProviderModelRules member is not an array, pass the original value unchanged to the personal model parser. Do not fabricate a missing list or replace malformed input with an empty rule set.

When that member is an array, return a new shallow object retaining the input's enumerable own top-level properties and replace only manualProviderModelRules with a same-order mapped array. Other top-level/rule fields, extra keys and invalid IDs are not cleaned. Each element that is not a record passes unchanged. For a record element, first safeParse its config with current strict manualModelConfigSchema. If valid, return the original rule object, ignoring that safeParse's parsed data; do not normalize/clone an already valid rule here.

Only if current manual validation fails, safeParse that config using the retained ordered union: (1) legacy complete model shape with sparse enabled, (2) legacy editable manual shape with requiresMfjsToolSchema restored as a required boolean property. Both schema shapes and validation must be preserved; recognizing the mere presence of a legacy field is insufficient. A success produces a new shallow rule object retaining all enumerable own rule properties, replacing config with extractManualModelConfig of the union's parsed data. This retained extractor selects only current product-editable schema leaves and parses the projection. It may throw and its error propagates.

If the legacy union fails, return the original rule, including bad config/unknown fields, for final personal validation to reject. Do not delete unknown/system keys to disguise corrupted or unauthorised configurations as successful input. Existing current manual shape, both old recognized shapes, enabled sparsity, complete numeric/boolean/option-map constraints and union order remain fixed. Compatibility does not apply to smart providerModelRules or other groups and does not change provider access rights. The final personal parser still rejects invalid rule IDs, mode conflicts, unsupported groups or extra keys.

## Encoding and output identity

Encoding does not call decode or run a schema validation of its own. It projects trusted supplied layer data through retained facade serializers, preserving those receiver calls. Build outer keys schemaVersion then config. Within config: conditionally project providerOrder when not undefined; then providerConfigRules with providerRules from update.providers.toJSON(); then modelConfigRules from update.models.toPersonalJSON(); finally conditionally project defaultModelSelection when not undefined. Preserve this getter/call order and synchronous failure boundary.

Optional field checks are undefined checks, not truthy/nullish checks. No cloning/defaulting is introduced for providerOrder or defaultModelSelection; included values preserve original references, including noncanonical runtime nulls which a later decode may reject. Retain facade serializer result references in fresh wrappers, even if supplied collaborators can return invalid values. Exclude providerTemplates and any arbitrary layer fields. Outer/config/provider-rule wrapper objects are fresh and mutable; arrays/selection/facade data are not deep-cloned or newly frozen. No pretty serialization, timestamps, credential masking or fallback rules are added.

The existing encoded return has no explicit source return annotation. The body-free declaration grounds version1 and nested output using canonical toJSON/toPersonalJSON ReturnType relationships. It is not a claim of complete semantic TypeScript/Zod inference closure; root will check against current retained public types.
