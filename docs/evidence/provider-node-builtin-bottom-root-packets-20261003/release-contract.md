# Complete release owner rules

Own exactly `packages/provider-node/src/builtin-release.ts`: schema-version constant, two readonly interfaces, decode, encode and serialize. Retain canonical provider/model parsers and their facade classes at `@knorvia/provider`; do not reconstruct their schemas/facades, static configuration, runtime state, registry/source selection or D's higher owners. No IO, version migration, cryptographic digest/signature, fallback, endpoint choice or comparison to current revision belongs here.

Decode synchronously validates unknown input with pinned Zod 4.6.5. Outer object is strict with schemaVersion equal to numeric literal 1, revision a number with integer, nonnegative and maximum Number.MAX_SAFE_INTEGER constraints, and strict config object holding exactly providerConfigRules and modelConfigRules with canonical unknown slots. Preserve canonical required-key/unknown/undefined semantics and ZodError issue generation; do not handwrite a different validator, coerce numeric strings, default values, strip extra keys or accept another version. Negative zero is not specially rejected/normalized. This owner does not impose revision monotonicity. The rule payload slots are validated by retained parsers, not the unknown-slot outer schema.

After successful envelope validation, call `parseKnorviaBuiltinProviderConfigRules` first with its provider slot. Preserve the returned providers and providerTemplates facade identities. Before parsing models, call providers.has with exactly `builtin:zapi`; if true, reject the entire release with a new Error and fixed message `Knorvia Studio Built-in Release 包含已退出的 Provider: builtin:zapi`. Do not filter/rewrite the rule, create a partial release or call the model parser in this branch. This prevents an old release/LKG from reintroducing the retired provider; higher source selection owns any compatible-candidate fallback. If provider validation fails, its original error propagates and models are not parsed.

Call `parseKnorviaBuiltinModelConfigRules` with its slot only after the provider guard passes; preserve returned identity. Construct config with own enumerable keys providers, providerTemplates, modelConfigRules in that order, freeze that object, then construct/freeze the outer object with own enumerable keys schemaVersion, revision, config in that order. schemaVersion is the fixed constant, revision is the parsed numeric value. These are shallow freezes of the two new envelopes, not a deep traversal/clone of supplied facades or nested records. Provider parsing, retired-provider guard and model parsing error/side-effect order is observable. Standalone decode propagates canonical schema/parser/facade errors unchanged; only the retired-provider branch adds this owner's exact Error. Download's separate boundary later sanitizes all of them.

Encode is synchronous and returns a fresh plain object with root own keys schemaVersion, revision, config in that order. It always projects fixed schemaVersion 1, even if a malformed caller object carries a different value; it directly reads release.revision and does not validate/normalize it. Config contains providerConfigRules then modelConfigRules. providerConfigRules contains templateRules then providerRules; evaluate providerTemplates.toJSON with its facade receiver before providers.toJSON with its receiver, then modelConfigRules.toKnorviaBuiltinJSON with its receiver. Use collaborator return values directly: no copying/sorting/filtering/deduping, no Promise or replacement serialization, no mutation/freeze of inputs or returned envelopes. Canonical facade serializers own ordered rule projection and any schema validation/error, including model serializer validation; the encoder does not add another envelope/retired-provider/revision validation. Any thrown error propagates. Output is typed object in the original API, not a strengthened new public return shape.

Serialize calls this owner's encode then native compact JSON.stringify with no replacer/space argument/newline. Preserve ordinary property order and JavaScript JSON handling of undefined/nonfinite/toJSON/errors; do not add stable sorting, pretty printing, trailing newline, defensive normalization, caching or error conversion. Existing callers separately pretty-print disk data and append their own newline where appropriate; that is not this function's responsibility.

Acceptance scenarios for root's later bounded review: version 1, revision 0/MAX_SAFE_INTEGER and -0; reject wrong version, negative/fractional/too-large/wrong-type revision and strict extra keys; provider-first error order; retired provider halts before model parser; returned identities plus two shallow frozen envelopes; exact property/evaluation order; encode always fixed version and propagates collaborator errors with receivers; compact serialization without newline; no migration/retry/source fallback. Schema/facade exact behavior remains the dependency's responsibility, and runtime/type acceptance has not been executed here.
