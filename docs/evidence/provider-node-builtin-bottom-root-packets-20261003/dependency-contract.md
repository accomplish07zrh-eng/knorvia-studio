# Retained public dependencies and runtime ports

| Route | Reading view / retained boundary |
| --- | --- |
| `./builtin-release.js` | release-api.d.ts and release-contract.md, independently allocated to root; download consumes decode plus release type |
| `@knorvia/provider` | dependency-types.d.ts describes the two parser signatures and minimal canonical facade type relationships; actual provider/model implementations and static schemas remain retained |
| `zod` | package pinned to 4.6.5 in provider-node package metadata; canonical schema construction/parse, ZodError and first issue path/code behavior, not a replacement validator |
| Native URL/URLSearchParams, AbortController/AbortSignal, timers, TextDecoder, JSON, Object.freeze | existing platform semantics used by the complete owners; no new package or API |
| Caller request callback | download options includes its exact `(url: string | URL, init: RequestInit) => Promise<Response>` signature; URL objects actually supplied; preserves options receiver |

Declaration files are body-free reading views, not relocated executable packages or complete facades. Canonical import spelling and nominal class/type relationships remain original. Pick aliases identify only used methods while preserving canonical return types; they do not replace the canonical class declarations. Full TypeScript/Zod/global-web-platform semantic closure remains deferred. Do not follow source implementation bodies during independent authoring. Root can provide canonical public type surfaces later for checking.

The retained provider parser validates strict builtin rule groups templateRules/providerRules, including nonempty identity fields and canonical duplicate-ID errors; then produces provider and template facades preserving declared order. Builtin provider config excludes personalModelIds/modelOrder and requires group zai-family or bigmodel-family, not standard-personal or null. Template config admits canonical logo/access/api/builtinModelIds fields; template API-key access schema omits apiKey. Template language map accepts only optional zh-CN/en-US nonempty values. Rule metadata remains providerId, optional/null templateId/providerName and optional enabled. Nested canonical sparse/nullable provider access, API, visibility, logo and model ID validation is unchanged; no new credential/body input is in these packets.

The retained model parser validates strict arrays in fixed group order: modelRules, modelApiRules, providerSiteRules, templateModelRules, builtinProviderModelRules. Pattern rules retain nonempty anchored-RegExp-valid syntax and their canonical required/optional matching fields; exact/template rules use nonempty identities. Config uses unchanged canonical sparse model data and option-map validation. Parsing constructs rule types model, model-api, provider-site, template-model, provider-model in that same group order, preserving order inside each group. No personal/manual rule group is added here. Provider parser errors, duplicate rules, mapping/regex validation and model constructor behavior are retained collaborator facts, not reimplemented by these two owners.

Facade ports actually consumed: providers.has for retired-provider rejection; providerTemplates.toJSON and providers.toJSON for canonical arrays preserving membership/order/metadata; modelConfigRules.toKnorviaBuiltinJSON for exactly the five builtin groups. Model serialization canonically validates its constructed builtin data, filters by builtin rule kind in group order and retains within-group order; errors propagate. Neither owner overrides collaborator outputs or performs complete-provider admission validation. Exact schema nested fields/diagnostics remain source-derived canonical definitions at fixed metadata bindings, not duplicated runtime code. Existing [schema qualifications](../provider-config-file-codec-root-packet-20261003/schema-contract.md) describe shared model/provider schema boundaries, but personal-only rules there are not these builtin rules and that document is not an additional author input.

Runtime safety stays with existing browser/Node primitives and caller-supplied Response/streams: reader cancellation is fire-and-forget with rejection observed and locks released, late response cancellation observed, timer unref optional, methods preserve platform receivers. No physical network/TLS/redirect enforcement, actual cache access, OS or security certification was run by the packet checks. Request initialization describes this owner's policy; injected callback compliance requires later review.
