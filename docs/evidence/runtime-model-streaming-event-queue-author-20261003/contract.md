# Ordered streaming event write queue

Constructor synchronously captures highWaterMark=params.highWaterMark ??128 only; mutable params runtime/trace/events are read when each queued write begins, not at construction. Return keys in order drain,enqueue,maybeApplyBackpressure. Initial native resolved promise chain and pending0; no runtime calls until microtask. Each enqueue synchronously checks truthy remembered failure then increments pending, schedules one serialized native promise continuation, catches failure, and finally decrements pending. Retain original payload reference and mutation visibility until write. Each continuation skips emission iff remembered failure truthy; otherwise awaits params.runtime.emitModelStreamingEvent(payload,params.traceContext,params.events) receiver-bound. Catch first non-nullish failure using nullish assignment; falsy reasons0/false/empty-string are remembered but do not trigger truthy failure guards; null/undefined permit replacement. Keep these legacy observations rather than repair.

Native async drain: internal drain awaits current tail then checks truthy failure; returned public drain itself awaits that internal drain (two native async boundaries). Concurrent enqueues after capture do not alter the captured drain tail. maybeApplyBackpressure native async checks failure first; pending below threshold returns with no internal-drain await, else awaits same internal drain. No new timers/flush/retry. Queue remains single lifetime/error owner; callback/event persistence belongs runtime. Preserve then→async write→catch→finally phase ownership, not a detached pump with different microtasks.
