# Complete ChannelClient call/subscription lifecycle

Own only `packages/rpc/src/channelClient.ts`: exported ChannelClient class implements IChannelClient and IDisposable, with constructor(protocol), readonly onDidInitialize, generic getChannel and dispose(reason?: Error). No extra exports/public factories or transport/reconnection/foundation/serializer implementations. Public signatures and canonical imports are supplied separately. Root's PR12 transport consumes this retained RPC API; this owner is a different file/layer. Retain source attribution/fixed wire material and freeze a complete candidate before comparison; no license or independent-expression acceptance follows from this specification.

One client owns initialization state (uninitialized initially, idle after Initialize), disposed flag, monotonically incrementing numeric request ID counter starting at 0 shared by calls/event factories, response handlers keyed by ID, a separate pending Promise rejection collection, active disposable collection and protocol-message subscription. Promise reject collection is distinct from event handlers so connection disposal never tries to reject subscriptions as RPC calls. Native Promise/Map/Set ordering/assimilation and retained Event/Emitter semantics remain observable. Do not add timeout, retry, ID reuse/wrap policy, backpressure, validation, reconnect, revision/account state or second cache. Private declarations in the original are TypeScript-private rather than runtime # fields; this specification does not claim a source-private security boundary like the endpoint-scoped owner.

Construct the initialization emitter and retain its event as public readonly onDidInitialize. Immediately subscribe once to protocol.onMessage with protocol receiver; dispatch incoming VSBuffer through retained deserialization. Constructor does not send Initialize, wait/drain or issue a channel request. getChannel always returns a fresh plain façade with call then listen, capturing supplied channelName unchanged. Each method reads current client state when called. After disposal call returns rejected Promise with new Error `ChannelClient is disposed`, and listen returns the exact retained Event.None without creating a request ID/emitter. getChannel itself is still allowed. No trim/type/schema/name normalization or façade freeze.

For a live call, allocate/increment the next ID before examining cancellation. Default undefined cancellation token to retained CancellationToken.None. If token is already cancelled, return rejected new Error `Cancelled`, without sending/registering pending work/disposable; that ID is still consumed. Otherwise create a native result Promise and record its reject under ID before any send. If idle, dispatch immediately; otherwise wait via retained Event.toPromise(onDidInitialize) and dispatch when initialized. At deferred dispatch time check disposed or absence of pending rejection, and silently return when already disposed/cancelled/completed. This fail-closed guard prevents a queued completed/rejected call being sent after Initialize. It does not apply to event-listen scheduling below.

Dispatch a call by registering its response handler before sending. Wire request is two retained serializations in order: header [RequestType.Promise, id, channelName, commandName], then exact supplied arg (including undefined). Use a fresh retained BufferWriter. The call handler acts only on PromiseSuccess/PromiseError/PromiseErrorObj. Before settling any of those, delete handler and pending reject. Success resolves the exact response data through native Promise semantics. PromiseErrorObj rejects raw response data unchanged. PromiseError creates Error from data.message, assigns data.name, and only when data.stack is truthy replaces stack with its array join using newline (empty array is truthy and joins empty string). Preserve the exact passthrough keys in retained-data, assigning only values not undefined (including null/false/0) without cloning/normalization; no arbitrary extra keys/cause or new error type. Then reject that Error. Unexpected response kinds for a call do nothing. Malformed payload/stack errors propagate from dispatch with original timing; do not repair them or add schema fallback.

After scheduling/dispatch within the Promise executor, register token.onCancellationRequested with token receiver. Cancellation callback first returns if pending reject is gone. Otherwise send PromiseCancel header [type,id] and undefined body, remove handler and pending reject, reject new Error `Cancelled`. Cancellation before Initialize still sends the cancel packet; the deferred call later does not send. It is legal for synchronous transport response/cancellation to happen during scheduling/subscription: retain pending map guard and original order. Track the returned cancellation disposable in active requests. Return the result Promise's finally wrapper: dispose that cancellation subscription with its receiver, then remove it from active requests if present. Cleanup errors can replace Promise fulfillment/rejection and stop subsequent cleanup; no catch/suppression or exactly-once normalization beyond retained disposer's own semantics. Client.dispose may already have disposed it; finalization still calls it again.

Calling live channel.listen allocates/increments an ID immediately, creates a retained Emitter and installs a response handler before any real event listener. This handler passes response.data directly to emitter.fire, without filtering response discriminator or cloning. Return its Event, not the emitter or subscription. First-listener hook either dispatches immediately when idle or queues via whenInitialized; dispatch adds the emitter to active requests then sends [RequestType.EventListen,id,channelName,eventName] and exact arg. Last-listener-removal hook removes the emitter from active requests, sends [RequestType.EventDispose,id] and undefined body, then deletes its response handler. No extra guard/re-registration/retry is inserted.

Preserve current event lifecycle edges rather than silently fixing them: deferred EventListen dispatch has no disposed/pending/has-listeners guard, so removing listeners or disposing before Initialize does not rewrite that continuation. Deleting the handler at last removal is not undone on a later first-listener hook of the same Event, which reuses its originally allocated ID. Inactive event factories can retain a handler even with no active listener. A retained Emitter disposed by client.dispose clears listeners but does not invoke the last-listener hook. Any later disposal of a previously returned listener disposable follows retained hook semantics, including sending EventDispose through the still-called send boundary. These source behaviors need explicit source comparison, not invented connection recovery.

Both normal and cancel/event-dispose packets create a new writer and serialize header then body. Serialization/constructor errors occur outside the send catch and propagate with original surrounding Promise/hook behavior. Only protocol.send(writer.buffer) is inside a swallow-all catch (including writer.buffer access there); keep protocol receiver. A thrown transport send does not auto-reject/remove/retry the call/event or tear down the client. No drain, flush, socket close/native write or transport flow mutation is owned here.

Incoming processing constructs retained BufferReader(message), deserializes header first and body second even for Initialize/unknown types, then reads header[0]. Initialize sets state idle and fires onDidInitialize with undefined for every such packet, including repeated Initialize. PromiseSuccess/PromiseError/PromiseErrorObj/EventFire dispatch ID=header[1], data=body to the existing handler if present. Unknown type has no further effect after deserialization; unknown/completed ID is ignored. Incoming handler is called unbound. No new parsing/catch/schema/ID-kind validation. Deserializer/emitter/listener/handler exceptions propagate; do not turn them into a new pending rejection. whenInitialized resolves immediately if idle, else uses retained Event.toPromise; no disposal rejection is introduced for this separate initialization wait.

dispose is synchronous and idempotent after first entry: set disposed first, dispose protocol-message subscription with its receiver, then null its slot. If that throws, later steps do not run and subsequent dispose returns. Use caller's Error reference when provided; otherwise create new Error `ChannelClient disposed` and set name `ConnectionClosed`. Iterate the live pending rejection collection in insertion order; remove each reject and handler before invoking its reject unbound, all with the same rejection object. This covers both sent calls and calls queued before Initialize. Then iterate active disposables in native Set order and dispose each with its own receiver; clear active and pending collections, and dispose initialization emitter. Cleanup exceptions propagate/stop the remaining sequence; no rollback, retry or suppression. There is no blanket clearing of every handler; event handlers not removed by their hooks remain. Do not reject event listeners, issue network cancellation beyond retained hooks, or close the underlying protocol. Pending Promise finally handlers run under native Promise ordering and may repeat disposer cleanup after client.dispose.
