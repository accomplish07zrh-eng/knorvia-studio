# 用量持久存储与统计验收

基线 `dca7ae1`。按[先行合同](../specs/knorvia-usage-storage.md)独立替换三种写入、清理和两个查询入口。三张现有 SQLite 表仍为唯一持久状态；写入先完成原有准备和投影，再由既有自有事务整体 upsert、取清理时钟、裁剪并提交。无 schema、facade、前端或真实数据改动。

## 先行和补强证据

旧目标最终先行 **50 项：31 通过、19 预期失败**，0 跳过。19 个失败由三种写入各五项原子场景、直接裁剪三个自动回滚场景和一个清理双失败场景组成，不表示 19 个独立产品缺陷。前五项覆盖新增、冲突更新、外层事务拒绝前未修改、真实延迟外键 COMMIT 失败、成功 upsert 后时钟抛错。旧版在清理失败时留下已写入的行或覆盖值，自动回滚后的第二次 ROLLBACK 又可能掩盖首因。

兼容检查保留全部模型字段、轮次与工具的不同合并政策、原生 FK/check/secondary unique 错误、JSON 首因和字节顺序、准备与时钟阶段、严格 30 天全局裁剪、自身过期的成功写入、原生日期桶、应用聚合和任务独立输入基线。时间/次数/累计量按各字段原政策处理，没有统一做截断或补零。

测试审查补入了另一会话隔离、同日多模型、不同正数轮次计数、工具 nullable flags；主代理另补每会话全 NULL duration 在跨会话 MAX 前按零处理，旧版先行通过。后续只读复核发现两个新实现差异：原生 SUM 变 NULL 后必须先零化再做模型排序；NaN offset 的 days 分组键需要保留原生 null。两项在新代码上先运行 **8 项：6 通过、2 失败**，再按行为合同修正。

主代理首次额外断言误把 dayModels 的相同键也预期为 null；冻结旧模块明确返回 0，已修正合同和夹具并记录该失败。days 与 dayModels 的这项既有不同投影继续保留。最终冻结旧模块的两组数值边界四断言通过；没有把错误预期或初版通过数量当作最终验收。

## 来源和限制

逐文件输入、表达与许可范围见[来源记录](../licensing/evidence/usage-storage.md)。主代理与复核者读过旧实现；隔离作者只收到先行合同、选定公共声明和依赖签名，以及行为级澄清。既有事务 helper 继续拥有清理，不在新模块复制 catch/rollback；写入、应用聚合和任务累加按不同政策组织，不以移动、改名、标准 SQL、行数或测试通过单独证明原创。

所有验收仅用构造的内存库和离线数据。没有真实模型调用、设备操作、真实用户库、跨进程压力或磁盘故障验证；不保证任意 Proxy/getter、损坏数据库或未定义排序输入完全等价。应用查询仍是多次独立同步读取，未增加快照一致性承诺。相邻 schema/migration/facade/调用者不随本批改许可；根 Apache-2.0、预览版本与第三方声明保留，整仓独立和最终稳定发行尚未完成。
