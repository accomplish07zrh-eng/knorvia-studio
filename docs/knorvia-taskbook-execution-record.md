### T10 性能（`81b2073` + `6e1b4f2`）

先测量后优化，并如实记录测量条件：本机 Node `v26.3.0`（非 mise 固定的 24.14.0）。真实基线：滚动 6 样本 p50 6.8–10.0ms、p95 20.1–26.7ms、>33ms 帧 0–2、挂载行 20、锚点位移 0/0px；桌面冷启动到首个引导页 5904–6430ms，**未达到 3 秒目标**，且热启动无改善，阶段拆分显示 Host fork → 首次可交互约占 65%。按证据实施了两项优化：

1. **运行历史有界化**（`81b2073`）：真实组件 100 次运行 × 8 步，挂载 442/471ms → 235/249ms，刷新 236 → 132/142ms，挂载步骤行 800 → 160，DOM 节点 3613 → 726，且可完整展开还原 101/101 次运行。
2. **并行准备两个数据库**（`6e1b4f2`）：复核确认 2.8–3.0 秒的存储准备是 tasks-index 与 CLI 会话库**两段串行**（不同文件、不同 WAL、互不依赖），已改为并行并保持阶段通知顺序与失败优先级不变。同机同命令前后对比：首次可交互 median 5799 → 5554ms、Host fork → 首次可交互 3782 → 3516ms、`[database-startup]` 2906 → 2654ms（收益约 250–300ms）。**`<3 秒` 仍未达标**（约 5.5 秒）；剩余固定成本是 15.9MB CLI 包启动、SQLite 建库/WAL/fsync，以及约 0.8s Host 启动、0.24s 服务构造、0.18s 端口/IPC/渲染，全部仍在同一条串行链上；要达标必须把「首次可交互」与数据库就绪解耦，属产品/架构决策，未擅自改动。
