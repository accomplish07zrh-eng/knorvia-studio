边界与剩余风险：任意用户主动输入的文本可能本身就是秘密，会保留在会话数据中；按字段名和常见凭据形态脱敏无法证明识别所有自定义格式。以前版本生成的原始崩溃转储仍留在本机原目录，未自动删除或改写，也不会进入诊断包。临时配置恢复对无法确认已死亡的 PID 保守保留；若操作系统复用 PID，可能需要用户手动检查遗留目录。此处的“通过”只指列出的离线夹具和本机检查，不代表真实服务或已登录 CLI 的实测。

## 阶段 1 手动诊断预览补充

`packages/desktop/test/local-diagnostics.test.ts` 在隔离目录写入虚构 API Key、token、创作记录、Studio SQLite、凭据文件，以及含密钥的日志文件名和内核元数据。手动预览及随后导出的 ZIP 均无原密钥命中，ZIP 只含匿名日志、内核概况和不含主机名的系统摘要；每项 SHA-256 均与预览一致。预览后改写源日志不会改变冻结包，已消费或任意路径形式的 ID 无法再次导出。Node v24.14.0 下整套离线测试为 502 项通过、0 失败（103 个文件）；类型、lint、架构检查均通过。脱敏仍无法识别所有未遵循常见格式的秘密，因此设置页要求用户预览后主动导出，不自动上报。
