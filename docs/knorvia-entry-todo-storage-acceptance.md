# 会话条目与待办持久写入验收

固定基线 `0758673`。按 [先行规格](../specs/knorvia-entry-todo-storage.md) 重建两个仓储及一个同步写边界，SQLite 行仍是唯一状态。独立条目写入及其 session touch 一起提交；已有外层事务只借用，不由本方法提交/回滚。Todo 始终取得自己的事务。原公共签名、表结构、读取次序、模型选择包装/旧成员保留和 UI 不变。

## 先失败后修复

主代理先行 21 项在旧代码运行：18 通过、3 预期失败。真实触发器证明独立条目 touch 失败仍留下已提交 entry，Todo 自动回滚后第二次回滚掩盖首因；模拟清理再次失败证明旧逻辑只返回清理错误。新边界把独立条目 upsert/touch 放在同一事务，只清理仍活动的自有事务；双失败 AggregateError 同时保留两个原因及主因 cause。

新版 21 项通过后，只读复核补做四个全新内存库场景：已有 entry 更新后 touch 失败的恢复、条目和 Todo 的真实延迟外键 COMMIT 失败、借用事务的 SQLite 自动终止，全部通过。将两项延迟外键场景固化为源码回归，确认 INSERT 阶段已完成、COMMIT 才失败，附带写入也被撤销。最终新增 **23 项**，含 full-access 和 codec-store 的相关组合 **47/47** 通过。

借用分支不主动结束外层事务，但 SQLite 本身仍可通过 RAISE(ROLLBACK) 终止它；文档不把“不发控制命令”说成阻止数据库回滚。已有外层事务的普通 entry 失败保留待决写入，由外层 owner 决定清理；该语义和独立调用的原子性分别验证。
