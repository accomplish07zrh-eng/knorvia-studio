# 创作已知失败测试时序验收

2026-09-29。本批只修正创作离线测试与先行规格，保留服务的500ms截止时间、终态轮询1000ms预算和总提交数恰为4的要求，不修改产品实现、UI、凭据、任务数据或重试规则。CreationService继续独占业务状态；测试独立控制业务截止时钟，终态观察使用真实计时器。

原始GitHub run [36517528509](https://github.com/accomplish07zrh-eng/knorvia-studio/actions/runs/36517528509)，提交1789ad9，Windows的json-api组合用例在取消提交门闩后计数3而非4；3,000项中2,999通过、1失败。Linux2,993通过、7平台跳过。原始运行没有重跑或改成成功记录。

原用例首轮只断言failed。业务在等待running落盘、凭据或参考图时已启动截止计时；提交前超时也按既有规则记为failed，可能在没有请求供应商时满足这条断言。仓外隔离复制件仅给首次模拟凭据读取加600ms真实等待，保留原500/1000ms和精确4，复现首次failed/超时/0提交，随后最终3而非4。该实验确认一条误通过路径，**没有证明原CI具体慢在磁盘、凭据还是调度**。

修正从首轮已知失败起冻结业务截止时钟；failed还必须含供应商400错误且提交数为1，成功重试后须为2。轮询helper新增可选调度器，仅这些用例传捕获的真实计时器；默认调用不变。超时分支依旧先等待提交门闩，再推进500ms并恢复真实时钟等待终态落盘；取消分支仍单独冻结截止时间并断言精确4。独立的提交前、成果落盘及取消落盘截止用例继续保留。

```text
业务虚拟时钟冻结 → 首轮收到400且提交1 → 重试成功且提交2
  → 等到超时任务提交 → 推进500ms → interrupted落盘
  → 等到取消任务提交 → 精确4 → cancelled且不可一键重试
真实轮询计时器 ───────────────→ 每次仍以1000ms预算诊断未完成
```

验证记录：

- 隔离原症状复现1项失败，810.7608ms；首次提取脚本括号遗漏导致转换失败，修正夹具后才得到上述行为证据。隔离修正复制件三协议3/3及严格类型通过。
- 整合后创作与截止测试14/14，0失败/跳过/取消，2884.0249ms。第一次定向命令遗漏既有模块模拟开关，截止文件加载报mock.module不可用；另11项通过，但整轮不记成通过。补齐与统一测试入口相同的开关后得到14/14。
- 根对整合文件再次复制并只加入首次模拟凭据600ms等待，三协议3/3，9457.2748ms；保持500/1000ms及全部精确计数。第一条外部加载命令用Windows路径而非URL导致启动失败，原日志保留；改用根入口可解析的tsx后才得到运行结果。OpenAI协议首次凭据读取发生在模型保存期间，因此这不是三协议均在提交前卡住的证明。
- 根类型检查（含desktop main及5422个中英文键）、根lint2781文件0警告/错误、两测试严格类型、改单测试94规则严格lint、架构0违例及两文件格式通过。
- 产品源码及CLI产物未改，沿用已验证13f7d2f构建。修改后的完整离线回归 **3,071/3,071**，0失败/跳过/取消，514917.9591ms；固定Node24.14.0、Python3.13.14绝对路径和本地驱动归档，无编译缓存。

子进程模块原始run [36519316617](https://github.com/accomplish07zrh-eng/knorvia-studio/actions/runs/36519316617)，提交13f7d2f，Windows3,071/3,071及Linux3,064通过/7平台跳过，全部质量步骤成功。它不包含本测试修正，也不能推翻较早运行的真实失败；本修正自己的云端结果另记。

未调用真实供应商或付费模型。冻结setTimeout可能影响本机文件重试等待，真实1000ms看门狗仍会如实失败；本次未注入文件锁重试。有限行为测试不证明全部负载条件。原测试/规格的来源分类不因这次小修正改变，只有本篇新文档按具体摘要审阅；根Apache-2.0、保留权利和preview身份继续有效，全量独立目标未完成。
