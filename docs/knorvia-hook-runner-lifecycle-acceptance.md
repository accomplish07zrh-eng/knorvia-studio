# Hook Runner 批次与回调生命周期验收

以 `d7f56db` 为固定基线，按先行 `specs/knorvia-hook-runner-lifecycle.md` 将每次 run 表达为同步生成器计划。计划拥有参与列表、可见数量、两种索引和结果；异步驱动只执行发布/回调端口并返回原值或异常。后台使用独立计划，dispatch 的 CallbackLease 拥有子信号、定时器、结算入口与清理。不引入跨运行队列、权限缓存、配置副本或旧执行实现 fallback。

## 来源限定

已接触原源码，不作无接触声明。独立实现依据是先行的批次/资源所有权规格、类型化动作程序和单一驱动/结算路径，不以拆文件、改名或测试通过单独判断。七份实现中 runner-plan 只有内部动作/身份类型，六份有运行时代码。固定协议字段、文案、公共接收对象、原有事件次序、Promise/定时器/取消平台语义不主张为原创发明。

配置与进程执行、workspace 信任与存储、display-metadata 脱敏、公共 Hook schema/types 和相邻模块保留适用许可。根 Apache-2.0、0.8.0-preview.3 和旧发行不变；没有 UI、用户数据、真实命令/模型/浏览器/设备、安装/便携或官网操作。整仓独立与最终 MIT/稳定发行尚未完成。

## 修复与保留

Started 发布可等待，在此期间撤销/禁用后，旧版仍启动前台或后台回调。保留初始预筛和逐条开始前检查，新增发布完成后、实际 dispatch 前的同步准入；与回调之间不增加 await。拒绝或晚到的 skipLifecycle 用同一 runId、描述符、索引和 hookCount 关闭为 Blocked，后条仍继续。Hook 准入拒绝不注入工具权限 deny；同时取消且撤销时采用 Blocked，仍获准但取消采用 Failed/cancelled。

登记数组复制、登记对象活引用、每 run 成员快照、runtime/visible 索引区别、原输入、描述符和更新引用、注册端口与 logger/emitEvent 接收对象保持。输出在前台终态发布前合并，终态发布故障不回滚；后台不解析输出。取消、超时和迟到回调只结算一次，父监听和定时器清理。

signal 在 Started 返回后读取；前台 getter 故障进入 Failed，后台 getter 仍在背景执行 try 之外向上拒绝。后台启动到下一条准备之间不增加等待。驱动只捕获端口执行故障，计划内的失败日志异常不再次注入计划，避免重复 Failed 或吞掉原异常。

## 先行及定向验证

30 项先行合同在旧版 **23 通过、7 预期失败**：前/后台撤销及禁用、撤销同时取消、最终准入与回调之间无等待。首稿修复后 30/30 通过。之后补充前/后台的 allowed 仍为 true 但 skipLifecycle 变为 true 的关闭场景；不把后补用例描述为最初先行测试。

独立只读复核发现 Started 后拒绝沿用了开始前拒绝的零耗时，违反本批生命周期起算点。新增前/后台两个时钟断言，初稿 11 通过、2 失败（0 不等于 125 毫秒），随后只在已发布 Started 的拒绝路径计算实际经过时间。当前新增 **34/34 合同通过**；初始拒绝仍保持零耗时。

独立复核再次用内存探针确认新拒绝前/后台均为 125 毫秒、初始拒绝为 0，原身份和 callback=0 保持；另对七类等待/异常、三类动态 signal，以及 thenable、同步取消、微任务取消后迟到成功、异步拒绝四类租约场景，与固定旧版的轨迹、监听解绑、接收对象和结果一致。此为只读有限复核，不代替完整回归和来源审查。

两次严格类型检查分别发现驱动局部 value 未初始化、ES2023 类型库不提供 Promise.withResolvers；已初始化返回值并改用普通 Promise 结算端口，不放宽类型目标。定向类型修正后通过。首次关联回归 91/91 通过；最终新增用例和完整回归见后文。

固定基线源码有限对照 **3,780 个 Runner 场景 + 231 helper 场景** 一致：七事件、前/后台、allow/deny/skip、可见性、九种输出/异常及五种发布路径。分别核对原输入/描述符/updatedInput 引用、接收对象、事件字段与键顺序、错误和警告；准入调用从 6,300 增至 7,308 属新增第三次检查，逐例断言其次数而非忽略。此枚举不覆盖任意 Proxy、原型篡改、外部设备或所有客户端时序。
