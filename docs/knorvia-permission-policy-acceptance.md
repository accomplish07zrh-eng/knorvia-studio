# 权限策略独立实现验收

本批按 `specs/knorvia-permission-policy.md` 执行。基线为 `24a3302`，范围仅是模式/授权优先级、能力默认值解析与 Service 会话规则访问。旧策略分支实现及 plan-mode-policy 已从源码移除；不保留运行时 fallback。

## 实现与来源边界

Service 拥有唯一的临时会话授权状态及原配置引用；不可变规则记录表达条件、结果类别、规则号和解释；惰性程序选取交互、强制确认或普通路线，统一投影命中的决定。能力解析采用模块级名称索引和逐字段优先级，不再为每次检查构造工具集合。

本批复核四份实现：permission/service.ts、capability.ts、policy-program.ts、policy-evaluation.ts；五份新测试/夹具、规格和本文另按新编写材料复核。已访问原源码，不作无接触声明；公共接口、规定的优先级、工具名、结果字段、固定解释与标准集合/迭代操作不声称为发明。表驱动、拆分、改名和测试通过都不能单独证明独立，逐文件依据绑定最终摘要。

项目规则匹配、规则更新合并、workflow-drafts 路径、WebFetch 预批准、公共类型、运行时能力解析、Hook/memory 覆盖及授权持久化仍使用各自适用许可，不能根据本批的调用关系推定整个权限模块已成为 MIT。根 Apache-2.0、版本和既有发行记录保持不变。

## 先行与复核证据

- 原实现的 20 项先行合同全部通过，覆盖能力默认值、显式 false、完整结果、五种模式与 plan overlay、硬拒绝、仅本次批准、配置变更、工作流归属、草稿/WebFetch 和可信 CUA 规则作用域。
- 首版迁移对原 context 的 planEnabled 重读造成单次决定漂移；新增回归先失败，再在普通路线进入时捕获本次事实。下次调用仍读取最新状态。
- 只读复核发现项目规则回调通过公共 grantSessionPermission 同步增加授权后，入口抓取的旧 ruleset 引用不能看到更新。固定基线反例为旧版同次返回 session allow、首版只能下一次允许；已补入独立比较及先失败再修复的永久回归。现在通过 readSessionRules 在相同 Service owner 上惰性读取，同次授权立即生效；allowAlways:false 仍禁止复用。只读复核确认修复覆盖原反例。真实生产 Bash 策略回调仅做匹配，未复现桌面用户故障。
- 固定基线先完成 55,261 组有限源码/编译入口对照，比较完整结果、风险、原异常和自定义策略回调轨迹；上述新发现的重入边界在扩展对照中明确失败，没有用已有总数掩盖它。修复后源码对照扩展为 55,262 组，全部一致；专项含 22 项新合同和 12 项真实 CUA 权限集成，共 34/34 通过。有限对照不证明任意 getter/Proxy、私有属性篡改或全部真实客户端场景等价。

## 验证中的实际失败

独立测试类型检查最初使用 ES2022，无法识别邻接共享代码已有的 findLastIndex；改用与实际 Node 能力相符的 ES2023 后通过，未修改产品类型。首次严格 lint 沿根配置跳过 CLI，明确返回没有文件；使用原规则且无 ignorePatterns 的专项配置后，九份源码/测试实际检查为 0 警告/0 错误。

仓库外对照器首次用裸 Windows 路径指定 ESM loader，启动失败；改用工作区 tsx 加载器后执行。编译 source map 会移除普通注释，首次产物检查将缺少 SPDX 注释误当为代码未更新；应以真正执行的公开入口、新模块路径与发出代码验证，源码许可由逐文件记录核对。没有将这些工具/夹具失败记作产品验证通过。

架构上下文首次误传源码路径而非模块 ID，返回未知模块；改用 cli 后确认为现有 unmanaged CLI。基线新鲜度检查与原架构门槛通过。旧 helper 的三个遗留、Git 忽略的 dist 产物已在逐个确认路径后移除；这一步只删除已失去源码的编译产物，不涉及其他源码、用户数据或缓存。
