## 先行原生调查

旧 `session-target.ts` 457 行，SHA-256 `fe71035659f3c097028b5c65aa5a17ba7edeb33ccf8334ee1578c9c137181c28`。最初三个真实当前 schema 的新内存库调查中，set/clear 的目标写入已经完成，随后 session touch 的原生触发器 RAISE(ABORT) 抛出 SQLite 1811，但目标变化留存；调用者先开始事务的第三个对照则保留该事务，调用者回滚恢复全部前态。主代理独立核对完整行、错误、事务与关闭状态；原始 JSON 摘要 `d43c0475606852748429f333381ab43059824edd67f2351cdfcd45dfa3290167`。调查后的 PowerShell 摘要处理曾误用内置变量报错，原始原生记录完整，后续仅重新解析，没有重跑原生取代首次结果。

据此先批准复用既有 borrow 事务 owner，使无外层事务的目标写、touch、读回构成同一原子单元；已有事务由调用者负责。finish/recover 在可能写入时进入事务并重读，再计算和 CAS；无写早退仍不新开事务。锁内重读首先来自静态风险分析，后续受控同连接交错不能冒称多连接并发实证。

主代理另外运行两组旧版公开 Store 原生观察：NaN/null 显式状态三场景，记录摘要 `35fa44b868ff2f0b0244d079cfc99def77e1befb9eb1081c82ed72febfc2fd90`；source 继承属性与应忽略活动访问器两场景。全部使用独立新内存库并关闭。前者确认 SQLite 空值绑定仍走预算/保留状态分支，后者确认分叉按需要的结构属性访问，未读取要清空的活动字段。这些补充先写规格再进入候选验收，不代表产品支持非法状态或真实用户曾传入访问器。
