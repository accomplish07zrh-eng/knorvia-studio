# Hook 输出投影与累积验收

本批以 `c8ac97a` 为固定基线，按先行 `specs/knorvia-hook-output-reduction.md` 替换原 output.ts。事件能力表与有序字段程序解释输出；累积规则单独描述追加、粘性标志、非 undefined 替换和权限决定/理由的优先级。matcher 用字符分类选择精确集合或正则。唯一结果仍由原 Runner 每次运行持有，没有第二套审批队列、结果缓存或旧实现 fallback。

## 有意修复与兼容

- 真实 Runner 的合法 structured deny 不再被后续 allow/modify 覆盖；后续回调、上下文与生命周期仍按登记顺序执行。同级 deny 仍取最后完整对象和原引用，不继承前条 message。
- Pre 的理由随获胜 deny/ask/allow 决定选择。弱决定不污染强决定，更强决定缺理由时清掉旧弱理由，同级缺席保留同级理由、显式空串有效。legacy stop/block 与 specific 弱决定冲突时用停止理由；顶层 continue:false 与 approve 矛盾时也归一为 deny。后者旧版已由 preventContinuation 拒绝，不描述为新增执行阻断。
- 保留七事件的控制区别、Stop 反馈、上下文原序与重复、输入引用/null、自有 undefined 停止覆盖、matcher 和可恢复错事件错误。后台输出不解析/合并；前条改写不作为后条输入；并发 run 隔离；终态发布失败不回滚已合并结果。

合法 PermissionRequest legacy 拒绝同时产生 preventContinuation。独立只读复核的 121 个混用组合中，85 个含停止标志均拒绝，4 个旧放行均属本批 structured 覆盖缺陷；另五个真实 Runner 代表场景一致。直接自定义 HookRunner 返回 legacy deny + structured allow、却不带停止标志，既有 adapter 仍按 structured 优先，本批未扩大改变该扩展接口。

## 先行失败及修正

25 项合同先在固定旧源码执行，17 通过、8 失败；失败对应结构化拒绝覆盖、理由污染/缺席/空串及真实工具入口错误解释。替换后全部通过。

只读复核另发现三处迁移访问边界：specific 事件名多读一次可使合法回调访问器抛错，从而将拒绝变为失败且丢弃结果；structured presence/value 从两读变一读；reason 回调晚于 behavior 捕获。三项新增测试先失败，再恢复入口核验与分派共两读、原 presence/value 分开读取、reason 先于行为选择。后两项仅 direct-helper 可达，普通 Runner 投影为普通属性，未扩大成真实桌面故障。

进一步补齐两个 direct-helper 边界：行为第二读消失时保留已读理由、理由第二读消失时保留自有 undefined。均先失败再修正。独立复核确认两例结果与字段顺序一致，81 个普通强弱/理由组合再次通过；还确认原真实 Runner 访问器反例恢复 started→blocked。最终新增 **31 项合同**，含相关适配/执行测试 **69/69 通过**。有限证据不证明任意 Proxy、原型篡改或所有真实客户端时序等价。
