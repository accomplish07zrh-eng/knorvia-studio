## 真实问题与兼容范围

自有 resolver 同步取消 caller 后返回一个拒绝 Promise，旧实现第二次取消检查会提前离开而没有观察该 Promise，产生未处理拒绝。新实现先承担已取得 Promise 的拒绝观察责任，再按原顺序决定取消，既不等待落败 resolver，也不改变同步 throw、已取消或 IP literal 的优先级。普通 pending DNS 的取消监听旧版原本就能移除，没有将其误记为修复。

主代理另运行七项边界观察，确认真正查询的是 lookup 的运行参数 hostname，工厂 URL 只作错误上下文；没有 callback 时不解析 URL；有 callback 的无效 URL 同步失败，其他 resolver/策略错误异步交付。保留原数组、条目、family 和错误身份，不筛选或重新排序地址，不扩大公网允许范围。
