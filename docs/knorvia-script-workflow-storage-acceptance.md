# 脚本工作流存储验收

2026-09-28，基线 `947b126`。按[先行规格](../specs/knorvia-script-workflow-storage.md)替换定义/运行、活动/事件/任务链接及记录投影三个模块。SQLite 为唯一持久状态；十二个 Promise 入口、五种记录、现有 schema、执行器和界面保持。来源判断及其限制见[来源记录](../licensing/evidence/script-workflow-storage.md)。

## 实际行为

七个写入口复用已有同步事务 helper 的 borrow 策略。没有外层事务时，从当前值/编号读取到写入、完整回读及解码一起提交；已有外层事务时不替调用者提交或清理。修复同轮不同字段更新丢失及自有写入在回读失败后遗留数据的问题。自动回滚保留原始错误，清理双失败保留两项错误与首因。

创建类入口在事务前取时钟；更新在事务内读到完整当前值、通过缺失检查后才取时钟。保留 JSON 原始/重编码范围、null/undefined、返回 own keys/顺序、精确作用域、原生约束、事件最新尾部顺序、缓存选择及 task-link 按 child 冲突时只改状态/更新时间的规则。DWF actor 的任务链接仍省略指向 legacy run 的外键。

运行时 `addRunStats` 的先读后计算绝对累计值、动态 journal、schema、facade 的其他事务及执行状态规则不在本批，不能由本次同步补丁宣称全部并发问题已解决。

## 先行失败与修正

- 旧版主代理 53 项：34 通过、19 预期失败；加复核者 25 项兼容测试，最终旧版 **78 项：59 通过、19 预期失败、0 跳过**。19 项分别为两条同轮丢字段、七种写入的回读原子性、七种真正延迟 COMMIT、清理双错误、准入失败和时钟/事务顺序。旧版本来能保留自动回滚首因，未将该情况错记为旧版缺陷。
- 初稿接入 **78/78**。有限对照另发现 SQLite 非 STRICT INTEGER 列可存 TEXT，初稿的 JS 最大值加一把 `not-numeric` / `12cats` 拼接成字符串，旧行为应为数字 1 / 13。补两条原生回归后相关两文件 **18 通过、2 失败**，作者按行为反馈改成数据库原生运算；最终新增 **80/80** 通过。
- 七个写入口分别验证外层成功/ABORT 不主动提交清理、自有回读失败全回滚、原生 RAISE(ROLLBACK) 首因、真正延迟外键 COMMIT 失败。另验双重清理错误、BEGIN 失败无清理、借用回读失败交还原 owner、同字段绝对值以后次为准。触发器自己的自动回滚不能误说成仓储保留了外层事务。
- 复核者 cache 初跑因未声明 ESM 导致三文件加载失败；仅补外部 package.json 后 25/25。主代理严格类型首轮发现一个 SQLite 原始行夹具断言缺少 `unknown` 中间转换，已修正夹具，规则未放宽。原始失败日志均保留。
