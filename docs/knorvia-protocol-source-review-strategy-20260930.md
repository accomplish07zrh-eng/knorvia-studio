# 协议/shared 来源闭合策略

2026-09-30。本说明给父任务复核使用，不编辑来源决定或授予许可。工程验收、来源关系、
有权授权的范围、分发义务和产品迁移目标分别记录；测试通过不能代替任何一个来源决定。

## 前两组新增 MIT 来源结论为何为零

六个文件的原实现均已阅读，不能声称 clean-room。阅读本身也不自动证明侵权、派生或永远
不能独立：需要审查具体表达、设计生成记录和权利范围。当前证据完成的是字段/故障/调用者
兼容、独立测试 oracle 与 before/after 指纹，还没有接受的逐文件来源审查或贡献授权记录。
用户禁止本轨修改 shared ledger，故这里提供审查包，实际资格由父任务来源工作流决定。

## 可执行的闭合路径

1. 父任务固定候选 SHA/逐文件 hash；复核者读取本轨规格、冻结记录、消费者证据和实现生成
   记录，并比较具体旧/新表达。复核者可与实现者分开，但这不是虚构未接触源的历史。
2. 对每个文件列片段表：接口/字段/标准算法约束、保留上游或第三方文字/代码、独立设计新增
   表达、不确定片段。区分功能与表达可参考美国版权局对程序的说明，但其美国法范围不替代
   项目适用法和逐片段判断。[US Copyright Office Circular 61](https://www.copyright.gov/circs/circ61.pdf)
3. 对可证明的自有增量确认贡献者及可授权权利范围，包括适用的雇佣/委托/贡献安排；不能仅
   依赖 Git 作者、AI 生成标记或父任务授权代替真实权利依据。没有此依据时继续保留原许可，
   不擅自添加 Copyright/MIT 所有权声明。
4. 审查结果可分别为：有证据的独立替换；保留派生/混合 Apache 表达；未知来源继续待审。
   每个结论绑定路径、hash、basis、evidence，按现有 ledger 规则由父任务接受。任何表达变化
   使 hash 失效后重审；分发义务另随 source/dist/bundle/第三方依赖和 NOTICE 核对。
5. 对未证明独立的必要片段，选择保留并履行其原许可，或按真实独立设计进一步替换并复核。
   替换必须带来明确设计/可靠性/性能价值，不能反复改写只求差异量。工程合格但来源待审的
   候选可以继续用于受 Apache 约束的过渡版本，不能据此宣称全仓 MIT 或迁移完毕。

需要权利人确认的场景是：具体材料缺可靠授权/署名来源、贡献者是否有权授权不明，或希望
对保留的受保护上游表达移除现有义务并作 MIT-only 决定。已有有效 Apache 授权、按其条款
使用/修改/分发时，并不因混合 MIT 而一律需要另索许可。Apache 第4条允许为自有修改或派生
整体附加不同条款，同时保留其列明的原许可、修改声明和适用署名/NOTICE义务；这不能证明
整个文件都是新作者独立表达。[Apache License 2.0 §4](https://www.apache.org/licenses/LICENSE-2.0)

没有确认就不移除义务、不联系权利人、不生成同意记录。27 项现有 unresolved material
obligations 仍按其历史证据逐项推进；不把本轨三组的通过数用于冲销它们。

## 可以保留 Apache 共存的范围

本仓现有 [第三方 inventory](../third-party/inventory.json) 已记录具体可保留候选：
TypeScript 6.0.2 的 LICENSE.txt；playwright-core 1.59.1 的 LICENSE/NOTICE；ECharts 6.1.0
的 LICENSE/NOTICE 与单独 D3 声明；pdfjs-dist 5.4.296 的 Apache LICENSE 及字体、CMap、
ICC、WASM 子材料的各自声明。四者不在 inventory 的 exceptions 中。它们是通用第三方
依赖，可按有效版本许可及实际分发范围核对后保留，不必为了将自有模块许可定为 MIT 重写。
子材料不因顶层 Apache 标签自动变成 Apache；仍需保留其对应声明。本说明没有重新认证
全部发布者材料或整个安装包的依赖闭包。

| 范围                                                                | 共存处理                                                                              | 与用户迁移目标的关系                                                                  |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 版本/来源明确的 Apache 第三方库、运行时或单独依赖                   | 保留原 license/copyright/NOTICE，记录实际分发范围及修改说明；自有 MIT 模块可链接/组合 | 规格允许通用第三方依赖，通常不为“改成 MIT”重写                                        |
| 协议公开 schema、声明、注释或必要保留实现，确认来自有效 Apache 授权 | 可以继续按 Apache 使用/修改/分发；必要时按文件/片段明确混合来源及义务                 | ZCode 派生产品实现即使可合法共存，仍不自动满足用户“无未替换 ZCode 实现”的最终工程目标 |
| Apache 正文、NOTICE 和准确来源记录                                  | 原样保留，按标准许可文本/来源性质复核                                                 | 不把许可正文算成待重写产品逻辑；不能删除归属来改变来源                                |
| 声明缺失、授权链不明或27项未决材料                                  | 继续待审，补发布者版本/原始声明/授权证据                                              | 不能仅因目录或根 Apache LICENSE 推定已经合法闭合                                      |

MIT 授权本身也要求保留相应版权和许可文本；不同许可证的组合不意味着一份根 LICENSE
消灭其他部分义务。[MIT 原文](https://opensource.org/license/mit)
ASF FAQ 明确指出修改 Apache 代码仍需履行其许可，换掉全部代码行也不是去来源证据。
[Apache FAQ：改进与分发](https://www.apache.org/foundation/license-faq.html)

来源复核或必要的权利人/法律确认。本组不会修改根许可、前两组证据、共享 ledger 或发布材料。
