# 输入历史持久存储验收

基线 `15c993f`。按[先行合同](../specs/knorvia-input-history-storage.md)隔离替换输入历史记录与回忆入口。SQLite 是唯一持久状态：同步只读预检保留空操作，自有写事务内重新读取和去重后才能插入及全局裁剪，使用既有事务 helper。保留附件投影、ID/时间、全局 100 条上限及外层事务边界；不修改 schema、facade 或前端。

## 先行证据

初始 40 项在旧目标上为 **33 通过、7 预期失败**。只读复核确认阶段和断言有效，并指出应覆盖第二连接在预检后提交坏附件 JSON；新增该测试仍在旧目标上先运行，最终 **41 项：33 通过、8 预期失败**，0 跳过。失败覆盖同事件轮次重复、同步完成、锁内最终读取、两连接重复/损坏 JSON 间隙，以及插入/裁剪自动回滚掩盖首因和清理双失败。不是八个独立产品缺陷。

兼容合同覆盖输入 trim/空操作、四种附件与小写 data: 过滤、原始字段存在性、JSON 错误、项目隔离、仅最近一项去重、ID 与创建时间独立、原生 skip、全局排序裁剪和触发器改写不影响本次返回。显式运行时 sessionID:null 在 record 返回保留 null、SQL 为 NULL、recall 为 undefined，单独核对；不把此有限兼容扩大为任意 getter/Proxy 访问次数相等。

原生 SQLite 的触发器、延迟外键和 authorizer 验证真实 INSERT/DELETE/COMMIT 与锁阶段；双连接使用新建临时文件，在预检后的 UUID 分配回调内真实提交对方记录。该受控时序不代表跨进程压力。已有外层事务的空、重复及解码失败不收尾，真正新写入仍由原生 BEGIN 拒绝；不悄悄变成借用成功。
