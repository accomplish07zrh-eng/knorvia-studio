## 2. 两道门槛的算法与取值

**行相似度**（与记账同一算法，`similarity.mjs`）：

- 规范化：去首尾空白、丢弃空行、丢弃只含 `{ } ( ) [ ] ; ,` 的行、丢弃以 `import `、`export * from`、`export {` 开头的行；注释保留。
- 只与同类文件比较：`ts/tsx/js/jsx/mjs/cjs/mts/cts` 归一组（`js-family`），其余按扩展名各自一组。
- 包含率：候选的每一行取包含它的上游文件，得到该上游文件包含的候选行数，除以候选规范化行数，取最大值。
- 最长相同段：只从「前一位置不相同的极大对齐起点」向后延伸，避免把错位的重复行拼成假长段；取全部同组比较文件的最大值。
- 门槛：规范化行数 ≥ 10 时，包含率 < 0.2 且最长相同段 < 8；规范化行数 < 10 时包含率必须为 0。
- 纯声明文件：先按 `interface.md` 列出的名字剔除兼容行，再套上面的门槛。

**结构相似度**（专抓改名照搬与逐行翻写）：

- 词法单位取自 TypeScript AST 的叶子节点。标识符（含 `#private`）统一换成同一占位符；字符串、数字、大整数、正则各自统一占位；模板表达式与无替换模板整体合成一个占位符；注释与 import/export 声明不进入序列。
- winnowing：每 25 个 token 一个哈希，窗口 20 取最小哈希（并列取最右）；指纹集合即比较单位。
- 指标：新文件指纹落在同一个比较文件里的比例，取最大值。
- 门槛：`STRUCTURAL_LIMIT = 0.4`，写在工具常量里，校准后不再调整。
- 不足一个 k-gram（25 token）的文件不产生指纹，指标为 0，结构门槛对这类文件不可判定；它们只能靠行门槛把关，报告里按 `tokens` 与 `fingerprints` 字段如实体现。

### 关于 0.4 这个取值

计划书要求「取能让 439 个已登记文件全部通过的最小值，向上取到 0.05 的整数倍；高于 0.4 时取 0.4，把超过 0.4 的历史文件列入替换队列」。

本轮实测：439 个文件里最大值是 1.00，因此「全部通过的最小值」为 1.05，按规则截到上限 **0.4**。同时确认 0.4 就是工具校准前的常量值，两者一致，不需要改动工具常量。超过 0.4 的 5 个历史文件见第 4 节，按计划书列入替换队列（本任务不改来源登记，交还计划所有者处理）。

**取 0.4 的把握度验证**（第 5 节）：用 2,286 个 upstream-modified 的 JS 系文件做「只改名的副本」，0.4 把其中 2,246 个全部拦下（检出率 100%，可判定范围内 0 漏网）。这同时说明 0.4 不会松到放过改名照搬。

## 6. 复现命令

```text
node scripts/provenance/similarity-calibrate.mjs \
  --repo <主仓检出> \
  --upstream-repo D:/tools.cache/knorvia-provenance/upstream.git \
  --out calibration.json
```

输出 JSON 结构：`limits`、`upstreamCommit`、`registered`（路数、分桶、超门槛清单、逐文件行）、`renamedCopies`（候选数、拦下、漏网、不可判定）。

判定单个包时用：

```text
node scripts/provenance/similarity.mjs --targets <manifest.json> \
  --repo <主仓检出> --old-commit <被替换文件所在提交> \
  --upstream-repo D:/tools.cache/knorvia-provenance/upstream.git
```

`manifest.json` 每项写 `{ path, replaced: [被替换的旧文件], compatNames: [interface.md 列出的名字] }`；退出码 0 表示全部目标两道门槛都过。

## 7. 校准过程中工具自身的三处修正

写测试与校准期间发现并修掉了三处会让门槛失真的问题，都补了回归测试：

1. **模板字面量吞掉后续 token**。原先用 `ts.createScanner` 一次顺序扫描，在模板占位符处扫描器切换状态，把模板后面的 `;` 一起吃掉（实测 ``return `a${value}b`;`` → `["return","TPL"]`，丢掉 `;`）。改为遍历 AST 叶子节点取词法单位，模板整体合成一个 `TPL`，注释与 import 天然不进序列。
2. **关键词被当成标识符改写**。校准用的「改名副本」生成器把 `declare` 之类以 Identifier 形态出现的字面量关键词也改了，等于改结构，会把改名照搬误判成独立写法（`globals.d.ts` 因此得 0 分）。改成只改真标识符，改名副本的指纹与原版一致（测试断言相似度为 1）。
3. **声明剔除的对照用例把语料按未规范化行建索引**。生产路径 `createCorpusBuilder` 先规范化再建索引，测试却用原始行建索引，等于测了另一套语义。改为两侧都先规范化，并补上「全部名字剔除后候选为空 → 包含率 0」「只剔除一部分 → 仍超标」两条断言。

另外把「目标文件不存在」与「目标文件读取失败」在报告里分成两条不同的错误信息，避免未登记的新文件看起来像权限问题。第一版单文件 609 行超出 `.oxlintrc.json` 的 `max-lines` 400 上限，按第 9 节拆成四个模块（`pnpm lint` 的 `max-lines` 与 `no-useless-escape` 两条已消除）。

工具文件本身也要过这两道门槛，因此还改了一处**行门槛超标**：拆分后的 `similarity-text.mjs` 行包含率 0.2941（最长段 7），超过 0.2。命中的全部是通用控制流行——`if (`、`) {`、`try {`、`} catch {`、`return null;`、`continue;` 之类，与上游 `apps/zcode-cli/packages/adapters/src/{commands/index.ts,exec/outputEncoding.ts}` 逐行相同但没有代码复用。处理办法是按计划书「改写到过门槛为止」重写该文件：把 7 个并列条件的 `if` 改成「谓词返回不合格说明」的 `relativePathProblem`，把 import/re-export 判断提成 `isImportOrReexport`，把 `decodeText` 的 `try` 改成先声明再赋值。重写后行包含率 0.1017、最长段 2，两道门槛都过。同一次重写用同一份语料复算过校准：439 个文件的分桶、超门槛清单、逐文件指标与 2,286 个改名副本的检出结果全部逐字节一致。

## 8. 未覆盖与已知限制

- 不可判定文件：token < 25 的文件结构门槛给不出指标（第 5 节 40 个）。这是计划书固定参数的直接结果，不通过调低 k-gram 规避。
- 结构门槛对**纯数据清单文件**会产生假阳性，与代码复用无关。实测例：`scripts/studio-test-manifest.mjs`（15 个测试目录 + 43 个显式测试文件的字符串数组，130 个 token）结构相似度 0.6667，对应上游 `apps/zcode-cli/packages/core/src/tool/handlers/amend-workflow-description.ts`。两份文件的 token 序列同形：
  - 候选：`["export","const","ID","=","[","STR",",","STR",...]`
  - 上游：同一形态
    原因是标识符与字面量都被替换成同一占位符后，「字符串数组」退化成一个与内容无关的重复形态，任何字符串数组都会互相命中同一批 25-gram 指纹。行门槛同时为 0（无对应上游文件），即没有代码复用证据。
    这类文件的正确处理是**知情登记并记录假阳性**，不是为过门禁把数据改写成对象键或模板字符串（那属于劣化设计）。是否要给纯数据文件单独判定由计划所有者裁定；本任务不改门槛，也不改校准值。
    注意：把清单换成 JSON 文件**不能**规避该现象——工具对非 JS 扩展名默认按 TS 解析，JSON 的 `[ "a", "b" ]` 同样退化成 `[ STR , STR ]` 形态。
- 非 JS 系文件（JSON、Markdown、CSS 等）同样进入结构门槛（`tokenSequence` 对未知扩展名默认 `ts.ScriptKind.TS`），只是得分通常为 0。计划书未要求为非 JS 文件定义单独的结构判定。
- 结构门槛不分扩展名分组，全语料共用一个指纹索引；行门槛按扩展名分组。计划书对结构门槛未规定分组，此处按「落在同一个比较文件里的比例」的原义实现。
- 上游树需在仓库外缓存目录准备（`git clone --bare` + `git fetch` 到固定提交）。工具不联网、不自带上游树。

## 9. 模块划分

工具按职责拆成四个文件，每个都在 400 行上限内（`.oxlintrc.json` 的 `max-lines`）：

| 文件                       | 职责                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| `similarity-text.mjs`      | 门槛常量、路径校验、二进制判定、行规范化、扩展名分组              |
| `similarity-lines.mjs`     | 行索引与包含率 / 最长相同段                                       |
| `similarity-structure.mjs` | token 序列、winnowing 指纹、结构相似度                            |
| `similarity.mjs`           | 语料装配、git 读取、目标评估、CLI（对上面三个模块再导出公开 API） |
| `similarity-calibrate.mjs` | 校准驱动（本报告的第 3、5 节）                                    |

拆分前后用同一份语料复算过：439 个文件的分桶、超门槛清单、逐文件指标，以及 2,286 个改名副本的检出结果全部逐字节一致，拆分未改变任何判定。
