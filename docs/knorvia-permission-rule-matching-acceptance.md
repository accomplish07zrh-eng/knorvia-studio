# 权限规则独立实现验收

本批按 `specs/knorvia-permission-rule-matching.md`，以 `549dc57` 为固定基线。范围是项目规则匹配、内容模式程序、通配/域名主题及有序授权合并；原实现不保留为运行时 fallback。

## 设计与许可边界

候选范围完整筛选后交给自定义端口或默认内容程序。默认程序按命令前缀、普通通配、字面量、WebFetch 精确 URL 分类执行；空内容先短路，不读取输入。通配编译按字符生成转义表达式。规则合并先快照两批输入，以工具名及内容分层记录身份，保留每类首次引用和顺序，结果仍由原 Service/store 持有。

四份实现共 202 行，较旧三份 170 行增加 32 行，最大文件 90 行。已访问原源码，不作无接触声明；独立依据限于新内容程序、字符编译和二元身份合并设计及本批复核，不以拆分、改名或测试通过本身证明独立。公共签名、规定的工具名、模式语法、字段顺序、读取边界和标准字符串/集合操作是兼容约束，不能声称为 Knorvia 的独创语义。

四份实现、四份新测试、规格和本文按具体文件摘要记录 MIT。建议生成、协议批准选项、Bash 专用策略、WebFetch 预批准清单、网络执行、安全检查、路径判定、公共类型、存储及相邻 UI 继续保留适用许可，不能因本批调用而被一并列为独立。根 Apache-2.0、当前预览版本及既有发行保持不变。

## 有意修正的行为

- 实际默认建议 → 项目批准选项 → 规则合并 → Service 的原始 URL 授权原先不能闭合：保存完整 URL，匹配却只看域名。现在仅原始 URL 全串相等时复用。路径、查询、片段、协议、端口、主机大小写、子域及空白变化均重新判定；URL 内星号也是字面量。原域名授权保持域名范围，非 URL 模式不会新增 URL 路径主题。
- 旧的 NUL 分隔身份会把不同工具/内容二元组当成同一条。按两层身份集合合并后两条均保留，缺席内容与空串仍等价。这是公共字符串合同反例，未宣称真实桌面出现过此故障。

本批不改变网络协议、地址、认证或重定向检查；许可匹配不是出站安全许可，也不代表请求必然成功。没有用网络请求验证规则。

## 先行测试与复核

初始 21 项测试为 16 通过、5 失败；其中一项错误期待无 flags 的 JavaScript 尾锚正则接受末尾换行。Node 24 与原实现均拒绝，已修正夹具并覆盖五种换行结尾。修正后的旧版基线为 17 通过、4 项预期失败，分别覆盖 NUL 与三项精确 URL 行为。首版实现 21/21 通过。

只读复核发现首版迁移的五项边界差异，均另补先失败再修正的永久测试：缺失名称不能命中不存在的别名；前条 getter 改变后条工具范围后必须重查；输入 getter 改变当前内容后使用最新内容；已有数组须在读取新增数组前快照；条目 getter 不能向当前新增快照追加规则。再次复核发现新增规则 getter 可改写更新类别；另补一项先失败回归，在回调前捕获目标类别后通过。最终本批 27/27 通过。自定义回调 receiver、原异常、候选引用/顺序及 false 不回退合同保留，不声称任意 Proxy 或原型修改等价。

固定基线有限对照包含 386,468 项相同结果、180 项仅精确 URL 的有意差异、3 项仅 NUL 二元组的有意差异，以及 1,305 项公共 Service 调用；比较通配表达式/flags、域名、匹配范围、更新值/字段顺序/对象引用/输入不变性。只读复核另确认 167 项 URL、域名和通配断言及 NUL 身份顺序。有限检查不等于全输入或全部真实客户端验证。

## 工具与夹具失败

首次独立测试类型检查有一个只抛异常的 getter 被推断为 void，已明确标注 string 后通过，未放宽类型规则。首次扩展权限测试遗漏 Node 的模块 mock 开关，104 项通过，tool-display-permission 文件以 mock.module 不存在失败；这次运行不是全通过，最终使用统一离线入口的正确开关验收。仓库外对照器首次把共享包路径写到 CLI 子目录，启动失败；改为实际根共享包后执行，没有修改产品路径。首次编译冒烟把 WebFetch 名称默认值当成实际工具声明，负例预期因此错误；改用编译后的真实 WebFetch entry 权限记录后 17 项通过，未更改产品策略。
