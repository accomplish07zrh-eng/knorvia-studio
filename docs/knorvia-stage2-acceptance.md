## T2.1 群聊任务进展与统计

群聊页在最近一次任务模式运行中展示可折叠进展区。当前计划轮次、成员派发状态、主持人复核结论及工作目录变更摘要均从 Studio Runtime 的持久快照读取；证据入口指向现有运行历史的逐文件审阅。依赖失败的任务显示未派发，取消中与结果未知分别呈现。补充说明重排后以已保存的新计划为准，不从成员文字推断完成。

输入卡下方显示最近一次群运行每位成员与合计的已上报 Token、成员 turn 耗时之和。每个 turn 持久保存成员和起止时间，重启后仍可读取；同一 turn 的重复用量更新不会重复相加。缺失用量、旧 turn 无时间戳、请求范围用量与超过最近 2000 个 turn 的运行标记为部分数据，未知显示 `—`。

## T2.2 群聊与工作流差异审阅

运行历史的逐文件审阅改用原 GUI 的 `DiffViewer`，展开文件时才挂载文字差异视图。新增与删除文件用空侧呈现真实增删；二进制或无法读取的文件明确说明没有文字预览，不把其内容显示成空文件。每个文件独立应用。若源文件在隔离后偏离原始版本与成员版本，审阅卡说明冲突并禁用应用；预览后源文件再变更时，Host 应用前的重新校验仍会拒绝覆盖并将错误留在弹窗中。目标路径只取自 Host 返回的相对路径。

## T2.3 工作流模板、计划触发与运行对比

已加入发版前检查、代码审查、文档整理三个可编辑的内置模板，中英文节点指令分别生成；模板不会在创建时启动模型。工作流原有运行历史中可折叠对比两次运行，逐节点读取各自保存的定义与结果；新增、删除、无记录、损坏记录与长输出截断均明确显示。

工作流编辑器现可创建每日计划，主侧栏“自动化”负责暂停、编辑、立即运行与历史，计划卡明确标注 Studio 工作流。定义保留工作流 ID 与项目归属；既有调度器把固定运行编号交给 Host，Host 在读取已保存定义并核对项目、图有效性后交给 Studio Runtime。重复派发取得同一运行，不会落入普通聊天。运行结果及中断状态回写自动化历史；Host 重启时重新观察未完成的 Studio 运行，手动触发的占用锁在真实终态后释放。旧任务数据库通过独立的 0005 迁移加列，旧迁移校验和不变。
