输入卡下方显示最近一次群运行每位成员与合计的已上报 Token、成员 turn 耗时之和。每个 turn 持久保存成员和起止时间，重启后仍可读取；同一 turn 的重复用量更新不会重复相加。缺失用量、旧 turn 无时间戳、请求范围用量与超过最近 2000 个 turn 的运行标记为部分数据，未知显示 `—`。

## T2.3 工作流模板、计划触发与运行对比

已加入发版前检查、代码审查、文档整理三个可编辑的内置模板，中英文节点指令分别生成；模板不会在创建时启动模型。工作流原有运行历史中可折叠对比两次运行，逐节点读取各自保存的定义与结果；新增、删除、无记录、损坏记录与长输出截断均明确显示。

工作流编辑器现可创建每日计划，主侧栏“自动化”负责暂停、编辑、立即运行与历史，计划卡明确标注 Studio 工作流。定义保留工作流 ID 与项目归属；既有调度器把固定运行编号交给 Host，Host 在读取已保存定义并核对项目、图有效性后交给 Studio Runtime。重复派发取得同一运行，不会落入普通聊天。运行结果及中断状态回写自动化历史；Host 重启时重新观察未完成的 Studio 运行，手动触发的占用锁在真实终态后释放。旧任务数据库通过独立的 0005 迁移加列，旧迁移校验和不变。

## T2.4 显式接力与 Markdown 导出

原生 Knorvia 单聊与 Studio 外部单聊均可打开可编辑的本地接力摘要。草稿仅取当前已加载的最近 24 条可见用户/助手正文及工具名称、状态；原生 V4 合成用户行、推理和工具原始输入输出不进入草稿。用户确认前不会创建目标会话或发送。外部目标继续由 Studio Runtime 创建独立会话并首发，两个固定命令 ID 支持同一尝试重试。外部会话现在也可选择原生 Knorvia：确认后经现有 V4 transport 握手，提交一条固定 ID 的 `createSession(firstInput)` 命令，只有收到带真实原生 session ID 的 accepted/duplicate ACK 才切到原生聊天。它不会创建 Studio Runtime 的同名内核会话；旧会话不删除，私有记忆不复制。

两类单聊均可导出完整持久历史为 Markdown。Studio 时间线和 V4 `rows/range` 分别逐页读取；原生导出遇到代际或修订变化会失败并提示重试，绝不把部分历史写成完整文件。导出仅含可见正文与工具名称、状态；凭据形态脱敏，文件名安全化，大小上限 8 MiB，记录上限 10,000。保存用平台文件对话框，取消保存不显示成功；Web 使用下载回退。弹窗的异步状态门禁阻止连点重复提交，来源或项目切换后的迟到回执也不会导航旧结果。

## T2.5 创作历史、重试与视频首尾帧

创作页的表单模式与历史筛选已分开：历史默认显示全部，可叠加按类型、模型和状态筛选；已删除模型仍以任务中保存的模型 ID 可见。只有明确失败的任务提供“按原参数重试”，Host 使用 `retry-<旧任务 ID>` 作为固定新请求编号，重启后重复点击仍返回同一新任务。原任务的提示词、模型和参考图都由 Host 私有记录恢复；读取前校验文件仍在本应用数据目录、大小及内容散列。取消、成功、运行中和结果未知的中断任务不开放一键重试。

视频模型仅在 JSON API 模板或 ComfyUI 工作流声明对应占位符时，显示首帧／尾帧入口。两张图分别做 MIME、大小与内容校验，分别保存私有文件；模型与任务公开响应不返回路径或原始字节。JSON API 填写各自的 base64／DataUrl，ComfyUI 各自上传后替换占位符。供应商明确 4xx 拒绝、协议失败或无效文件记为失败；提交后 5xx、网络丢失或超时保守记为中断并提示远端可能继续运行或计费。取消只停止本地等待，不把远端费用假定为零。

## T2.6 SSH 功能本地模拟验收

窗口 Host 的连接器用本地替身返回服务和关闭事件：覆盖 logical session 建立、项目路径与稳定工作区身份绑定、断线标为离线、同身份新连接接替及同路径异主机身份隔离。Studio 远端协议夹具覆盖已安装内核探测、未安装与陌生内核过滤、远端单聊目录绑定、本机与两台远端同类 CLI 的群任务分工和各自隔离目录。修正了一个探测边界：远端回报陌生内核 ID 时，保留同批有效的已安装内核，不让整个环境目录因映射异常消失。

停止夹具验证本机请求转发远端 `cancel`，并等到远端明确的取消终态才标为已知。发送后回执丢失的夹具将本机任务保留为结果未知；新发送和未经确认的继续被拒绝，断线时目录保持可见但显示离线，同一稳定身份重连后仅显式 `retryUncertain: true` 开始第二次尝试，派发 ID 随尝试变化。本轮没有让远端路径进入本机工作区准备、变更扫描或应用。

Node v24.14.0 下，本轮定向测试 5/5 通过；`pnpm typecheck` 通过；`pnpm lint` 0 警告、0 错误；`pnpm architecture:check --changed` 0 违规；`pnpm test:studio` 共 116 个离线测试文件、551/551 通过、0 失败。只验证窗口连接状态机与 Studio 协议替身；真实 ssh2 握手、认证、远端部署、跨设备、远端 CLI 与实际网络故障恢复均属“本轮不做远程测试，未验证”。按用户要求未做人工目视复核；便携版等待阶段末打包。
