# HTTP 响应字节读取验收

2026-09-29。按[先行合同](../specs/knorvia-http-response-body.md)独立替换响应读取 helper，保留一个四参数公开函数和原错误工厂。只处理已经取得的 Response；请求、DNS、代理、证书、timeout 分类、egress 策略与界面均未修改。

## 旧版行为与批准修复

主代理完整阅读旧 helper、公共错误声明与 HTTP adapter 调用边界，再以自有内存流观察三个问题：待决 read 不响应单独的 caller abort；声明超限拒绝后 producer 未取消；实际超限等候 producer 的取消 Promise，且 reader 锁遗留。观察只证明 helper 行为，不等于正常 HTTP transport 一定不会自行销毁流。

另运行十八项有限优先级观察，确认负上限、header、getReader、已取消、null-body 的原有次序及 NaN/无穷/数值前缀处理。合同据此明确：getReader 的外部锁失败仍优先于取消；null fallback 不扩展取消竞速；不新增数值校验或改写公网访问权限。

新实现使单次调用统一拥有 reader、积累块、监听和终态。取消与大小拒绝先选主错误，不等待 producer 的清理完成，随后释放自有锁并观察落败 Promise。成功与原生 read 失败也释放锁；清理错误不覆盖主错误，成功路径的释放错误则原样返回。他人 reader 不被接管。undefined 仍是可保留的原生失败值，不以它充当没有错误。
