# 消息与片段仓储验收

基线 `dbce9b6`。按 [先行规格](../specs/knorvia-message-storage.md) 和批准的公共类型隔离重建消息/片段六个存储入口，沿用 SQLite 唯一状态、现有 codec 和写事务边界。两个保存方法现在将复制来源读取、目标 upsert 与 touch 放在同一事务；已有事务只借用，不抢外层提交权。

## 先行合同与复核修正

旧版初始 27 项为 22 通过、5 失败；将延迟外键测试补充为实际 INSERT→COMMIT 阶段断言，并增加序列化/查询失败顺序合同后，最终先行 **29 项：22 通过、7 预期失败**。这不是七个独立产品缺陷：四项覆盖消息/片段的新建和更新 touch 失败残留，两项要求进入自有事务 COMMIT 才处理延迟约束，一项要求复制快照也在写事务中。

新实现接入前，已澄清单条读取须先完成片段 SQL 查询，再解码消息和片段。接入后只读复核发现普通 timeline 新字段插入顺序不同；新回归在该版 13 通过/1 失败，隔离作者仅按行为要求调整赋值顺序，再接入。复核另用真实公开存储确认：旧目标 legacy 全缺席时，多余 JSON1 解析拒绝原可保存的深层 metadata；两条 1,100 层普通对象回归先失败，再补全缺席时直存新文档的条件，保留既有 JSON1 分支规则。最终新增 **32 项**，加 entry/full-access/codec-store 相关组合 **56/56 通过**。

测试涵盖角色和模型投影、subtask/timeline、旧 snapshot 和现代字段清空、NULL sequence、创建时间/rowid、跨 scope 改绑、精确复制与目标优先、排序/删除/孤立片段、同步执行时点、序列化错误、借用事务、自动回滚和真实延迟外键。复制读取事务使用 SQLite authorizer 观察，不绑定某种 SQL 拼写。strict 测试类型首轮因 fixture 的 branded model ID 不匹配失败，改用公共品牌类型后通过，未修改生产接口以迁就测试。

## 来源和未覆盖范围

[来源记录](../licensing/evidence/message-storage.md) 逐项列明作者允许输入、主代理的旧源码接触以及三个文件的判断。普通 SQL、固定字段及通用事务不是独创算法依据；此批不是把原函数移到新文件再换许可证。相邻 sessions、facade、schema、迁移等仍保留原来源，根 Apache-2.0 与 0.8.0-preview.3 不改。
