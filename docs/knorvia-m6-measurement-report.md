## 三、可达标性判据

### 3.1 ⚠️ 下界公式（极易用错 —— 同一晚连错两次）

**正确**：`下界 = 契约行 / 归一化总行数`
**错误**：`契约行 / 命中行` —— 这是「命中内占比」，**不是下界**

**实例（`contracts/tools/node-repl.ts`）**：

```
归一化总行数 42 / 命中 24 / 契约面 8
→ 下界 = 8 / 42 = 0.190   ✅ 可达（< 0.20）
→ 误用 8 / 24 = 0.333     ❌ 会误判「不可达」
```

**同一晚在两个文件上连错两次**：

- `oauth-lease`：说「下界 0.5 附近」→ 实际 18/93 ≈ 0.19
- `node-repl`：说「下界 0.27」→ 实际 8/42 = 0.19

**两次都是把「命中行内占比」当成了「下界」。**

### 3.2 两个必须区分的比率

| 比率                        | 定义            | 用途               |
| --------------------------- | --------------- | ------------------ |
| ① 命中行内契约占比          | 契约行 / 命中行 | 判断「相似从哪来」 |
| ② **契约行 / 归一化总行数** | —               | **这才是下界**     |

**下界 = ②**。即使把所有可改写的实现行全部消除，比值仍不低于 ②。

### 3.3 判定表

|    ② 的值 | 判定           | 行动             |
| --------: | -------------- | ---------------- |
|    > 0.20 | **数学不可达** | 如实记录，不投入 |
| 0.10–0.20 | 边缘           | 谨慎评估         |
|    < 0.10 | 有空间         | 可投入           |

### 3.4 诊断步骤

```bash
node scripts/provenance/similarity.mjs --repo . --candidate <path> \
  --upstream-dir <上游树> --upstream-rev <rev> --gates line --explain

# 统计命中行里「契约面」行数：
#   契约面 = 以 export / interface / type / declare / } 开头
#          或「标识符?: 类型」形式的字段声明
# 下界 ≈ 契约行数 / 归一化总行数
```

## 九、技术债

### `licensing/current-files.json` 是单一共享文件 → 所有 PR 互相冲突

今晚至少 12 次 PR 因它 `CONFLICTING`。

**`merge=union` 不可行**：它是按行合并，而 JSON 数组每条目跨多行，
union 会产生重复条目；且 `reviews.json` 里同一 path 只能有一个决定，
union 会造成语义冲突 —— **语义冲突无法用行合并解决**。

**根治方案**（不在 M6 范围，需用户批准）：

1. 每包一个文件（`licensing/entries/<pkg>.json`）
2. 或追加式目录（每次登记写一个新文件）

**当前代价可接受**：每个 PR 多一次 `merge main` + 重跑 `provenance:report`。

## 十、待裁决的问题

### 「契约面文件」的相似度在数学上不可达

**观察**：13–15 个文件的相似度来源是**契约面固有内容**：

| 类型              | 实例                                                              |    ② 下界 |
| ----------------- | ----------------------------------------------------------------- | --------: |
| 纯类型文件        | `execution-adapter-types` / `workspace-hook-trust-types`          |      >0.5 |
| 类型为主          | `catalog-types`                                                   |      >0.4 |
| 导出签名为主      | `errors/index` / `browser-control.port` / `tui-permission-broker` | 0.42–0.44 |
| 纯桶（re-export） | `exec/index` / `marketplace`                                      |    随叶子 |

**为什么这是「必然的相似」而不是「抄袭」**：
两个**独立实现同一协议**的代码，必然导出**同样名字的符号**、**同样字段名的接口**。
这些名字是「协议的一部分」，不是「表达的一部分」—— 所以它们在相似度上必然重合。

**三种可能处置**：

| 方案                                     | 说明                  | 风险                       |
| ---------------------------------------- | --------------------- | -------------------------- |
| (a) 契约面文件用另一套判据（只看实现行） | 需工具改动 + 用户批准 | 形成「按文件性质分档」先例 |
| (b) 接受这类文件永久 `pending-rework`    | 最保守，不调门槛      | M6 会「永久未完成」        |
| (c) 调整门槛                             | —                     | **红线，不可**             |

**当前不做任何一项，等用户裁决。**
