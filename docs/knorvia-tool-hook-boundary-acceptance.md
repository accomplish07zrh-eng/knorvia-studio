# 工具 Hook 适配与改写复核验收

本批以 `88d0afb` 为固定基线，依据 `specs/knorvia-tool-hook-boundary.md` 独立替换三份旧适配实现。能力声明按层合成，Hook 请求改为事件字段序列与惰性读取器，单结果回复按转移规则投影；复核用同步路由描述拒绝／沿用／再询问，由原 prepared owner 激活和清理。没有第二套 Hook 仲裁或审批状态。

## 来源与范围

已接触旧源码，不作无接触声明。新结构的来源决定覆盖三份替换及两份新内部模块；固定协议字段/顺序、文案、标准浅合并和 Promise/调用求值语义是兼容要求，不主张为发明。改名、拆分和测试通过不能单独证明独立。五份源码共 543 行，较原三份 402 行净增 141，最大文件 183 行；新增行主要是字段序列、局部类型约束和明确复核出口。

HookRunner、memory 路径/IO、公共类型、别名表、预览 helper、存储和其他边界继续保留适用许可。根 Apache-2.0、0.8.0-preview.3 与旧发行不变。没有 UI、用户数据、模型、Computer Use 实机、安装/便携包或官网操作；整体独立与稳定发布未完成。

## 已修复的三个既有缺口

- 改写输入后再次询问仍遵守工具声明的仅本次／仅会话选项，复用纯 AskProjection，不再次运行 prepareApproval。真实协议组件验证原请求和再询问都不提供越界的项目授权。
- 默认 Computer Use 建议保留可信能力组；持久为组规则后，同名非可信条目仍不能复用。策略自带建议（含空数组）继续优先，信任来源只读注册 entry。
- Started 的显式 sideEffectScope 优先读取 permission 子声明，与 Service 一致；不补工具名默认值、不更改 readOnly 缺席语义。合法仅嵌套覆盖 workspace 的工具不再误报 none。

这些是已复现的公共工具合同缺口；未确认现有内置工作流/Bash 的实机用户故障，未将有限探针扩大成全产品故障声明。

## 先行失败、修正与复核

最初测试将 CoreError 当构造函数导入，导致一个测试文件无法加载；按实际 createCoreError 公共 API 修正后，20 项为 17 通过、上述三项缺口失败。迁移后 CUA 用例误以为普通工具消费 session grant；既有 Service 只在强制确认路线消费此规则，测试改为本功能真实的 project grant，未改 Service 或放松非可信来源门。

迁移初稿另有五项有限边界差异，均先记录失败再修复：Hook 参数回调替换 runner/run、复核字段回调替换 broker/prepare、兼容结果原有两次行为读取、Pre 行为读取后决定被改为 deny，以及上下文读取期间追加条目。现在按原 JS 调用时点捕获接收对象/方法；Failure 的 String(error) 仍先于捕获；上下文仅遍历入口长度。没有把访问器探针描述为生产桌面的既有故障。

最终新增 **30 项合同通过**，覆盖能力及来源、四类 Hook 请求/结果、预览截断、异常原值、端口引用、同步 prepare、一次激活/dispose、短路矩阵和三个有意修复。真实 Service、protocol broker 与 V4 registry 组合确认：同 ID 改写后旧 RPC 即使忽略取消迟到返回 deny，也不结束新 owner；第二次允许执行改写输入，父取消则拒绝，两路无 pending，Requested/Resolved 各一次。V4 答案仅有 ID，不据此承诺能识别旧客户端同 ID 答案的版本。

独立只读复核再次运行原反例及五条同步/微任务轨迹，共 12 个有限场景与固定旧版一致。编译器内存探针验证缺必填字段、非法字段名、错误 reader 返回类型会失败。类型映射仍是跨事件值联合，不能独自证明所有 phase/value 相关性；固定字段序列及运行时合同继续约束最终受控断言。
