## 行为依据和已证实修复

主代理完整读取旧入口、公共声明、网络配置及调用边界。任务自建的本机代理只接收请求并自行响应，不解析或转发合成目标：200正常完成，204/205/304各触发Response构造异常逃出异步回调，原请求在观察时仍未完成。观察脚本保存状态后才清理自有资源，没有把清理说成旧产品自动恢复。

独立设计分为实例/每请求编排与Node消息交接两模块。有效204/205/304或实际发送的HEAD使用null正文，立即释放尚未交给reader的自有消息；仍走既有字节读取器，因此Content-Length上限不被跳过。消息转换发生的错误在异步回调内部被捕获，先保存首因再释放自有消息并拒绝请求；清理失败不覆盖首因，晚到自有错误事件不再成为全局异常。正常正文继续由原reader消费与取消，不新增另一套读取或全局agent清理。

保持准备顺序、普通options引用与WebFetch浅拷贝、CA成功undefined/Buffer缓存及失败重试、public预检后的请求字段读取、native fetch重定向与Node既有手动响应行为、trace header优先级、代理报告脱敏、端口错误身份和timeout/cancelled分类。CA读取、代理配置、DNS与字节reader继续使用已存在的公共依赖，未复制其实现。
