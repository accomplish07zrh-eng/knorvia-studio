# Fetch 代理请求与返回流生命周期验收

2026-09-29。依[先行合同](../specs/knorvia-proxy-fetch.md)独立重建模型/MCP共用fetch入口和私有Node流所有者。公开工厂、原选项、直接fetch身份、CA成功缓存、原生Request规范化与返回流取消语义保持。界面、用户配置、数据与网络权限未改。

## 范围与故障

旧入口在自有回环代理收到204/205/304时，异步Response构造异常逃出Promise并使请求挂起；合成setup/end失败遗留abort监听，晚错误及未交接消息未妥善释放。新实现区分外层Promise完成与返回流关闭，修复空响应、转换异常和清理边界。HEAD与204/205/304立即释放未交接消息并返回null body。普通返回流仍可在Response交接后取消，保留同一Error并先终止message再终止request；该Error身份原本就正确，不记成修复。

工厂管理原options引用及成功CA缓存；私有owner管理一次request/message/signal，不复用read-to-completion HTTP桥。准备、CA、已取消检查的错误优先级保持；GET/HEAD也跨完整异步规范化边界后读取实时CA选项。被动晚错误/晚消息处理器不捕获活动owner。原生headers、manual redirect和不解压正文的行为不扩张，未新增超时、重试、大小限制或代理策略。

## 先旧后新及修订

原生回环探针不转发目标，不解析外部域名；200可读，204/205/304在500ms观察点仍挂起并有异常。返回流取消探针确认旧版同一Error身份。另一个合成setup探针确认同步原异常保留但abort监听残留。所有证书文本和文件均为自建夹具。
